# Alpha101 参考实现审查与补全报告

## 1. 审查范围与结论

审查对象：

- `../MurphyHoops_alphas101.py`
- `../101 Formulaic Alphas.pdf`，尤其是附录 A 的 101 条公式、算子定义和输入定义

新实现：`alphas101_strict.py`。原参考文件未改动。

参考文件实际定义了 **82 个** `alphaNNN()` 方法，缺少 19 个：

`48、56、58、59、63、67、69、70、76、79、80、82、87、89、90、91、93、97、100`。

缺失原因可从原文件注释和缺失项分布确定：Alpha56 需要 `cap`，其余 18 个都需要
`IndNeutralize` 以及 sector/industry/subindustry 分类。原文件没有这些输入字段，也没有
行业中性化算子，因此作者只保留了公式注释。这是参考代码的数据模型和算子不完整，
不是论文认为这些 Alpha 无法实现。严格版增加了 `cap`、三级行业分类和
`indneutralize()`，已补齐全部 101 个方法。

## 2. 统一算子层面的缺陷

这些问题会同时影响多条因子，不能只看单个公式文本是否相似：

1. `scale()` 用 `np.abs(df).sum()` 默认按列求和，实际变成每个标的沿时间缩放；论文要求
   每个交易日做横截面缩放。严格版改为 `axis=1`，每行绝对值之和为 `a`。
2. `correlation()` 以及多条 Alpha 把 `NaN`、`+/-inf` 填成 0，Alpha34/38 又填成 1；
   Alpha53/54/55/60 则把零分母替换成任意的 `0.0001`。这些处理均不在论文公式内，
   会制造有效信号。严格版把数学上未定义的结果保留为 `NaN`。
3. 论文明确规定所有非整数天数取 `floor`。参考代码在后半部分混用四舍五入、手写整数，
   造成大量窗口偏差。严格版所有时间算子统一经过 `_window()` 向下取整。
4. 参考代码的 `rank()` 是 `[0,1]` 横截面百分位，但 `ts_rank()` 返回 `1..d` 的原始名次。
   这导致 Alpha68/86/95 又人工乘以 14、20、12 补尺度，已经偏离公式。严格版两个 rank
   都使用百分位，并列值取平均名次；公式中不再加入人工倍率。
5. `rank()` 原实现并列值使用 `method='min'`，会系统性压低并列项。严格版使用平均名次。
6. 原实现把 `adv{d}` 当成 `volume` 的均值。论文附录 A.2 明确定义为过去 d 日的
   average daily dollar volume。严格版优先读取 `dollar_volume`（或 `amount`），否则按
   `vwap * volume` 构造，再求移动平均。需要注意：论文的个别公式把 `adv` 与 `volume`
   直接比较，量纲本身并不理想；本实现仍按论文的显式定义执行。
7. 原文件用普通 `pow()` 实现 Alpha84，并且没有通用 `SignedPower`。严格版实现
   `sign(x) * abs(x) ** a`，避免负底数遇到非整数指数时落入复数/无效值。
8. 条件表达式在无产出期可能把缺失比较当成 `False`，继而产生 0、1 或 -1。严格版的条件
   比较保留输入缺失状态。
9. 原文件依赖未随参考文件提供的 `alphas`、`datas` 模块，不能独立导入。严格版仅依赖
   NumPy/Pandas，并提供 `compute(number)` 入口和明确的输入校验。

## 4. 新实现接口与数据约定

```python
from alphas101_strict import Alphas101Strict

calculator = Alphas101Strict(data)
alpha_32 = calculator.compute(32)
```

`data` 是字段名到宽表的映射，所有行情宽表必须拥有完全相同的日期索引和标的列：

- 必需：`open`、`high`、`low`、`close`、`volume`、`vwap`
- 可选：`returns`、`dollar_volume`（别名 `amount`）
- 按公式需要：`cap`、`sector`、`industry`、`subindustry`
- 行业分类可用“标的 → 分类”的静态 Series，也可用“日期 × 标的”的动态 DataFrame

若某个因子需要的 cap 或行业字段未提供，调用该因子会抛出带字段名的 `KeyError`，不会
静默跳过中性化。

## 6. 仍需使用者明确的数据口径

“严格遵循论文公式”并不等于可以脱离数据口径复现论文收益。尤其需要确认：价格是否按
论文交易时点要求复权、vwap/成交额的单位、期货合约乘数、动态行业分类的生效日期以及
横截面当日可交易样本。论文没有规定移动标准差采用总体还是样本估计；为与原参考代码的
Pandas 行为保持可比，严格版使用 Pandas 默认样本标准差（`ddof=1`）。
