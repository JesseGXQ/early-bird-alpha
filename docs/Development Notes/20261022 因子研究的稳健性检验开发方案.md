# 因子研究的稳健性检验开发方案

## 1. 文档定位

本文承接《因子研究闭环与组合实验层开发方向》第 9.3 节中的稳健性方向，结合当前诊断组合实验层与基础因子合成算子的实现，确定第一阶段的开发边界、研究语义、最小接口和验收标准。

本文采用《因子合成模块组件开发方案》所倡导的“研究驱动的基础设施开发”：先提供可以立即用于真实研究的独立工具与完整示例；只有实际使用反复暴露相同问题，才增加抽象、编排和框架能力。

本次交付是开发方案文档，不包含实现代码。文中的新增接口、示例及测试均是后续开发任务；当前代码与方案存在差异时，应以代码确认已有能力，以本文确定本轮新增行为。

第一阶段围绕四个研究问题展开：

| 能力 | 要回答的问题 |
|---|---|
| 训练、验证与样本外划分 | 哪些数据参与了拟合与选择，哪些数据仍可承担评价职责？ |
| Walk-forward | 仅使用当时已知信息重复训练与选择，结果能否在后续时期复现？ |
| 参数邻域 | 表现是否依赖一个孤立的最优参数点？ |
| 多重检验 | 同时检查多个假设后，哪些统计证据仍值得重视？ |

首期目标是让研究者能够依靠少量普通调用完成上述研究，并能追溯样本、选择过程和收益来源。不以“拥有完整稳健性框架”为完成标准。

## 2. 当前基础与职责边界

### 2.1 已有基础

当前代码已经提供：

- `factors/combination.py`：等权、投票、排名及 IC/ICIR 加权算子；监督合成器由调用方交付训练数据，使用 `fit/transform` 分离训练与应用。
- `factors/evaluation/ic.py` 与 `regression.py`：预测关系诊断及部分 HAC、bootstrap 推断。时序 IC 结果本身不提供一个可直接作为整体显著性证据的均值检验。
- `factors/diagnostic_portfolio/`：逐期权重状态、风险估计、下一期收益、换手、代理成本、绩效与贡献。
- `factors/evaluation/robustness.py`：已有 `adjust_pvalues`，默认使用 BH，仅对非缺失 p 值校正，尚缺少完整检验族、无效项和输入边界约定。

`LabelResult` 当前不携带逐行标签成熟时点。`LabelBuilder` 的固定前瞻标签按品种观测序列前移，不能直接用自然日推算其成熟日期；`LabelSpec.min_valid_obs` 默认允许部分有效观测，也不能据标签非空推断完整期限已经实现。

诊断组合运行器每次运行都会初始化新的权重状态。因此，独立运行各折后直接拼接收益，会改变折间持仓、换手和成本。

### 2.2 新能力的边界

首期新增时间及成熟度工具、邻域汇总、HAC 均值检验，并完善现有 p 值校正。工具保持独立：不直接接管数据加载、因子计算、预处理、监督拟合或组合运行。

调用方继续负责：

- 因子经济方向、因果预处理和动态品种池；
- 标签定义、完整性、真实可得时点与数据质量；
- 候选构造、共同有效样本和实验记录；
- 实际调用拟合、评价和诊断组合组件。

工具校验索引、时间边界、数值与计数契约；这些局部检查不能证明上游数据和算法完全不存在前视。首期不建设统一稳健性运行器、优化器、中央实验注册服务、缓存或报告平台，也不修改合成器和组合运行器的公共接口。

## 3. 证据层次与基本研究流程

稳健性同时覆盖预测关系与组合收获，不只检验 IC。

| 证据 | 首期观察内容 | 时间口径 |
|---|---|---|
| 预测证据 | IC、回归系数、方向一致性、覆盖率及有效样本 | 按因子决策时点归属，标签另外检查成熟度 |
| 组合收获证据 | 毛收益、代理净收益、Sharpe、回撤、换手与成本 | 权重按决策时点，收益按实现时点 |

两条证据共享候选身份和时间划分，但不强行共用同一套数值样本。例如，完整五期标签的有效决策样本与可结算一期组合收益的决策样本，本来就可能不同，必须分别报告数量与口径。

最短研究流程为：

```text
事前确定假设、候选和选择准则
    → 准备因果因子、标签与标签可得时点
    → 划分开发数据与最终留出样本
    → 开发期训练、验证和 walk-forward
    → 检查参数邻域及选择偏差
    → 冻结研究规则
    → 最终留出评价
```

统计显著不能替代经济价值。报告同时展示效果大小、方向、覆盖率、成本及样本量，不设置一个由 p 值或 Sharpe 单独决定的因子接受开关。

## 4. 时间切分与标签成熟度

### 4.1 四种数据角色

- **训练集**：拟合预处理参数、监督合成权重等。
- **验证集**：比较候选，选择参数和研究规则。
- **开发期测试集**：评价本折已经冻结的候选或选择流程。
- **最终留出样本**：位于开发期之外，在研究方案冻结后使用。

“样本内”在本文中指训练样本；训练加验证合称用于开发和选择的数据。不能因为验证数据没有参与第一次 `fit`，就把它描述为完全未参与研究选择的样本外。

开发期测试结果可以用于改进研究流程。一旦研究者据此修改候选、方向、参数范围或选择规则，该段结果便属于开发证据。最终留出段承担独立确认职责，不再参与人工调参。

留出身份是研究纪律，首期不开发访问控制或“解锁样本外”服务。若已有研究实际查看过某段数据，不能通过更换变量名恢复其未使用身份；需如实记录并寻找后续未参与选择的数据。

### 4.2 时间轴与切分约定

输入为调用方明确交付的 `pd.DatetimeIndex`，必须无 `NaT`、唯一且严格升序。它代表权威决策时间轴，不从某个候选的非缺失信号反推。

日频可以从已确认完整的研究面板时间轴取得；若面板本身缺少应有日期，先修复或交付正确日历，切分工具不会重建交易日历。

静态划分按日期边界执行，端点包含在前一段中：

```text
train:       timeline <= train_end
validation:  train_end < timeline <= validation_end
 test:       validation_end < timeline <= test_end
```

三段均须非空，边界顺序合法。边界可以落在非交易日，归属由时间比较决定，不自行补造观测。面板按时间集合筛选，同一决策时点的所有品种必须归入同一区间。

最终留出数据在生成开发期折之前就分离，不得参与开发期窗口长度、暖机覆盖率或候选优劣的选择。

### 4.3 前瞻端点与真实可得时点

对固定 `h` 期前瞻标签，在原始完整面板索引上逐品种寻找第 `h` 个后续观测，其时间戳为 `label_end`。这一计算在切分、过滤品种池及删除缺失样本之前完成，与现有标签的观测序列语义一致。

例如，某品种的观测为周一、周二、周四、周五，则周一的两期前瞻端点为周四。不能用周一加两个自然日，也不能在删除周二缺失信号后重新计算端点。

无法取得完整期限的尾部行返回 `NaT`。端点存在只说明名义期限完整，不保证其中收益都有限；示例另用 `min_valid_obs=h` 保证标签完整，不将两个检查混为一谈。

对无发布延迟的行情标签，示例使用 `label_available_at = label_end`。存在修订、发布延迟或自定义事件标签时，由调用方交付真实可得时点。仅调整端点不能修复使用事后修订数据的问题。

### 4.4 成熟掩码与拟合截止时点

监督拟合样本须同时满足：

```text
决策日期属于允许的拟合窗口
且动态品种池和成分共同有效
且标签为有限数值
且 label_available_at 非空并且 <= fit_cutoff
```

成熟工具只检查最后一项，不负责从 NaN 推断缺失原因，也不直接修改因子或标签。

首期采用保守的收盘后决策语义：用于验证的模型最迟在验证首个决策之前的全局时点完成拟合；用于测试的选择与重新拟合最迟在测试首个决策之前的全局时点完成。两者截止时点由权威时间轴确定。

当 `gap=0` 时，前述时点分别是训练段末尾与验证段末尾。`gap>0` 时，间隔内的决策不作为训练或验证样本，但已发生的行情可用于标签成熟及因果历史上下文；它不是禁止读取行情的隔离区。

首期仅做从过去向未来的划分。按真实可得时点排除跨越拟合或选择边界的标签，不另行套用通用 K-fold 的双向 purge/embargo 规则。额外时间间隔默认零，不能替代成熟度检查。

### 4.5 暖机与拟合必须分开

因子、滚动标准化和风险估计可以使用决策前的历史上下文。暖机数据不计入当前评价区间，也不自动变成允许监督拟合的样本。

无监督但需要拟合的全局均值、分位数、截断阈值等，同样必须限定其训练数据。因果滚动状态可以按既定规则持续更新，不能用全样本参数冒充暖机。

## 5. Walk-forward 的最小生命周期

### 5.1 窗口生成

输入开发期决策时间轴、训练长度、验证长度、测试长度及模式，按时间戳个数计算长度，不按面板行数计算。

- `expanding`：训练起点不变，训练终点随折推进。
- `rolling`：训练起点和终点共同推进，训练长度不变。
- 验证和测试长度固定，步长固定为测试长度，测试区间不重叠。
- 可选 `gap` 同时用于训练—验证及验证—测试之间，默认零。
- 第一折数据不足直接报错；尾部不足完整测试长度时不生成尾折，输出明确警告并在示例记录未覆盖日期。

历史测试区间在后续折变成已发生的历史，可以按既定滚动规则进入后续训练；在当时仍须遵守标签成熟度。这是顺序学习，不是让未来数据回流到过去。

### 5.2 每折步骤

1. 对每个候选创建新的预处理或合成实例，用训练窗口内截至训练拟合时点已成熟的共同样本拟合。
2. 冻结监督参数，生成验证信号，并按事前确定的共同样本与评分规则比较。
3. 仅使用截至测试前选择时点已经可得的验证结果选择候选。
4. 对选中候选创建新实例，使用训练与验证窗口中截至重新拟合时点已成熟的样本重新拟合。
5. 冻结本折监督参数，生成该折测试决策区间的信号。
6. 记录选择及拟合信息，然后推进下一折。

重新拟合从原始窗口重新形成成熟掩码。此前在第一次训练中被排除、现在已成熟的训练尾部标签可以重新纳入；不能仅拼接第一次训练留下的旧行集。

示例默认以验证期代理净 Sharpe 选参。并列按 `candidate_id` 排序确定，不能临时查看另一个指标破除并列。候选失败保留原因；所有候选无效则终止该折及连续研究路径，不静默跳过或补入“最优可用”结果。

每折至少保留一张普通记录表：训练、验证和测试边界，拟合及选择截止时点，各候选评分与状态，选中候选，重新拟合样本数，以及实际 `score_`、`weights_` 快照。无需建立状态仓库或拟合版本系统。

### 5.3 验证评分必须在选择时点可结算

预测评价仅使用选择截止前已成熟的验证标签。

组合评价仅使用验证决策产生、并在选择截止前已经实现的收益。若验证段最后一个决策形成于截止当日，其下一期收益尚未知，不能进入选参 Sharpe；将其用零代替同样不正确。

验证期候选实验可以独立从空仓开始，且使用同一暖机历史、起始锚点和成本规则。这是选择阶段的候选比较，不代表连续 walk-forward 的投资路径。

### 5.4 最终留出阶段

开发结束后冻结候选集合、经济方向、参数邻域、选择指标、组合规则及重新拟合日程。示例在留出开始前完成最后一次允许的选择与拟合，再交付留出信号及结果。

未来若需要在留出期间定期重新拟合，必须在进入留出段前规定日程与信息边界。按预定规则使用当时已知历史是允许的；根据留出表现临时修改规则会使其转为开发证据。

## 6. 连续组合收益的接入约定

### 6.1 拼接信号，一次运行

连续路径先按时间拼接各折测试信号，再交给现有 `DiagnosticPortfolioExperimentRunner` 一次运行。拼接前检查：

- 测试决策时间集合连续且不重叠；
- 每个决策时点只有一个所属折，同一 `(timestamp, product)` 不重复；
- 信号缺失保留为数据状态，不将缺失日期删除或用未来值填补；
- 研究面板额外保留最后一个测试决策的下一全局实现时点。

组合运行保留足够前置行情用于风险暖机，前置时点信号置空，调仓锚点设为首个测试决策。进入测试前保持空仓，首笔建仓成本正常计入，暖机空仓收益不计入测试绩效。

### 6.2 固定的组合规则

首期连续路径的 `DiagnosticPortfolioSpec` 全程固定，包括收获范式、风险参数、调仓频率、锚点、约束及成本代理。逐折变化可以发生在因子参数、所选预测变量和监督合成权重。

若折边界不在既定调仓日，切换后的信号等待下一次既定调仓生效，不能为了展示折效果额外调仓。

组合参数邻域中的每个候选可以分别运行一条完整连续路径，但不能逐折切换组合配置后仍假定由现有运行器自动保留全部语义。

### 6.3 收益归属与汇总

决策 `t` 的权重赚取下一全局时点的 `True_Return`，相应决策成本也对齐至该实现时点。逐折归属以产生权重的决策所属折为准。

因此，一折最后一个决策的收益即使在下一折首个时间戳实现，也仍属于前一折。保存显式的 `decision_timestamp → realization_timestamp → fold_id` 对照，不用收益索引直接切相同日期区间替代。

整体 Sharpe、回撤和复利净值从单次运行的完整测试收益重新计算，不平均各折 Sharpe，也不平均逐折回撤。逐折指标从同一次运行切片计算，用于观察时期差异。

不得把独立冷启动的折收益拼接为连续净值；不得直接用重叠多期标签构建逐日组合净值。最终留出绩效与开发期绩效分别展示，首期示例的留出实验另从空仓启动。

## 7. 参数邻域：从最优点转向稳定区域

### 7.1 显式候选表

研究者在查看评价结果之前声明中心候选及局部扰动。候选表使用唯一、非空的 `candidate_id`，明确中心身份，并保存具体参数值。例如：

| candidate_id | lookback | 角色 |
|---|---:|---|
| momentum_16 | 16 | 邻域 |
| momentum_20 | 20 | 中心 |
| momentum_24 | 24 | 邻域 |

允许扰动因子窗口、预处理窗口或阈值、合成参数，以及信号映射、调仓与风险参数。首期不自动生成网格、计算抽象参数距离或提供寻优器。

一次邻域实验固定标签定义、预测期限、经济方向、品种池规则、收益口径和评价区间。改变这些内容意味着另一个研究实验，应单独说明其问题与证据身份。

### 7.2 共同样本与覆盖率

所有候选使用足以覆盖最长回看的前置历史，以及同一评价区间。不能让较长窗口候选在另一段更有利的时期评价。

预测证据采用候选间共同有效的 `(timestamp, product)` 行；截面统计进一步遵守现有评价函数的组有效性规则，比较汇总时保留共同有效组。共同样本之外，另外记录每个候选原始有效行数、覆盖率、被共同掩码删除的数量，防止交集过小后掩盖覆盖损失。

组合证据使用相同完整实现时间轴、动态品种池、缺失信号政策和暖机安排，保留缺失信号触发的空仓及成本结果。不为了使曲线更整齐，按候选分别删除空仓或低覆盖日期，也不要求组合必须只交易预测统计的共同完整行。

相同起止日期、相同样本数不能证明样本身份相同。实际索引及共同掩码由调用代码检查；邻域汇总器只接收已经完成可比评价的指标，不宣称自行验证了样本身份。

### 7.3 最小汇总

原始指标表以全部声明候选为行，指标为列；失败候选仍占据一行，指标为 NaN，并在候选记录表保留失败原因。

汇总返回两张普通表：

1. 各候选相对中心点的逐指标差值；
2. 每项指标的中心值、最小值、中位数、最大值、声明候选数、有效候选数和有效比例。

仅对调用方显式指定的方向性指标，例如 IC 均值、平均收益及 Sharpe，额外计算正值比例与和中心点同号的比例。比例以有限候选为分母，必须与有效比例并列展示；中心值无效时同号比例与差值均无定义。零单独作为中立方向，不能当作正值。

分布包含中心与所有声明邻域点，不赋予概率推断含义。对换手、成本、波动率等指标只展示数值分布，不从符号推断好坏。

首期不产生统一“稳健性总分”，也不预设最大回撤、邻域正值比例等通用通过阈值。研究者关注平台宽度、方向反转、性能断崖和成本变化，并记录经济解释。

### 7.4 与选择及多重检验的关系

邻域点用于验证期选参时，它们属于选择过程。冻结后在测试集查看整张邻域表，属于诊断性分析，不能再据此重新选点却仍称原测试集未参与选择。

若在同一评价数据上检验多个邻域候选并据显著性筛选，应纳入相应检验族。邻域点相关，不意味着可以忽略多重性；也不意味着这些点构成独立重复实验。

## 8. 多重检验：先保证单项推断，再处理多重性

### 8.1 先定义假设

每项正式检验至少记录：检验族与假设身份、候选、评价区间、标签或收益定义、原假设、检验方向、统计方法及其参数。

首期默认双侧检验 `H0: effect = 0`。若希望支持“正向预测”或“正代理净收益”的解释，须同时检查估计值为正；双侧显著但估计为负，不能接受正向经济假设，也不能事后翻转方向再按一次尝试处理。

ICIR、Sharpe、正收益比例和 bootstrap 置信区间不是可以直接传给 p 值校正器的原始 p 值。不能将 `1 - 正值比例` 或“置信区间不含零”编码成自造 p 值。

### 8.2 原始 p 值的来源

预测证据优先复用现有 IC 与回归推断，但调用方必须确认其检验单元、样本处理与问题相符。例如，分品种时序 IC 的跨品种均值不能自动套用沿时间轴的 HAC 检验；截面 IC 删除无效日期后，滞后阶数对应的时间间隔也可能改变。

统计函数提供 p 值，不代表它在任意样本上都有效。对内部时间缺口、重复观测或与零假设不符的推断，不先做修正就不纳入正式证据。首期不借本轮重构全部已有评价方法。

为组合收益增加独立的 `hac_mean_test`，输入单条明确时间轴上的一期收益，也可用于满足同一时间契约的诊断统计序列。

其约定如下：

- `values` 为以时间为索引的实数 `Series`，索引须与显式提供的 `timeline` 完全相同；时间轴唯一、升序、无 `NaT`。
- 调用方负责交付真实评价时间轴；完全相等只能发现相对于该时间轴的遗漏，不能证明日历本身完整。
- 原假设固定为零均值、双侧检验；使用仅有常数项的 OLS、Bartlett 核 HAC、有限样本协方差修正及 `t(n-1)` 参考分布。该 t 推断仍是近似，不能解释为任意相关结构下的精确有限样本检验。
- `max_lags` 必须显式指定为非负整数，不静默缩小或自动选择。有效推断要求至少三个观测且 `max_lags <= n-2`。
- 内部 NaN 不删除、不补零；不足样本、滞后要求无法满足、常量序列或标准误非正时，返回明确不可检验状态与空 p 值。
- 非数值、布尔、无穷值、错误索引或非法参数属于调用错误，直接报错。

结果使用普通 `Series`，记录样本数、有效值数、均值、标准误、统计量、p 值、请求及实际滞后阶数、参考分布、自由度、修正政策和状态。无效结果可以保留描述量，但必须清楚标记不可推断。

一期收益不等于独立收益；`h-1` 也不是所有序列的充分滞后选择。滞后及敏感性范围在看显著性之前确定，不通过试出最小 p 值决定 HAC 参数。

### 8.3 检验族与尝试记录

一次调用校正一个已声明检验族。首期用普通表格记录完整尝试，不建设中央注册服务。

同一评价数据上实际参与比较与筛选的因子、参数、合成方法、方向、预测期限或收获规则，不能只保留最终赢家。不同主张可以有事前声明的不同检验族，但不能看到结果后拆成若干小族以获取显著性。

开发选择与最终确认区分处理：若候选选择已完全在开发数据上完成，最终留出只检验一个事前冻结的选择流程，则不机械地把所有训练候选当作该留出检验族的成员。若在留出数据上同时查看和筛选多个候选，就必须反映实际检验范围，并承认该段承担了选择职责。

选择一个既有候选时的训练表现不能替代独立评价。对同一数据拟合并评价得到的无效 p 值，即使加入完整检验族，校正也无法修复其失效。

### 8.4 方法与默认用途

| 方法 | 控制目标 | 首期用途 |
|---|---|---|
| Holm | FWER：一个检验族出现至少一次假阳性的概率 | 正式确认的默认示例 |
| BY | FDR：被拒绝假设中假发现比例的期望 | 依赖结构不明确时的探索性筛选示例 |
| BH | FDR，在独立或满足适当正依赖条件下使用 | 能说明依赖假设时的探索性筛选 |

三种方法均复用 `statsmodels.stats.multitest.multipletests`。BH 不因因子“看起来相关”就自动满足条件；BY 更保守，但也以有效原始 p 值和正确检验族为前提。FDR 不是某个选中因子为假的概率。

显著性水平默认 `alpha=0.05`。保留现有 `adjust_pvalues` 的默认 `method='fdr_bh'` 以兼容旧调用，新示例明确传入方法，不把旧默认当作研究推荐。

### 8.5 无效项、结果与兼容性

`adjust_pvalues` 增加可选关键字 `family_id`。非空时须为非空字符串；未传入时输出为空，不能伪造已记录的检验族身份。

输入 p 值为唯一索引的实数 `Series`，允许 NaN，不允许布尔值、无穷值或超出 `[0, 1]` 的数值。`alpha` 必须有限且在 `(0, 1)` 内；空输入和全 NaN 输入也必须检查参数是否合法。

声明的候选无有效 p 值时，内部以 `1` 参与校正，保留完整族规模。输出保留原始 NaN，校正值为空，`rejected` 为可空布尔的缺失值，并明确标记不可检验。不能把失败表述为“接受原假设”。空族返回结构稳定的空表。

保留原有 `raw_pvalue`、`adjusted_pvalue`、`rejected`、`n_tests` 列，其中 `n_tests` 继续表示有效原始 p 值数量。新增 `n_declared_tests`、`family_id`、`correction_method`、`alpha`、`status`。`n_declared_tests` 才是本轮实际用于校正的族规模。

所有 p 值有效时，现有校正结果与默认调用方式保持一致。存在无效项时，扩大为声明族的校正和可空拒绝标记是本轮有意修正的行为，需要文档与测试明确说明。

以 `1` 保留失败项不能替代完整尝试记录，也不能修复遗漏候选、失效 p 值或自适应定义检验族的问题。

### 8.6 首期不作的推断

不平均逐折 p 值，不按独立检验直接使用 Fisher 合并。相邻折的拟合历史可能重叠，收益也可能相关。

连续样本外收益可以作为一个完整冻结流程的评价序列，但对其使用 HAC 仍依赖相应近似条件；不能因此宣称已经精确校正所有开发过程和非平稳影响。

首期不实现 DSR、PBO、Reality Check、SPA，也不将校正后的 p 值称为“回测过拟合已经消除”。

## 9. 最小接口与文件边界

### 9.1 时间与邻域工具

新建 `factors/robustness.py`。只增加一个轻量切分结构，其余输入输出使用 pandas 对象：

```python
@dataclass(frozen=True)
class TemporalSplit:
    train: pd.DatetimeIndex
    validation: pd.DatetimeIndex
    test: pd.DatetimeIndex


def chronological_split(
    timeline, *, train_end, validation_end, test_end=None,
) -> TemporalSplit: ...


def walk_forward_splits(
    timeline, *, train_size, validation_size, test_size,
    mode='expanding', gap=0,
) -> list[TemporalSplit]: ...


def forward_label_end(index, *, horizon) -> pd.Series: ...


def mature_label_mask(label_available_at, *, cutoff) -> pd.Series: ...


def summarize_neighborhood(
    metrics, *, center_id, directional_metrics=(),
) -> tuple[pd.DataFrame, pd.DataFrame]: ...
```

上述签名用于明确最小调用边界，不引入通用协议。`fold_id` 由调用方按返回顺序编号，不放入切分结构；切分结构不持有数据集、模型或收益。

`forward_label_end` 接收唯一、升序、层名严格为 `timestamp, product` 的完整面板索引，`horizon` 为正整数，返回同索引的 datetime `Series`。`mature_label_mask` 接收同类索引上的 datetime 可得时点序列，`NaT` 返回 False；有限可得时点不得早于该行决策时点。日期及可得时点的时区必须兼容，不能静默丢失时区。

长度、期限和间隔参数不接受布尔值冒充整数。函数不得原地排序、改名、填充或修改输入。

邻域 `metrics` 以唯一非空字符串候选身份为索引、唯一指标名为列，数值允许 NaN、不允许无穷。候选与参数、原始覆盖率、失败原因的表由调用方保留；汇总器不接收模型或回调，也不重复计算收益。

## 10. 两个可以运行的研究示例

示例放在 `research/examples/robustness/`，直接组合调用现有组件与本轮工具。提供两个可通过 `python -m` 从仓库根目录运行的入口；默认使用确定性人工数据，不要求本地数据库存在。

共享的人工数据构造可放一个小型辅助模块，但不把示例循环提升为公共实验引擎。示例返回或打印普通表格；持久化由研究者按需使用已有工具，不为示例另建存储系统。

### 10.1 固定单因子参数邻域

使用一个由历史收益计算的因果因子，事前指定三个相邻回看窗口及中心点，展示：

1. 分离开发段与最终留出段，准备足够历史上下文。
2. 从原始完整面板构造完整前瞻标签与端点，明确 `min_valid_obs=h`。
3. 静态训练、验证和测试划分，记录各区间成熟标签数量。
4. 在验证共同样本比较预测证据，在共同实现时间轴比较组合证据。
5. 展示候选参数表、原始覆盖率、指标及状态、中心差值与邻域汇总。
6. 用验证期代理净 Sharpe 和固定并列规则选定候选，分别报告开发测试及最终留出结果。
7. 展示一个事前声明候选族的 HAC 原始 p 值和明确指定方法的校正结果。若用多个留出候选作多重检验演示，应标为多候选诊断，不据结果再选择部署候选。

重点是让研究者看见共同样本及覆盖损失，而不只得到一张“最佳参数”表。

### 10.2 IC 加权合成的 Walk-forward

使用至少两个同方向、尺度可比的因果成分，声明少量候选配方。按当前实现的 `method`、`score_` 和 `weights_` 接口调用，不照搬旧设计稿中的参数或属性名称。

示例完成：

1. 用开发时间轴生成滚动或扩展折，列出尾部未覆盖区间。
2. 每折按成熟掩码拟合新合成器，验证评分，选择后用训练加验证重新拟合。
3. 保存每折实际拟合样本、候选状态、评分与权重快照。
4. 生成仅覆盖各折测试决策的冻结信号，检查覆盖并按时间拼接。
5. 用固定组合配置运行一次，输出整体绩效、逐折绩效及决策—实现—折归属表。
6. 用完整样本外一期代理净收益做明确滞后的 HAC 检验；分别报告最终留出实验，禁止将开发结果与留出结果合并成一个确认性指标。

两个示例都必须明确：修改未来数据不会改变在此前截止时点已完成的拟合和选择；修改测试标签不能改变本折监督参数。

## 11. 测试与验收

### 11.1 时间与成熟度

- 静态边界包含关系、非交易日边界、同日多品种不跨集合。
- 滚动与扩展窗口的确切时点，步长、两个 gap、训练增长及尾部警告。
- 非法时间轴、空窗口、错误模式、非法长度与首折样本不足。
- 人工 ragged 面板中逐品种第 h 个后续观测的端点及尾部 `NaT`。
- 与现有标签前移定义一致；部分可用标签不会绕过完整期限约束。
- 可得时点等于截止时点时允许纳入；晚于截止或为 `NaT` 时排除。
- 时区兼容、延迟可得及输入不变。

### 11.2 邻域与选择

- 中心差值、分布、有效比例及方向比例可手算。
- 候选失败、中心无效、全无效及零值的明确输出。
- 不同暖机长度和不同覆盖率下，实际评价样本保持共同约定。
- 全部候选失败时终止；并列选择稳定；不使用测试表现破除并列。

### 11.3 HAC 与多重检验

- 用独立可复算的 Bartlett 自协方差公式核对均值标准误、统计量及参考分布，不只与同一个库函数互相比较。
- 覆盖缺失时间戳、内部 NaN、常量、样本不足、非法滞后、非有限值和时间轴不一致。
- 使用已知小型 p 值序列手算 Holm、BH、BY，并检查输入换序后恢复原身份。
- 覆盖单项、空族、全无效、部分无效、越界 p 值、非法 alpha 和重复身份。
- 无效项保留族规模；`n_tests` 保持旧含义，声明数量另列；不可检验不输出 False 冒充有效未拒绝。

### 11.4 联合因果性与连续收益

- 修改训练拟合截止之后的数据，不改变此前已完成的模型拟合。
- 修改测试数据，不改变本折选择、重新拟合状态及更早信号；后续折可随已发生信息变化，不能错误要求它们完全不变。
- 手算折间信号方向翻转的权重、换手及成本，证明单次运行保留折间状态。
- 覆盖折边界非调仓日、最后一个决策的下一期收益、逐折归属及暖机绩效排除。
- 两个示例均完整运行；所有人工测试独立于 `db/` 和外部 RAW_DATA。

建议新增测试位置为 `tests/factors/test_robustness.py`、`tests/factors/evaluation/test_robustness.py` 及 `tests/research/test_robustness_examples.py`。从仓库根目录使用 Conda base 验收：

```powershell
& 'C:\Users\Jesse\AppData\Local\anaconda3\python.exe' -m pytest tests/factors/test_robustness.py tests/factors/evaluation tests/factors/diagnostic_portfolio tests/research/test_robustness_examples.py -q
```

本方案文档阶段不要求运行上述尚未编写的测试。后续代码阶段完成新增测试，并回归现有评价与诊断组合测试；无需为本轮独立工具运行依赖真实数据库的全部 data 测试。

## 12. 开发顺序与完成标准

建议按以下顺序交付，每一步都能独立使用和验证：

1. 时间切分、前瞻端点和成熟掩码，先手算边界。
2. 固定单因子研究示例，明确共同样本、验证评分截止及覆盖记录。
3. 监督合成 walk-forward，完成重新拟合和连续组合路径。
4. 提取邻域数值汇总，保留候选与失败记录在调用层。
5. 新增 HAC 均值检验，完善校正函数及检验族示例。
6. 完成联合因果性测试、既有测试回归及使用说明。

如示例暴露既有组件导致最小链路无法运行的实际缺陷，应单独记录并做必要的局部修复；不能借此改写合成模块或组合模块架构。

第一阶段完成必须满足：研究者不需要新的统一运行器，就能从显式候选开始，完成验证选参、标签成熟检查、训练加验证重新拟合、样本外连续收益、邻域比较及声明检验族校正；所有关键时间和数值结果可用人工面板复核。

## 13. 后续演化条件

以下问题保留为后续研究方向，不作为首期必须实现的功能包：

- 分时期、分品种、分板块和分市场状态的系统比较；
- leave-one-product-out、leave-one-sector-out；
- 成本与流动性压力情景；
- DSR、PBO、Reality Check、SPA 等选择偏差研究；
- 多次研究出现稳定重复后提取轻量调用协议或编排；
- 真实复核需求推动的实验身份、持久化、缓存和报告集成。

启动下一阶段的依据应是具体问题：研究者反复手写相同边界处理、难以复核某次选择、需要更复杂的选择偏差证据，或现有最小工具无法回答明确研究假设。每次只围绕已经出现的问题局部扩展。
