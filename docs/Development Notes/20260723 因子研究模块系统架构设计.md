# 因子研究模块系统架构设计

## 1. 文档定位

本文描述日频因子研究模块的完整 V1 目标架构。

- V1 一次性建立完整、可运行的日频因子研究框架，不再把基础能力拆成 V1/V2 两轮实现。
- `V2` 名称保留，但不预先分配功能；只有未来真实研究暴露出 V1 无法支持的问题时，才另行设计和开发。
- 日内因子研究不属于当前 V1，也不预先归入 V2。它在因子构造、数据来源、标签、成本、评价和策略交付等方面与日频研究差异显著，未来若有明确需求，应单独进行领域设计。

上位设计参见《20260723 因子研究与策略回测双层架构设计》。V1 的具体文件和编码顺序参见《20260723 因子研究模块 V1 开发-代码写作方案》。

## 2. 设计目标

因子研究模块负责回答：

- 某个变量是否包含对未来收益的预测信息？
- 它在哪些预测期限、品种、时期和市场状态下有效？
- 结论是否依赖少数样本、特定参数或错误的数据处理？
- 该因子是否值得交给策略层，接受组合、成本、账户和执行约束的进一步验证？

完整研究链为：

```text
DataFacade / ResearchFeed   <-- 从数据引擎获取时间语义正确的单品种历史行情
    -> ResearchDataset      <-- 将行情校验、规范化并组织为统一的多品种研究面板
    -> DynamicUniverse      <-- 按上市时长和流动性等历史可得条件确定逐时点品种池
    -> FactorDefinition     <-- 定义因子参数和输入字段，并计算预测变量
    -> PreprocessingPipelines <-- 完成单因子处理、中性化、跨因子正交化和平滑
    -> LabelDefinition      <-- 构造严格向前看的未来收益标签
    -> FactorEvaluator      <-- 完成预测、稳健性、归因和冗余等诊断
    -> ResearchResult       <-- 汇总因子、标签、诊断结果、元数据和警告
    -> CoreTables / TearSheet <-- 按需输出核心表格或完整标准报告
    -> CandidateFactor      <-- 将研究者认可的因子整理为策略层交付物
    -> Strategy / BacktestEngine <-- 将候选因子转化为策略，并验证交易可实现性

ResearchExperiment         <-- 用显式配置编排并记录上述完整流程
```

因子研究结果不是策略回测结果。IC、分组收益和多空组收益只属于预测能力诊断，不得被命名或解释为真实可交易收益。

## 3. 架构决策

### 3.1 采用单一完整 V1

因子研究是独立的研究业务域，对订单、成交和账户的运行时依赖很低，其核心概念也相对稳定。因此可以先定义接近完整形态的架构，不必像期货账户一样逐版改变内部业务语义。

但“完整”限定为个人策略研究所需的完整能力，不包括分布式集群、在线 Feature Store、实时因子服务、多用户权限和 AutoML 平台。

### 3.2 依赖方向

允许的生产代码依赖为：

```text
data <- factors <- strategy <- backtester
```

- `factors/` 可以调用 `DataFacade`，但不得依赖 `strategy/`、`backtester/`、`portfolio/`、`executor/` 或 `account/`。
- `strategy/` 可以使用因子公共接口，将因子值映射为信号和目标仓位。
- 因子不得创建订单、成交、持仓、PnL 或账户状态。
- 因子诊断不得调用事件驱动回测来计算 IC 或分组收益。

这使因子研究可以独立运行，同时保证同一因子定义可以进入下游策略。

### 3.3 批量与增量双接口

因子以 pandas 面板上的批量纯计算为第一接口：

```python
Factor.compute(df) -> pd.Series
```

实验编排器只把因子声明的 `required_columns` 组成输入视图传给因子，不把标签和无关字段暴露给因子。V1 同时提供批量接口和增量接口：批量接口服务历史研究，增量接口服务逐 Bar 更新和策略接入；二者必须遵守同一时间语义并通过等价性测试。V1 不建设复合因子抽象、因子注册中心或查询系统。

### 3.4 配置与结果显式化

研究过程中的品种池、样本区间、频率、因子参数、标签期限、预处理和评价方法都必须进入配置或结果元数据，不能只存在于 notebook 局部变量中。

## 4. 系统边界

### 4.1 模块负责

- 从 `DataFacade` 组装单品种或多品种研究面板。
- 构建并记录历史动态品种池。
- 校验索引、字段、唯一性、排序和基础数据质量。
- 定义并计算时序因子和横截面因子。
- 构造严格向前看的未来收益标签。
- 对因子执行可配置、时间语义明确的预处理。
- 计算覆盖率、IC、Rank IC、分组收益、衰减、换手、归因、稳健性和冗余等诊断。
- 组织可复现的研究实验。
- 输出结构化结果、报告和候选因子交付物。
- 向策略层提供通用、支持增量更新和多因子输入的适配接口。

### 4.2 模块不负责

- 将因子值映射成最终目标仓位。
- 资金分配、组合风险预算和保证金约束。
- 订单生成、撮合、手续费和滑点。
- 账户 PnL、权益和绩效回测。
- 自动判定一个因子在经济意义上“有效”。

最后一点必须由研究者结合统计证据、经济解释、交易成本和样本外结果判断。

## 5. 统一研究数据契约

### 5.1 ResearchDataset

`ResearchDataset` 是因子模块内部统一输入，不改变 `ResearchFeed` 的职责。其核心数据采用长表面板：

```text
index: MultiIndex[timestamp, product]

required columns:
    trading_date
    Dominant_Contract
    Adj_Open / Adj_High / Adj_Low / Adj_Close
    Raw_Open / Raw_High / Raw_Low / Raw_Close
    Volume
    OpenInterest
    True_Return
    is_roll

optional term-structure columns:
    Near_Contract / Near_Close / Near_DaysToExpiry
    Far_Contract / Far_Close / Far_DaysToExpiry
```

约束如下：

- `timestamp` 表示该 Bar 的日历结束时间，索引必须有序且唯一。
- `product` 统一为大写品种代码。
- 每一行表示一个品种的一根已结束 Bar。
- 不同品种不要求每个时间戳都有数据，缺失必须保留为面板事实，不能任意前向填充价格或因子。
- `ResearchDataset` 保存 `start_date`、`end_date`、`freq`、`view`、动态品种池配置和数据来源配置等元数据。
- 所有计算组件不得原地修改输入面板。
- 展期收益率实验通过期限结构数据适配器，把选定近远月合约字段对齐到主研究面板；原始多合约明细仍由数据提供者维护，不在因子中临时查询或猜测。

### 5.2 期货价格字段语义

- 因子若研究连续价格趋势，默认使用 `Adj_*`，避免主力切换价格跳空污染预测变量。
- 物理价格 `Raw_*` 主要用于检查市场状态和解释换月，不直接跨合约计算连续收益。
- 未来收益标签优先由 `True_Return` 复合构造，不直接使用等差复权价格的百分比变化替代真实收益。
- `Dominant_Contract` 和 `is_roll` 必须保留，以支持换月期归因和数据质量检查。

### 5.3 True_Return 契约

因子模块要求 `True_Return[t]` 明确表示从同一可比物理合约的 `t-1` 收盘到 `t` 收盘的一期收益。h 期未来标签定义为：

```text
forward_return_h[t]
    = product(1 + True_Return[t + j], j=1..h) - 1
```

因此：

- 当前行的 `True_Return[t]` 不属于 `t` 时点之后的标签。
- 标签必须按品种独立构造，绝不能跨品种或跨面板缺口串联。
- V1 开发前必须通过人工换月样本验证 `ResearchFeed` 的 `True_Return` 端点对齐；若现有实现与该契约不一致，应先修正数据契约或增加明确适配，禁止因子模块静默猜测。

## 6. 核心领域对象

### 6.1 DatasetSpec

描述研究数据请求：

- `products`
- `start_date`
- `end_date`
- `freq`
- `view`
- `UniverseSpec`
- 可选字段和基础过滤条件

V1 只支持日频，并同时支持显式静态列表和动态历史品种池。`UniverseSpec` 至少记录品种上市时长、历史窗口、日成交量或滚动平均成交量、数据覆盖率等准入条件；所有条件及其生效时点必须进入实验配置。

### 6.2 FactorDefinition

因子定义包含：

- 稳定名称和说明。
- 参数及其可序列化表示。
- 必需输入列。
- 因子类型：`time_series` 或 `cross_sectional`。
- 最小历史窗口。
- `compute(df) -> pd.Series`。
- `initialize_state() -> FactorState`。
- `update(state, timestamp_df) -> IncrementalFactorResult`。

输入 df 只包含因子声明的字段和规范面板索引，因此因子不依赖完整 `ResearchDataset`，策略层也不需要伪造 `True_Return` 等评价字段。输出 Series 必须：

- 与输入面板索引对齐。
- 名称唯一且稳定。
- 允许因历史窗口不足产生 NaN。
- 不得删除或重排行。
- 不得声明或访问标签列。

批量接口和增量接口均在 V1 实现。增量输入 `timestamp_df` 表示同一时间戳下已经可见的品种截面，使时序因子和横截面因子能够共享接口；批量结果是语义基准，增量结果必须与其逐时点对应。

`FactorState` 只保存滚动窗口、累计统计量等计算状态，不保存标签、策略权重、仓位或账户状态；状态必须支持重置和序列化，以便实验恢复和策略热启动。

### 6.3 FactorResult

保存：

- 因子名称和参数。
- 因子值 Series。
- 必需输入字段。
- 计算时间和样本摘要。
- 缺失率、有效起点等基础质量信息。

冻结 dataclass 只能防止属性重新绑定，不能使 DataFrame 真正不可变，因此实现仍需遵守“不原地修改”的约定并由测试保护。

### 6.4 LabelDefinition 与 LabelResult

标签定义必须显式记录：

- 收益来源列。
- 预测期限。
- 收益口径。
- 对齐方向。
- 最低有效观测要求。

标签只供评价器使用，不得进入因子输入。V1 支持多期限真实收益、收益方向、未来实现波动率、基准或风险暴露调整后的残差收益，以及配置化事件标签；每种标签都必须明确预测期限、端点和缺失传播政策。

### 6.5 EvaluationConfig 与 FactorEvaluationResult

评价配置记录：

- `time_series` 或 `cross_sectional` 评价模式。
- 标签期限。
- IC 最小样本数。
- 分组数量和分组方向。
- 缺失值政策。
- 年化或统计汇总参数。

评价结果采用结构化表格保存明细和汇总，不以一张图片作为唯一结果。

### 6.6 ExperimentConfig 与 ResearchResult

实验配置组合动态品种池、数据、一个或多个因子、单因子预处理、跨因子矩阵预处理、标签、评价、样本划分、参数网格、缓存、并行和报告配置。`ResearchResult` 至少包含：

- 因子值。
- 标签。
- 覆盖率结果。
- IC 和 Rank IC 明细及汇总。
- 分组收益和多空组收益。
- 衰减结果。
- 换手结果。
- 稳健统计、多重检验和参数敏感性结果。
- 分品种、分时期、分品种组和分市场状态结果。
- 因子相关性、正交化和冗余分析结果。
- 警告和被排除样本的原因。
- 实验 ID、配置哈希、数据指纹、Git 提交和运行环境等元数据。

### 6.7 CandidateFactor

`CandidateFactor` 是研究层向策略层的交付物，保存因子定义、参数和研究证据引用。它不是交易信号，也不自动包含目标仓位。

是否成为候选因子由研究者明确决定，框架不能只根据单个阈值自动批准。

## 7. 子系统设计

### 7.1 DatasetBuilder

职责：

- 对每个品种调用 `DataFacade.get_historical_vector(...)`。
- 添加并规范化 `product` 维度。
- 合并为统一长表面板。
- 校验必要列、索引类型、唯一性、时间顺序和字段类型。
- 生成数据质量摘要。
- 根据 `UniverseSpec` 在每个历史时点生成可研究品种集合。

V1 只处理日频数据，支持 `scheduled` 或 `realized` 视图、串行或并行加载、静态列表和动态品种池。动态品种池至少支持：

- 品种上市或拥有有效数据达到最短时长。
- 过去固定窗口内达到最小有效观测数和覆盖率。
- 日成交量或滚动平均日成交量达到流动性阈值。
- 可选的持仓量、可交易状态和研究者指定排除条件。

过滤只能使用准入时点已经可见的数据。若策略在 t 日收盘后决策，允许使用 t 日成交量；若配置为开盘前确定品种池，则只能使用 t-1 及以前信息。品种池参数和判定时点必须完整进入 `ExperimentConfig`。

V1 可以通过缓存和并行读取提高批量实验速度，但多品种面板的对齐、缺失和准入政策始终由因子模块负责。

### 7.2 FactorLibrary

V1 因子库直接保存具体因子实现，不建设因子族层级、复合因子框架或注册查询系统。首批基础因子为：

- 时间序列动量。
- 横截面动量。
- 展期收益率。

后续按实际研究需要增加基差动量和仓单变化率因子。展期收益率需要同一品种多个可比合约的价格、到期信息和流动性信息，不能仅凭主力连续价格可靠计算；V1 必须通过数据引擎或可注入数据提供者取得期限结构数据。基差动量和仓单变化率所需的现货、仓单等外部数据源在对应因子开发时再明确接入。

### 7.3 PreprocessingPipeline

预处理是独立组件，不写进具体因子：

```text
raw factor
    -> invalid-value handling
    -> winsorization
    -> neutralization
    -> normalization
    -> cross-factor orthogonalization
    -> smoothing / denoising
```

时间语义要求：

- 横截面变换只能使用同一时间戳的当期截面。
- 时序变换只能使用当前及过去数据。
- 禁止使用全样本均值和标准差生成历史时点可交易因子。
- 任何需要拟合的变换只能在训练窗口拟合，再应用于验证集或样本外。
- 预处理顺序会改变结果，完整步骤和参数必须进入实验配置。

V1 包含：

- 缺失值、无穷值和异常值处理。
- 横截面与滚动时序缩尾。
- z-score、robust z-score、秩归一化和分位数归一化。
- 行业/品种组、波动率、成交量/流动性、持仓量和展期收益率中性化。
- 回归残差化和因子正交化；正交化方法及因子顺序必须显式记录。
- 只使用历史数据的移动平均、指数加权、截尾或其他平滑降噪方法。
- 具有 `fit/transform` 语义的可拟合变换器。

单因子变换与跨因子矩阵变换必须分开建模，避免让普通 `FactorPreprocessor` 隐式依赖其他因子。

### 7.4 LabelBuilder

V1 支持多期限未来复合收益、收益方向、未来实现波动率、基准或风险暴露调整后的残差收益，以及配置化事件标签，并严格保留尾部 NaN。

标签构造与因子计算分开执行。`FactorDefinition.required_columns` 不允许包含任何标签列。

### 7.5 FactorEvaluator

#### 覆盖率

输出总体、分时点、分品种覆盖率和有效样本数。

#### IC 与 Rank IC

- 横截面 IC：每个时间戳在品种截面上计算，再对时间序列汇总。
- 时序相关：每个品种沿时间计算，必须明确命名为 time-series correlation，不得伪装成横截面 IC。
- 样本不足时返回 NaN 和原因，不返回误导性的零。

V1 支持 Pearson IC、Spearman Rank IC、均值、标准差、ICIR、正值比例、样本数、稳健标准误、bootstrap 置信区间和多重检验控制。

#### 分组收益

- 横截面模式在每个时间戳内按因子值分组。
- 明确处理重复值、组数不足和有效品种不足。
- 输出各组未来标签均值和最高组减最低组。
- 该结果是等权诊断组合，不含成交、成本和资金约束。

#### 衰减、换手、归因和稳健性

V1：

- 用多个标签期限形成衰减表。
- 计算分组成员变化和标准化权重变化形成换手指标。
- 输出分品种、分时期、分品种组、分市场状态和分交易所结果。
- 分析因子容量、流动性条件、成本代理和稳定性。
- 分析因子间相关性、冗余性和边际解释能力。
- 执行样本内外、walk-forward、参数敏感性和多重检验。

### 7.6 ExperimentRunner

固定编排顺序：

1. 构建并校验研究数据。
2. 计算原始因子。
3. 执行预处理。
4. 构造未来标签。
5. 对齐因子、标签和研究范围。
6. 运行各评价器。
7. 汇总元数据、警告和结果。
8. 生成报告或候选因子交付物。

V1 提供实验 ID、完整配置、随机种子、参数网格、样本划分、配置哈希、数据指纹、Git 提交、持久化结果仓库、缓存复用、批量调度和可配置并行执行。并行执行不得改变结果顺序、随机性和实验身份。

### 7.7 ReportBuilder

V1 支持两种输出模式：

- 核心表格：只输出结构化指标表和必要元数据，适合批量筛选。
- 完整 tear sheet：输出一份标准化 HTML 报告，设计借鉴 [Alphalens-Reloaded](https://alphalens.ml4trading.io/) 的收益、IC、换手和分组分析，并增加适用于期货的动态品种池、覆盖率、因子衰减、流动性、展期收益率暴露、稳健性和归因页面。

tear sheet 是本系统自己的报告契约，不直接把股票假设照搬到期货，也不要求运行时强依赖 Alphalens-Reloaded。

### 7.8 Strategy Integration

因子层只输出因子值。策略层负责：

```text
factor value
    -> signal rule
    -> position sizing
    -> TargetPosition
```

V1 直接提供通用策略适配器：

- 将 `BarMarketEvent` 和策略历史视图转换为因子声明的输入结构。
- 调用因子增量接口，维护各因子的独立状态。
- 在同一决策时点同步多个因子值并交给策略侧组合模型。
- 处理热身期、缺失值、品种池进入/退出和状态重置。

多因子组合属于策略侧的信号模型，不建立 `CompositeFactor`；策略负责权重、方向、阈值和仓位映射，因子模块仍只提供预测变量。

## 8. 完整目录结构

```text
factors/                     <-- 因子研究模块，封装从研究数据到候选因子的完整流程
    __init__.py              <-- 统一导出稳定的公共接口
    base.py                  <-- 定义 Factor 抽象接口及通用契约校验
    models.py                <-- 定义数据集、因子、标签、评价结果和候选因子等领域对象
    dataset.py               <-- 从 DataFacade 构建、校验并描述统一研究面板
    preprocessing.py         <-- 实现因子清洗、缩尾、标准化和预处理流水线
    labels.py                <-- 构造与因子严格隔离、向前对齐的研究标签
    experiment.py            <-- 定义实验配置、结果对象并编排完整研究流程
    reporting.py             <-- 将结构化研究结果整理为表格、文件和标准报告
    universe.py              <-- 管理动态品种池、历史准入条件和样本资格
    storage.py               <-- 持久化实验、数据指纹和缓存结果以支持复现与复用

    library/                 <-- 保存具体因子实现，不提供因子族、复合或注册机制
        __init__.py          <-- 导出当前实际使用的因子定义
        momentum.py          <-- 实现时间序列动量和横截面动量
        carry.py             <-- 基于期限结构数据实现展期收益率因子
        basis.py             <-- 按后续研究需求实现基差动量因子
        warehouse.py         <-- 按后续研究需求实现仓单变化率因子

    evaluation/              <-- 组织因子预测能力、稳定性和冗余性的诊断组件
        __init__.py          <-- 导出评价模块的公共接口
        ic.py                <-- 计算 IC、Rank IC 及其统计汇总
        grouped.py           <-- 计算因子分组未来收益和组间差异
        diagnostics.py       <-- 计算覆盖率、衰减、换手等通用诊断
        attribution.py       <-- 分解因子在品种、时期和市场状态中的表现来源
        robustness.py        <-- 执行稳健推断、重采样和多重检验
        redundancy.py        <-- 分析因子相关性、重复信息和边际解释能力
        evaluator.py         <-- 按配置统一编排各项评价并汇总结果

strategy/                    <-- 将候选因子组织为信号、仓位和可交易策略
    factor_adapter.py        <-- 将策略历史视图转换为因子输入并复用同一因子定义
```

目录采用中等扁平结构：核心接口、模型、数据集、标签、预处理、实验和报告直接放在 `factors/` 顶层；只有会自然扩展出多个实现的因子库和评价器保留子包。`factors/data/` 不再建立，以免与仓库顶层 `data/` 混淆。

`CandidateFactor` 归入 `models.py`；不建立单独的 `integration/` 生产包；通用策略适配器位于依赖方 `strategy/`，保持 `strategy -> factors` 的依赖方向。

V1 创建代码写作方案列出的实际文件，其中 `basis.py` 和 `warehouse.py` 在相应数据源和研究需求明确后添加。若 `experiment.py` 等文件以后因真实复杂度明显膨胀，再按职责拆成子包，而不提前搭建空壳。

## 10. 架构不变量

以下规则从 V1 起必须由测试保护：

- 因子值在时点 t 只能使用 t 及以前可见的数据。
- 未来标签只能使用 t 之后的数据，且不得进入因子计算。
- 因子和标签必须按 `timestamp, product` 精确对齐。
- 所有滚动和滞后操作必须在品种内部执行。
- 横截面处理必须在同一时间戳内部执行。
- 动态品种池在时点 t 只能使用其准入判定时点已经可见的数据。
- 可拟合预处理器只能在训练集拟合，样本外数据不得参与参数估计。
- 输入面板不得被因子或评价器原地修改。
- NaN 必须区分窗口不足、未来标签不足、原始缺失和过滤排除。
- 单品种结果不得冒充横截面 IC。
- 分组收益不得被称为账户收益或策略净收益。
- 相同数据和配置必须产生相同结果。
- 因子批量计算与逐时点增量计算必须产生等价的因子值。
- 多因子组合不得反向改变原始因子值或因子状态。

## 11. 错误与警告策略

直接报错：

- 必需字段缺失。
- 面板索引重复或未按规范命名。
- 因子输出索引与输入不一致。
- 标签跨品种构造。
- 因子声明依赖标签列。
- 非法预测期限、分组数或最小样本数。
- 同一实验中因子名称冲突。
- 动态品种池过滤器依赖判定时点尚不可见的数据。
- 中性化、正交化或平滑配置缺少拟合窗口和生效时点。

保留结果并给出警告：

- 某些时点截面样本不足。
- 某些品种历史窗口不足。
- 因子覆盖率低于配置阈值。
- 某些品种因上市时长、流动性或数据覆盖率不足被排除。
- 分组因重复值无法形成预期组数。
- 尾部未来标签自然缺失。

所有警告应进入 `ResearchResult`，不能只打印到控制台。

## 12. 测试体系

### 12.1 人工面板单元测试

核心测试只使用小型人工面板，覆盖：

- 两个以上品种、非完全重合交易日。
- 趋势、反转、常数和全缺失因子。
- 因子重复值和分组不足。
- 换月点和 `True_Return` 对齐。
- 多期限标签尾部缺失。

### 12.2 因果性测试

修改时点 t 之后的价格，t 及之前的因子值必须完全不变。标签可以变化。这是因子模块最重要的黄金不变量。

### 12.3 手工黄金路径

使用可手算面板逐项验证因子值、未来收益、IC、Rank IC、分组收益、衰减和换手。

### 12.4 批量与增量接口测试

将同一人工面板一次性送入批量接口、再按时间戳逐批送入增量接口，两条路径必须产生等价的因子序列。测试同时覆盖热身期、横截面同步、品种池进入/退出和状态重置。

### 12.5 真实数据冒烟测试

通过 `DataFacade` 加载少量日频品种，运行完整研究实验。该测试依赖本机数据，应与不依赖外部数据的核心回归测试分开。

## 13. 主要风险与待确认事项

- 已确认：换月时点 `t` 的 `True_Return[t]` 使用新主力合约在 `t` 与 `t-1` 的价格计算，并写入 `roll_date`；日频分支符合该端点语义。
- 多品种研究在 V1 由因子模块逐品种调用 `DataFacade.get_historical_vector()`，再由 `ResearchDatasetBuilder` 负责拼接、时间对齐和缺失政策。未来如出现读取性能瓶颈，数据引擎可以增加批量获取接口，但研究面板的组织仍由因子模块负责。
- 期货产业分类采用 `asset_class / sector / subsector / supply_chain` 等分层或多标签结构，用于动态品种池、归因、风险集中度和可选中性化；V1 需要新增可靠、可追溯的分类元数据。
- 仓库缺少依赖清单。V1 的稳健统计、持久化、并行和 tear sheet 会使用 pandas、NumPy、SciPy、statsmodels、PyArrow、Matplotlib、Seaborn 等组件，开发前必须建立并锁定正式依赖清单。
- 展期收益率需要多合约期限结构数据；当前单一主力连续序列不足以完整计算该因子，V1 开发前必须确定数据引擎接口或可注入的数据提供者。
- 日内因子研究明确不属于当前架构。未来若有需求，应单独讨论数据、标签、评价、成本和策略交付，不在日频管线中增加 `freq` 分支硬接。
- 研究中使用 `scheduled` 或 `realized` 视图会影响结论口径，实验元数据必须记录。
- 因子研究和事件回测是反馈循环。高换手、流动性和成本问题可能推动因子重新设计，候选因子不能被视为一次性最终交付。

## 14. V1 完成标准

V1 完成后，系统应当能够：

- 在统一日频多品种研究面板上，按历史可得信息构建动态品种池。
- 通过批量和增量接口定义、计算和复用时序及横截面因子。
- 研究时间序列动量、横截面动量和展期收益率三个基础因子。
- 完成缩尾、归一化、中性化、正交化、平滑降噪等完整预处理。
- 可靠构造多种未来标签并证明无未来信息。
- 完成标准因子诊断、稳健性检验、归因和参数实验。
- 保存可复现的实验配置、数据指纹、代码版本和结果。
- 对大量因子和参数进行可缓存、可并行的批量研究。
- 按需输出核心表格或标准化因子 tear sheet。
- 将候选因子通过通用适配器按增量方式交给策略层，并支持多因子组合输入。
- 保持与账户、执行和回测基础设施的单向低耦合。

`V2` 在本阶段没有预定义完成标准。
