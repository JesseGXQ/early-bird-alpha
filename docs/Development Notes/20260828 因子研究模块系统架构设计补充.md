# 因子研究模块系统架构设计补充

> 文档定位：本文补充[《20260723 因子研究模块系统架构设计》](<./20260723 因子研究模块系统架构设计.md>)中尚未覆盖、但会影响后续开发方向的架构语义。本文只记录原则、组件职责与开发提示，不在当前阶段确定具体类字段、公共 API 或算法实现。以后新增的补充主题应继续写成新的独立章节。

## 1. 组合收获语义与有效标签对齐

### 1.1 背景与结论

因子研究不能只回答“因子与哪一种未来收益相关”，还要回答“下游组合通过怎样的权重映射，能够收获收益中的哪一部分”。研究链路应补充为：

$$
\text{组合任务}
\rightarrow
\text{权重映射}
\rightarrow
\text{可收获收益}
\rightarrow
\text{评价口径}
\rightarrow
\text{诊断组合实验}
$$

若研究时刻的权重映射为 $w_t=A_tf_t$，则组合收益可写成：

$$
w_t^\mathsf{T}r_{t+1}
=
f_t^\mathsf{T}A_t^\mathsf{T}r_{t+1}
$$

此时 $A_t^\mathsf{T}r_{t+1}$ 是与该组合任务对齐的有效收益标签。若权重映射包含排序、仓位边界、协方差优化、换手惩罚或其他动态非线性约束，则通常不存在唯一且长期固定的有效标签，评价必须进一步依赖组合实验。

### 1.2 原架构的设计缺失

原架构已经区分时序评价与截面评价，也支持残差收益标签、IC、Rank IC、分组收益和因子诊断，但仍缺少以下连接层：

| 缺失 | 造成的问题 |
|---|---|
| 缺少对下游收获方式的显式描述 | 相同因子用于全市场排名、板块中性或时序 CTA 时，系统无法自动选择匹配的标签、指标和组合实验 |
| 将 `residual_return` 直接视为基础标签方法 | 混合了“预测对象是什么”与“为了某个组合任务怎样观察预测对象”两种语义 |
| `EvaluationConfig` 主要表达时序/截面估计方式 | 无法表达中性约束、风险缩放、风险预算、组合目标和成本近似 |
| 指标集合与下游任务未建立选择规则 | 容易把通用 IC 当作部署价值，或者计算了正确的统计量却使用了错误的样本、权重和控制变量 |
| 统计诊断之后直接交给策略/回测层 | 缺少成本较低、用于验证信号到连续权重映射的研究级组合实验 |
| 缺少有效标签的来源与精确性元数据 | 系统无法区分精确线性等价、局部代理和不可用单一标签表示三种情况 |

其中，残差收益本身并非不允许成为基础标签。如果研究问题独立地定义为预测某种风险模型残差，它仍可作为原生预测目标；如果残差化只是为了模拟某个下游组合约束，则它应属于评价阶段生成的派生视图，而不是 `LabelSpec` 的固有方法。

### 1.3 应新增的架构概念

后续架构应明确三个彼此独立的维度：

1. **因子计算范围**：因子如何从数据中产生。
2. **评价模式**：统计关系沿时间还是沿截面估计。
3. **组合收获范式**：下游怎样把信号映射为权重，并受何种中性、风险和交易约束影响。

建议补充以下概念职责，名称暂定：

| 概念 | 职责 |
|---|---|
| `LabelSpec` | 只描述基础预测对象、期限、收益口径和时间对齐，不默认携带组合任务语义 |
| `HarvestProfile` | 声明研究所近似的下游收获方式，包括信号映射、中性约束、风险缩放、风险预算、组合目标与成本近似；它不是完整策略配置 |
| `EvaluationTaskSpec` | 把因子、基础标签、评价模式和 `HarvestProfile` 组合为一次完整的评价任务 |
| `AlignmentResolver` | 根据评价任务生成可执行的 `AlignmentPlan`，确定联合样本、配对变换、权重、控制变量、指标套件及是否需要组合实验 |
| `EffectiveLabelView` | 表示评价期内临时生成的有效标签及其来源；它不应冒充新的基础 `LabelResult` |
| `MetricSuite` | 按评价模式与收获范式选择核心指标、辅助诊断及不适用指标 |
| `DiagnosticPortfolioExperiment` | 将信号映射为研究用连续权重，输出毛收益、简单成本后收益、换手、暴露、风险和贡献 |

`EffectiveLabelView` 至少需要表达以下精确性等级：

- `exact_linear`：已知且仅使用时刻 \(t\) 信息的线性映射，可严格构造有效标签；
- `partial_proxy`：只表示权重规则中的一部分，例如只近似风险缩放而未覆盖仓位边界；
- `not_representable`：动态非线性映射不能由单一标签可靠表示，必须以组合实验为主。

### 1.4 研究流程补充

原有“构造标签后直接评价”的流程，应在评价前增加任务解析与联合对齐：

```text
原始数据 → 原始因子 → 因子预处理
                    ├→ 基础标签构造
                    ↓
          EvaluationTaskSpec
                    ↓
           AlignmentResolver
                    ↓
联合样本与 AlignmentPlan
        ├→ 有效标签/配对变换 → MetricSuite
        └→ 必要时运行 DiagnosticPortfolioExperiment
                    ↓
       EvaluationResult + 完整元数据
```

有效标签不宜由 `LabelBuilder` 脱离评价上下文提前物化。因子变换、标签变换、样本掩码、截面权重、暴露矩阵和控制变量必须在同一个 `AlignmentPlan` 中共同确定，否则即使公式正确，也可能因为统计口径不一致而失去组合含义。

### 1.5 系统边界的修订说明

原架构关于分层边界的总体原则仍然成立，但需要增加一个例外说明：

- `factors` 层可以生成**研究级诊断权重与代理收益**，用途仅限于检验因子在指定收获范式下能否转化为组合收益；
- 诊断组合不处理订单、成交、合约张数、保证金、涨跌停、账户状态和真实执行，不输出最终 `TargetPosition`；
- 最终仓位生成、组合优化、交易成本模型及可交易净收益仍属于 `strategy`、`portfolio` 与 `backtester` 等下游层。

因此，新增诊断组合并不意味着把完整回测器搬入因子模块，而是补上“统计相关性”与“完整策略回测”之间缺失的研究验证层。

### 1.6 必须保留的架构不变量

1. 配对评价中的因子、标签、暴露、权重和控制变量必须共享同一时间截面、动态品种池和有效样本掩码。
2. 所有残差化、风险缩放和投影操作必须记录输入口径、参数、拟合窗口及数据指纹，并遵守因果性约束。
3. 只有在权重映射确为已知线性映射时，才可声明有效标签与组合收益严格等价。
4. 对排序、边界、优化器和成本等非线性任务，不得用一个“残差标签”伪装成完整下游目标。
5. 诊断组合收益必须明确标记为研究代理收益，不得与策略净收益或账户收益混用。
6. `HarvestProfile` 负责声明评价假设，不拥有策略实例、优化器运行状态或账户状态。

### 1.7 对原架构章节的影响

| 原架构位置 | 后续修订提示 |
|---|---|
| 4. 系统边界 | 补充研究级诊断组合的有限职责 |
| 6.4、7.4 标签域 | 区分基础标签与由收获范式派生的有效标签视图 |
| 6.5、7.6 评价与诊断域 | 在时序/截面评价之外引入 `HarvestProfile`、`MetricSuite` 和任务解析 |
| 6.6、7.7 实验与编排域 | 在对齐和评价之间加入 `AlignmentResolver`，并按需运行诊断组合实验 |
| 7.9 策略接入 | 保持因子与最终仓位解耦，同时允许研究层声明并近似下游权重映射 |
| 10. 不变量 | 增加有效标签精确性、联合对齐、元数据来源和诊断收益命名约束 |

### 1.8 开发顺序提示

后续进入详细设计时，建议依次处理：

1. 清理基础标签与任务派生标签的分类边界；
2. 定义 `EvaluationTaskSpec`、`AlignmentPlan` 和 `EffectiveLabelView` 的最小信息契约；
3. 先实现少量明确映射：恒等收益、市场/板块残差、逆波动率缩放、风险加权板块残差；
4. 对无法由固定标签表示的任务，统一转入诊断组合实验；
5. 最后扩展评价结果、元数据、缓存键与测试不变量。

本章只用于约束未来开发方向。在真正修改 `LabelSpec`、`EvaluationConfig`、实验编排或公共接口之前，仍需单独完成详细设计与迁移方案。
