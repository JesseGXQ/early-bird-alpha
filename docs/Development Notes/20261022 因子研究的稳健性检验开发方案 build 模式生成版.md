# 因子研究的稳健性检验开发方案

日期：2026-10-22
状态：开发规划；本文不表示相关能力已经实现。

## 1. 文档定位与核心决策

本文承接[《因子研究闭环与组合实验层开发方向》](<./20260924 因子研究闭环与组合实验层开发方向.md>)第 9.3 节，规划因子研究下一步立即可用的稳健性检验工具。开发方法遵循[《因子合成模块演化式开发方案》](<./20261019 因子合成模块组件开发方案.md>)：以具体研究问题牵引基础设施，先交付语义正确的最小工具，在真实研究出现稳定重复之后再抽象。

第一阶段聚焦四个问题：

| 研究问题 | 最小交付 |
|---|---|
| 效果是否只存在于用于设计因子的历史？ | 按时间划分训练、验证与最终保留样本，显式处理标签成熟度 |
| 如果按当时可见的信息持续研究和更新，效果是否仍然存在？ | rolling / expanding walk-forward 划分、逐折选择记录和连续研究收益 |
| 效果是否依赖一个孤立的参数尖峰？ | 预先声明的小型参数邻域、可比样本和完整结果表 |
| 看过许多候选后，显著性是否只是偶然？ | 完整候选／检验清单、有效的原始 p 值、明确检验族的多重校正 |

**第一阶段建设少量纯函数和一份可修改的研究示例，不建设独立的稳健性框架。** 不增加统一 Runner、插件注册、实验 DAG、优化器、配置 DSL、通用拟合状态体系或报告平台。

最小可行不意味着可以省略研究边界。时间可得性、标签完整性、样本外使用规则、仓位衔接和检验族定义属于首版正确性要求；大型对象体系和自动编排属于可延迟的工程便利。

## 2. 现有代码与复用边界

以下判断以当前代码为准，早期架构文档中的类名不直接视为现有能力。

| 现有位置 | 当前能力 | 本轮关系 |
|---|---|---|
| `factors/combination.py` | 等权、投票、排名、IC/ICIR 加权；监督算子有 `fit/transform` 边界 | 每折新建实例，交付已经切好的训练样本，不修改合成器职责 |
| `factors/preprocess/` | 拟合型预处理和截面预处理等 | 调用方区分需要冻结的估计量与允许因果更新的规则 |
| `factors/labels.py`、`LabelResult` | 标签值与定义；目前没有逐行的完整成熟／可得时间 | 在研究适配代码中补充时间序列，不先扩充核心领域模型 |
| `factors/evaluation/ic.py` | 截面 IC 时间序列、HAC 均值检验、循环块 bootstrap；时序 IC 按品种汇总 | 可复用合适的统计输出，不把跨品种 IC 当成时间序列 |
| `factors/evaluation/regression.py` | 截面系数时间序列推断、逐品种 HAC 回归、pooled 固定效应与双向聚类 | 需要预测系数检验时直接使用，记录实际模型与推断口径 |
| `factors/evaluation/robustness.py` | `adjust_pvalues` 对非空 p 值调用 statsmodels 校正 | 收紧输入和缺失语义，补齐方法与样本数记录；不另写校正算法 |
| `factors/diagnostic_portfolio/` | 信号到连续研究权重、下一期收益、换手、成本与归因 | 作为独立实验工具调用；不让它理解 train / validation / test |
| `factors/diagnostic_portfolio/storage/` | 保存实际输入、结果和重放依据 | 引用已有 run_id，不建立第二套组合结果仓库 |
| `research/io.py`、`research/README.MD` | 轻量评价导出和研究目录约定 | 研究脚本保存划分、候选清单与结论；核心模块不反向依赖 `research/` |

现有 `adjust_pvalues` 会删除 NaN 后按剩余数量校正，缺失检验的 `rejected` 初始为 False，且方法与 alpha 未写入结果。这可以用于简单探索，但不足以表达“声明的整个检验族已经接受校正”。本轮应明确修正，而不是再包一层后默认沿用。

另一个必须正视的接口事实：组合实验将决策时间 `t` 的权重与成本计入下一全局时点的收益。稳健性工具不能用相同的日期切片同时截取信号、权重和收益，再假设三者处于同一时钟。

两项接入限制也需要在开发前明确：

- `FittedTimeSeriesZscore` 的当前 `transform` 会调用拟合，并且禁止应用窗口与拟合窗口重叠；它不是一个可以直接在训练特征和应用特征上任意调用的 sklearn 式转换器。首版示例先使用无需估计历史参数的因果处理，监督拟合重点验证 IC/ICIR 合成；不为适配稳健性研究而重构预处理生命周期。以后接入拟合型尺度处理时，必须单独核验训练特征变换与第一笔应用信号的可调用边界。
- `DiagnosticSignal.source_stage` 目前只接受 `raw` 与 `preprocessed`。若示例包括复合信号的组合重放，本轮允许一个局部接入修改：增加 `composite` 枚举值与往返测试，在 recipe 中记录合成配方及逐折拟合引用；不把复合因子谎称为原始／预处理单因子，也不增加新的信号领域对象。

## 3. 研究结论的层次

稳健性不是一个最终的通过／失败分数。首版保留三层证据：

1. **预测证据**：IC、Rank IC、回归系数及其覆盖率，反映预测关系是否延续。
2. **收获证据**：固定组合规则下的毛收益、代理净收益、Sharpe、回撤、换手及贡献，反映信息能否被收获。
3. **选择证据**：候选集合、选择规则、拟合时间、最终保留期和多重检验，反映结果经过多少选择。

例如，IC 在多个时期方向一致、但成本后收益消失，结论应是“预测关系存在，当前收获规则未形成稳定经济价值”；不能只用显著 IC 宣称组合稳健。反之，组合收益为正但高度集中于一个品种，也不能仅凭总 Sharpe 宣称预测关系普遍成立。

本轮利用现有品种／板块归因作为背景证据，但不建设新的分状态、leave-one-out 或成本压力测试组件。

## 4. 第一阶段范围与责任

### 4.1 核心工具负责

- 在调用方交付的共同时间轴上产生可审查的时间划分表。
- 根据明确的标签结束／可得时间生成布尔掩码。
- 对一条具有明确时间含义的序列进行简单 HAC 均值检验。
- 对调用方声明的单个完整检验族校正 p 值。
- 校验输入，保留失效信息，不修改输入。

### 4.2 研究脚本负责

- 获取数据，计算基础因子、预处理、标签与动态品种池。
- 声明候选、方向、邻域、评分指标、选择规则和最终保留期。
- 构造标签时间信息，执行逐折拟合、验证选择和可选的重新拟合。
- 调用现有评价与组合实验组件，形成可比表格。
- 合成按历史时点有效的信号路径，连续重放诊断组合。
- 保存轻量研究记录，解释结果和限制。

首版不把这些职责变成回调协议。研究者直接写 Python 循环，是刻意保留研究过程可见性的选择；真正反复出现且稳定的部分以后再提取。

## 5. 时间与信息边界：首版最重要的契约

### 5.1 三类时间必须区分

对于因子行 `(t, p)`，区分：

- `t`：信号所属的决策时间，因子只能使用截至此时可见的信息。
- `label_end[t, p]`：完整标签使用到的最后一个未来观测时间。
- `label_available_at[t, p]`：完整标签实际能够用于拟合／评价的最早时间。

通常日频收盘收益标签可以令 `label_available_at = label_end`。遇到结算、延迟发布或修订数据时，这个等式不自动成立。只有确认立即可得的标签，才允许调用方显式传入相同序列。

同一个收盘时间戳内采用明确顺序：当期数据到达 → 完成截至该时刻的拟合／选择 → 计算信号和权重 → 计入下一期研究收益。这沿用诊断组合的代理时间假设，不等于已经证明能够按当日收盘价真实成交。

### 5.2 共同时间轴

第一阶段仅支持当前日频研究。切分长度按**共同研究时间轴上的交易日位置**计数，不按面板行数、自然日数或单个品种的非空观测数计数。同一天的所有品种属于相同的时间角色，不进行随机拆行。

调用方提供唯一、升序、无 NaT、时区口径一致的 `pd.DatetimeIndex`。它必须来自已经核验的研究交易日历／完整日频面板，不能从某个因子的 `dropna()` 结果反推。没有任何品种行情的一天也不能因为静默丢行而压缩时间。

当前组合实验从主面板唯一时间戳构建时间轴，代码中也保留了权威日历尚待完善的说明。因此示例应先核验主面板时间轴与所选日历一致；不一致就停止该实验，不在稳健性层静默补齐行情或修改数据引擎。

### 5.3 标签成熟掩码

设名义样本窗口为闭区间 `[a, b]`，信息截止时间为 `c`。用于拟合或预测关系评分的行至少满足：

\[
a \le t \le b,\qquad
label\_end_{t,p}\le b,\qquad
label\_available\_at_{t,p}\le c.
\]

此外要求完整标签时间已知、标签数值有效、因子满足该次评价的共同有效样本要求，并且动态品种池合格。时间函数只负责时间掩码；数值完整性与品种池由调用方在外部合并。

训练时通常 `b = c = train_end`；验证评分时 `b = c = validation_end`。重新拟合训练＋验证时，把它作为一个新的历史窗口，重新按 `b = c = validation_end` 生成成熟掩码，不能直接拼接旧的两个评分掩码。后者可能漏掉此时已经成熟的跨原训练／验证边界标签。

该规则同时避免训练标签引用验证收益、验证指标引用最终保留期收益。最终保留期也只评分完整落在其末端之前的标签，不为凑样本缩短预测期限。

### 5.4 当前标签实现的必要适配

当前前瞻标签通过**逐品种行移位**构建，且 `LabelSpec.min_valid_obs` 默认是 1。因此，一个名为 h 期的标签可能在尾部不足 h 个未来观测时仍然非空。`notna()` 不能作为完整成熟的证明。

首轮研究适配必须做到：

1. 对固定期限标签使用完整 h 期口径；收益／方向标签明确令 `min_valid_obs=h`。其他标签也核验完整观测数，不假设所有类型都以同样方式使用该参数。
2. 使用与标签构造一致的、未按因子有效性删行的逐品种源索引，取得第 h 个未来观测的时间，形成 `label_end`；不能简单加 h 个自然日。
3. 对不足 h 个未来观测的尾行，`label_end` 为 NaT，即使旧标签数值非空也排除。
4. 任一组成未来观测缺失时，不把“不足 h 期的部分收益”冒充完整标签。
5. 核验源索引确实符合预期交易日历。若缺行导致 h 个品种观测不等于 h 个研究交易日，停止并先解决标签／数据定义；不在这里猜测修补。

逐行 `label_end` / `label_available_at` 在首版由研究适配代码提供，不新增 `LabelResult` 字段，也不让合成器推断成熟度。未来支持事件标签时，必须交付事件的实际结束与可得时间，不能沿用固定 h 的捷径。

### 5.5 手算边界例子

设有共同交易日 `d1 ... d12`，完整 3 期标签使用 `t+1 ... t+3`，训练窗口截止 `d6`，验证窗口为 `d7 ... d10`：

- 训练行 `d3` 的标签结束于 `d6`，在 `d6` 收盘后可用于拟合。
- 训练行 `d4` 的标签结束于 `d7`，不能用于 `d6` 的拟合。
- 验证行 `d7` 的标签结束于 `d10`，可进入验证预测评价。
- 验证行 `d8` 的标签结束于 `d11`，不能进入截止 `d10` 的验证评分。
- 到 `d10` 重新拟合时，原训练行 `d4` 已经成熟，可以进入新的历史训练窗口。

短窗口会因此剩下很少样本，这是正确的失败信号；不能放松完整期限来让实验跑通。

### 5.6 purge、gap 与 embargo 的边界

这里的 purge 是删除跨越拟合／评分边界的标签行，而不是机械删除因子回看窗口长度那么多天。验证期因子使用更早的历史价格暖机完全合法；历史特征窗口重叠本身不是未来泄漏。

第一阶段采用严格向前的划分，每次拟合不使用当期测试之后的数据；依靠实际标签端点和可得时间清理边界，**不另外实现通用 embargo 或双向交叉验证**。有明确发布延迟时，通过 `label_available_at` 或显式调整研究时间窗口表示；它不是一个默认拍定的 gap。

时序向前、标签成熟和统计独立是三个不同条件。边界没有泄漏，不代表相邻窗口独立，也不代表测试收益没有自相关。时间有序验证的重要性可参考 [scikit-learn 的 TimeSeriesSplit 官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)；本方案不直接把它应用于长面板行索引，也不新增该依赖。

## 6. 样本内、验证集与最终保留样本

### 6.1 三段分别允许做什么

| 区段 | 可以做 | 不能据此声称 |
|---|---|---|
| 训练／样本内 | 提出候选、拟合预处理、确定方向、估计 IC 合成权重 | 对此前未见数据的预测表现 |
| 验证 | 按预定标准比较有限候选、检查参数邻域、确定配方和更新政策 | 完全未参与选择的独立样本外证据 |
| 最终保留样本 `final_holdout` | 配方冻结后进行一次预先声明的确认性评价 | 看结果后再改模型仍属于同一次盲测 |

时间边界由研究者显式指定，不把 60/20/20 或固定年数设为系统默认。长度需要同时容纳因子暖机、标签成熟、足够的评价观测和有意义的市场变化。日期比例只是研究选择，不构成可信度保证。

最终保留期的起止、数据截止时间和是否已经被查看，都写入研究记录。已经用于旧实验、看图、判断方向或修改过滤条件的数据，即使现在重新命名为 test，也不能重新获得“未见”身份。

### 6.2 首版冻结约定

进入最终保留期之前，至少冻结：

- 因子定义、经济方向、成分与合成方法；
- 预处理方法、拟合窗口与更新政策；
- 标签、品种池规则、组合范式、风险规则、调仓锚点、成本率和年化口径；
- 主要评价指标、比较基准、检验假设与检验族；
- 若有适应性更新，冻结候选集合、选择准则、重估频率、失败政策和 tie-break 规则。

冻结的是**完整决策规则**。预先声明的滚动风险估计可以继续利用截至当时的行情；它不等于允许根据保留期表现重新调参。

首版最终保留期示例使用一个冻结配方和固定的监督拟合状态，风险估计按既定因果规则更新。需要在最终保留期内周期性重拟合的研究，可以后续扩展示例，但必须先冻结整个更新政策，并保证每次只使用当时已成熟的历史标签。

### 6.3 验证选择与重新拟合

第一阶段示例使用以下可审查的顺序：

```text
训练期内拟合每个候选
    ↓
冻结候选的拟合状态，在验证期比较
    ↓
按事先声明的规则选出一个配方
    ↓
可选：按既定政策在训练＋验证的成熟样本上重新拟合
    ↓
冻结配方和状态，在最终保留期评价
```

“是否重新拟合”必须在看保留期结果前确定；首版示例默认重新拟合。重新拟合后监督权重可能与验证期不同，因此同时保存验证阶段和最终阶段的权重。验证结果证明的是选择流程的依据，不是最终权重已经在验证期独立获验。

若重新拟合失败，实验记为失败，不隐式退回等权或原候选。研究若需要 fallback，应把它作为另一个事先声明的政策，而非异常处理中的隐藏行为。

拟合型预处理与 IC/ICIR 合成使用每个候选／每折的新实例，避免覆盖前折状态。截面排名等无监督变换可以使用当期合格截面，但不能使用未来品种池或全样本方向选择。

## 7. Walk-forward：检验一条研究与更新政策

### 7.1 与最终保留期的关系

首版建议先在**开发历史**中进行 walk-forward，再打开最终保留期。开发历史可以是固定三段划分中的训练＋验证区间。

每折的 test 称为 `wf_test`，它在产生时未参与该折选择；研究者如果根据所有折结果继续修改配方，这些折总体上已经成为开发证据。必须与仍未查看的 `final_holdout` 分开报告，不能把多次修改后的 walk-forward 曲线称为最终独立盲测。

### 7.2 两种窗口，共用同一套规则

第一阶段支持：

- `rolling`：训练窗口长度固定，随折向前滚动。
- `expanding`：训练起点固定，训练终点随折向前推进。

验证长度与测试长度固定，**步长等于测试长度**，只生成完整折；末端不足一折的尾部记入覆盖说明，暂不支持重叠测试窗、任意 step 和缩短尾折。

以交易日位置、左闭右开的数组切片描述调度公式。设初始训练长 `L`、验证长 `V`、测试长 `H`，第 k 折偏移 `q=kH`：

| 窗口 | rolling | expanding |
|---|---|---|
| train | `[q, q+L)` | `[0, q+L)` |
| validation | `[q+L, q+L+V)` | 相同 |
| test | `[q+L+V, q+L+V+H)` | 相同 |

输出表将这些位置转换为各窗口实际的起止时间，时间边界统一按闭区间解释。`train_size` 是名义时间长度，清理标签后有效训练行数通常更少。

例如 `L=6, V=2, H=2`：第一折训练 `d1...d6`、验证 `d7...d8`、测试 `d9...d10`；第二折 rolling 训练 `d3...d8`、验证 `d9...d10`、测试 `d11...d12`。较早的测试期后来成为验证或训练历史是允许的，但只能在相应数据和标签已经可得后使用。

### 7.3 每折只做一条显式流程

1. 读取该折边界，构造截至训练末端的成熟训练样本。
2. 按预定候选集合，分别拟合预处理与监督合成。
3. 用冻结状态生成验证信号，并按共同验证日历计算预测与收获证据。
4. 使用预定的单一主指标和约束选择候选；其他指标用作解释，不能临时替换主指标。
5. 依据既定政策重新拟合截至验证末端的成熟历史。
6. 在该折测试期生成信号；本折测试结果不影响本折候选与拟合。
7. 记录候选选择、两次拟合窗口、权重、样本数、失败情况和测试证据。

主指标例如成本后 Sharpe，但不写死在基础函数里。研究脚本可先按覆盖率、有效样本、约束有效性等预定条件筛选，再按主指标排序；并列时按预先固定的候选顺序打破，不增加事后挑选自由度。

### 7.4 固定配方与逐折选参应分别命名

- 固定配方按窗口重新拟合：检验估计量随时间更新的稳定性。
- 每折在固定候选集中验证选择：检验“候选集合＋选择准则＋重新拟合”的完整政策。

两者可以使用相同时间划分工具，但不能合并成“某个参数的样本外效果”。如果每折参数不同，最终曲线属于适应性政策，需要同时展示各折参数与合成权重。

### 7.5 失败折不能被隐藏

名义窗口不合法或无法产生任何完整折，划分函数直接报错。成熟样本不足、合成拟合失败、没有合格候选等研究失败，记录 `status` 与原因。

首版示例遇到这样的折即停止并输出已有明细，不给不完整过程计算正式的汇总样本外 Sharpe。不得删除失败折、仅汇总成功折，也不得默认用零收益填补模型失败。有效的空仓决策与模型运行失败是两种不同事实。

## 8. 组合实验接入：收益时钟、暖机与跨折状态

### 8.1 时间窗口按收益实现时间评分

划分表的窗口 `[a,b]` 用于组合指标时，含义是：统计**实现时间位于 `[a,b]` 的单期研究收益**。设全局时间轴为 `u0,u1,...`：

\[
R_{u_{i+1}}=\sum_p w_{u_i,p}\,r_{u_{i+1},p}-C_{u_i}.
\]

因此，评分 `[a,b]` 需要的决策时间是 `[prev(a), prev(b)]`。在 `prev(a)` 当期数据到达后完成拟合／选择，生成第一笔被评分的权重；不能等到 a 收盘才开始产生该期收益。

例如训练截止 `d6`、验证 `d7...d10`：候选在 `d6` 收盘后拟合，`w[d6]` 对应第一笔验证收益 `R[d7]`；验证最后一笔 `R[d10]` 来自 `w[d9]`。在 `d10` 看到完整验证结果并重新拟合后，生成 `w[d10]`，对应 `R[d11]` 的首笔测试收益。选择没有读取测试收益。

预测统计量仍以**因子决策行时间**及第 5.3 节的完整标签掩码评分。预测表与收益表应各自记录有效日期和样本数，不暗示两类统计使用完全相同的观测行。

### 8.2 暖机不是训练标签授权

可以为因子、波动率、协方差和调仓规则保留评分起点之前的原始历史。只允许按当时信息计算状态，不能把历史上下文中的全部标签都送入拟合，也不能让未来收益回填暖机失败。

示例的冷启动规则：评分所需首个决策之前的信号掩码为 NaN，按现有缺失信号政策保持空仓；历史行情仍进入风险估计。首个有效决策从零建立研究权重，其建仓成本计入第一笔评分收益。必须先检查风险所需历史已经充分，不能把未暖机的空仓曲线当成有效候选。

不同候选使用相同上下文起点、评分区间、调仓锚点和成本规则。长窗口候选的暖机不足，不得通过缩短它的评价区间获得更有利比较。

### 8.3 Walk-forward 总收益必须连续重放

逐折 `portfolio_returns` 直接拼接，可能遗漏参数切换的换手成本，并在折边界重置持仓或风险状态。首版总路径采用：

```text
每折仅利用当时历史，生成测试期所需的决策信号
                         ↓
按决策时点拼接为一条无重叠、无缺口的有效信号路径
                         ↓
一次 DiagnosticPortfolioExperimentRunner.run()
                         ↓
按收益实现日期裁取全部 wf_test 区间，重新计算总绩效
```

这样，折边界上的新信号自然与上一期实际研究权重比较，成本和持仓衔接由现有组合实验负责。监督合成的状态由研究代码按时切换；事前风险估计沿固定规则持续更新。

第一阶段邻域只改变因子／预处理／合成配方，**整条测试路径固定组合 Spec 与调仓日历**。不支持逐折更换风险模型、成本率或组合约束，否则单次重放无法表达这些状态变化，需要另写方案。

监督状态更新与实际权重调整也要区分：新合成权重从指定决策时点生效，但研究仓位仍遵守原调仓表。示例采用逐日调仓；研究使用低频调仓时，必须保留共同锚点，记录状态生效日与下一实际调仓日，不能因为切折就强行调仓。

最后一个实现时点必须有其前一决策；单期收益只出现一次。对末端没有后继行情的决策不评分，与现有运行器最后一行只作为收益实现时点的约定一致。

### 8.4 总绩效不能平均各折 Sharpe

按唯一实现日期合并测试收益，在连续净值上重新计算总收益、波动率、Sharpe 和回撤。逐折 Sharpe、正收益折比例和参数选择频率保留为稳定性诊断，不作为总体 Sharpe 的组成公式。

主表使用整个预定测试日历，包括合法的零仓位收益；不使用“从首个非零暴露开始”或只保留活跃日期的口径筛选候选。裁切收益后可复用 `compute_performance` 的完整区间 `gross` / `proxy_net` 两行，明确忽略其另两行有效起点指标；不要再次平移已经按实现时间对齐的收益。

各折可以对连续重放结果切片汇总。候选验证时的独立冷启动结果与连续测试路径应标记不同的初始化语义，不能混作同一条净值。

## 9. 参数邻域：检查可用区域，而非寻找最好看的点

### 9.1 研究者显式声明小范围

首版不增加通用网格搜索器。研究脚本用一个候选表声明少量设置，例如某动量窗口的 `[15,20,25]`，或者围绕两个有经济含义的参数建立小型二维表。

候选表至少包含：`candidate_id`、参数字典、基准／中心点标记，以及稳定的候选顺序。所有影响结果的设置都需要进入配方，包括方向、标签期限、预处理、成分组合和缺失政策；不能只记录名为 lookback 的字段。

邻域应在看该轮评价结果前给定。第一次探索可以在训练历史中确定中心点，再冻结其邻域用于验证。看完验证结果后不断移动中心、加密网格或改阈值，会增加选择次数；必须追加记录，不能用最后一张局部平滑图掩盖此前搜索。

首版不自动根据训练最优点生成“最优半径”，也不允许依据最终保留期结果移动邻域。

### 9.2 可比性的两套口径

**预测统计**：在同一窗口中，用同一个动态品种池、同一完整标签和同一组候选共同有效行作主比较，并额外记录每个候选原生覆盖率和共同样本保留率。截面评价仍需满足共同截面的最小品种数。

共同有效样本可能只保留更容易研究的子集，因此共同样本结果与覆盖损失应同时展示；若邻域扩大导致大量样本消失，不能仅展示幸存子集中的平滑结果。

**组合收益**：使用同一实现日历、同一动态品种池和同一组合规则，保留每个候选自己的合法信号缺失与空仓行为。不能把收益序列取“所有候选都持仓的日期交集”，这会删除策略真实经历的空仓与失败风险。

窗口起点前充分暖机。因子尺度差异会与 clip 等映射相互作用；需要比较纯参数敏感性时，固定预处理尺度和组合风险规则，同时报告暴露、波动率和换手，避免把杠杆变化误判为预测改善。

### 9.3 第一张表应能回答什么

每个候选、每个窗口输出：预测指标、覆盖率、毛／代理净绩效、换手、主要集中度证据及状态。第一阶段直接用 pandas 透视表或研究脚本绘图，不建设通用 tear sheet。

邻域汇总只使用透明的描述性量：

- 有效候选数／声明候选数、无效候选及原因；
- 主指标的中位数、四分位范围、最小值、最大值；
- 正代理净收益候选比例，以及中心点相对邻域的位置；
- 分折结果和最差时期，是否依赖少数品种贡献。

无效候选不能按零分填充，也不能从覆盖分母消失；数值汇总注明有效候选分母。小邻域中的相近结果只能说明对已测扰动不敏感，不能证明在未测参数、其他时期或其他市场普遍稳健。

不设统一的“邻域通过率 > 80% 即通过”规则，不对高度相关的参数点做独立样本 t 检验，也不把一张平滑热力图转化为显著性证明。参数选择影响了研究结论时，相关检验必须进入下一节的检验族。

## 10. 多重检验：从计算校正值到声明检验对象

### 10.1 首先说清一个原始检验

首轮经济问题优先使用固定候选在未参与其拟合的评价区间上的：

\[
H_0:E[R^{proxy\_net}_t]=0,
\]

并要求经济方向为正。第一阶段使用双侧检验；不根据样本里出现的正负号临时改成单侧。它检验的是指定代理成本与收获规则下的均值，不直接检验 Sharpe，不证明因子有独立 alpha，也不代表真实策略可交易。

需要预测显著性时，可以另外声明已有的截面 IC 均值或回归系数检验。不同的预测与收获假设必须在清单中分清；如果结论允许“任何一个指标显著就算发现”，所有这些备选检验都属于需要共同控制的选择机会。

不能把 Sharpe、ICIR、各折正收益比例直接当成 p 值。时序模式下分品种 IC 的跨品种均值也不能直接调用时间序列 HAC 检验；如需时序预测推断，使用已定义的回归模型及其合适协方差，或者暂时只报告描述统计。

### 10.2 第一阶段增加一个小型 HAC 均值工具

在现有 `factors/evaluation/robustness.py` 增加 `mean_hac_test`，用 statsmodels 的常数项 OLS 和 Newey–West HAC 协方差计算均值、标准误、统计量与双侧 p 值；采用 Bartlett 权重、有限样本协方差修正和 `use_t=True`，并记录这些设置。

这是一个近似推断工具，不承诺在短样本、结构突变或所有依赖过程下精确控制误差。HAC 不会修复先看同一批收益再构造候选的选择偏差。

输入只接受一条按共同交易日轴完整排列的有限数值时间序列，`max_lags` 由研究者事先指定。内部缺失、被压缩的交易日轴、样本太短或滞后阶数不合法时，不自动 dropna、补零或收缩滞后。日历完整性由调用方核验；函数本身无法从日期猜测交易日是否缺失。

标准误为零／非有限时返回无效状态和 NaN 推断值，不把恒正序列处理成无限显著。常规净收益中的合法零仓位日保留；数据错误或模型失败造成的缺失不能变成零。

多期标签通常至少需要关注 h−1 阶重叠相关，但 h−1 不是适用于所有序列的充分带宽；日度组合收益也不能机械沿用标签期限。带宽由经济持有结构与序列依赖事先确定，并记录理由；看 p 值后换带宽同样增加研究自由度。HAC 的等间隔序列前提见 [statsmodels 官方文档](https://www.statsmodels.org/stable/generated/statsmodels.stats.sandwich_covariance.cov_hac.html)。

已有 IC／回归推断可以继续使用，但须核验实际有效序列和缺失处理。特别是把有内部空洞的逐期统计 dropna 后按相邻交易日做 HAC，会压缩间隔；首版遇到这种情况不宣称该 p 值已经获得正确时间推断，改为描述结果或另行制定缺失推断方案，不扩张本轮范围。

### 10.3 检验族由研究问题定义

一个 `family_id` 表示为同一研究发现提供备选依据的一组声明检验，不等于一次脚本调用、一个目录或一张报表。

例如，在同一验证期考察 9 个事先固定的动量候选，并且每个只用成本后均值作为主检验，则该检验族有 9 项。不能先选出最好的一项，再只对它做一次校正。

若同时考察不同因子、窗口、方向、标签期限、预处理或合成方法，并从中挑选发现，清单应覆盖这些实际选择机会。品种级／板块级显著性如果也被用来挑选结论，同样需要进入相应的预先定义检验族。

不要求把所有不同科学问题机械并成一个无限大族，但不能在看到结果后把原先的一次搜索拆成许多个小族。跨次实验的相关搜索记录由研究者维护；首版不建设全局试验注册中心。

参数点的多重检验，控制的是声明候选中错误拒绝的风险；它不会给“验证期选出的赢家”提供无偏收益估计。赢家的效应大小仍需看未参与选择的后续样本。

### 10.4 三种方法，明确选择理由

| 方法 | 控制目标与条件 | 首版用途 |
|---|---|---|
| `holm` | 控制至少一次错误拒绝的概率 FWER；在各原始 p 值有效时可处理任意依赖 | 首版默认，适合少量候选的保守确认 |
| `fdr_by` | 控制错误发现比例的期望 FDR；在有效原始 p 值下允许一般依赖 | 较大且相关结构不明确的声明检验族，代价是较保守 |
| `fdr_bh` | 在独立或适当的正依赖条件下控制 FDR | 明确说明依赖假设的探索筛选；不因参数收益相关就自动认为条件满足 |

FDR 是 `E[V / max(R,1)]`，不是某个已入选因子“有 5% 概率为假”；FWER 与 FDR 也不能混用。BH 的 PRDS 等条件与 BY 的一般依赖处理参见 [Benjamini 与 Yekutieli（2001）](https://doi.org/10.1214/aos/1013699998)，可执行方法见 [statsmodels 的 FDR 文档](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.fdrcorrection.html)。

一次主要结论事先选定一个方法与 alpha，不能运行三个方法后只展示最容易拒绝的那个。其他方法若作为敏感性展示，需要并列说明。

### 10.5 对现有 `adjust_pvalues` 的最小修改

保留“一个 p 值 Series → 一个结果 DataFrame”的接口形态，只接受 `holm`、`fdr_by`、`fdr_bh` 三个明确名称。默认改为 `holm`；当前仓库未发现其他调用点，实现时仍应重新检索并说明这一行为变化。

契约如下：

- 索引为唯一、非空的 `hypothesis_id`；保留输入顺序，不原地排序。
- 值必须是非布尔实数；有限值在 `[0,1]` 内，允许 NaN 表示声明但未取得有效检验的项；无穷或越界直接报错。
- `alpha` 必须为有限实数且在 `(0,1)`；非法方法即使没有有效 p 值也必须报错。
- **`n_tests = 声明的全部行数`**，`n_valid` 才是有限 p 值数；不能再按 dropna 后数量缩小检验族。
- 声明但无效的项在内部使用 p=1 参与保守校正，输出保留原始 NaN，`adjusted_pvalue` 为 NaN，`rejected` 为 nullable boolean 的缺失，`status='not_testable'`。
- 有效项返回校正值和是否拒绝；同时记录 `method`、`alpha`、`n_tests`、`n_valid`。
- 空 Series 直接报错；全 NaN 的非空族保留全部无效行，不能产生任何发现。

内部 p=1 是对**已经声明、没有获得有效证据**的项保留计数的保守办法，不是在断言其真实 p 值为 1。调用方仍需保留具体失败原因；不能把已知但难看的 p 值改成 NaN，也不能拿补 1 修复未知的历史搜索次数。

该函数一次只处理一个明确的检验族，不自动按任意列 groupby。`family_id`、假设说明、候选与样本范围通过调用方按 hypothesis_id 一对一连接；这既保持函数简单，也避免隐式分组改变科学问题。

### 10.6 最小研究清单与完整性说明

研究脚本在评价前声明候选和假设，评价后补齐状态。不同折的 p 值不取平均，不在没有依赖假设的情况下用 Fisher 等方法直接合并；整体政策的检验使用其唯一日期上的完整测试序列，并说明均值推断假设。建议用两个普通表，不建立数据库：

- `candidates`：candidate_id、完整配方、声明批次、稳定顺序、基准标记、运行状态和失败原因。
- `hypotheses`：hypothesis_id、family_id、candidate_id／policy_id、样本角色与范围、原假设、统计口径、原始 p 值、有效样本量、推断设置、失效原因及校正输出。

候选运行清单与正式检验族不必一一对应：同一条 walk-forward 政策的各折是构成其完整测试路径的时间片，不默认各自算一个新因子发现；多个候选、多个政策各有自己的整体假设。若逐折显著性也被用于挑选或宣称发现，则另行声明完整的相关检验族，不能只摘取显著折。

如果候选是看完同一评价样本后反复发明的，或此前实际搜索无法枚举，结果标记 `exploratory / family_incomplete`。即使对当前可见列表算出校正值，也不宣称获得覆盖全部选择过程的 FWER／FDR 保证。后续通过冻结政策和新的未见样本获取更强证据。

多重检验不能消除泄漏、无效原始 p 值、遗失的失败试验或反复查看保留期的影响。有关金融研究中大量候选改变显著性解释的背景，可参考 [Harvey、Liu 与 Zhu 的原始研究](https://www.nber.org/system/files/working_papers/w20592/w20592.pdf)；本文不把其中特定数据背景的 t 值门槛移植成 CTA 的统一标准。

## 11. 第一阶段最小接口与文件边界

### 11.1 时间工具：一个普通模块

新增 `factors/robustness.py`，初步只放三个纯函数：

```python
make_holdout_split(
    timeline: pd.DatetimeIndex,
    *, train_end: pd.Timestamp, validation_end: pd.Timestamp,
) -> pd.DataFrame

make_walk_forward_splits(
    timeline: pd.DatetimeIndex,
    *, train_size: int, validation_size: int, test_size: int,
    expanding: bool = False,
) -> pd.DataFrame

label_window_mask(
    sample_index: pd.MultiIndex,
    *, start: pd.Timestamp, end: pd.Timestamp, as_of: pd.Timestamp,
    label_end: pd.Series, label_available_at: pd.Series,
) -> pd.Series
```

以上是拟实现的接口草案，不代表现有可调用代码。输入时间边界必须是时间轴上的真实时点；不做自动 bfill、归一化或自然日换算。三个名义区间必须非空且严格按时间先后排列。长度参数只接受正整数，排除布尔值。

划分表以 `fold_id` 为索引，包含 `train_start/end`、`validation_start/end`、`test_start/end`，以及三个名义长度。固定划分返回一行；walk-forward 按时间返回多行。末尾未覆盖的范围由调用方将最后 test_end 与输入终点比较后记录。所有边界均为闭区间。

`make_holdout_split` 把传入时间轴从起点到 train_end 作为训练，之后到 validation_end 作为验证，余下作为 test；时间轴范围决定研究起止。因此最终保留期和开发期 walk-forward 使用不同的显式时间轴切片，不能无意把 final_holdout 交给开发循环。

`label_window_mask` 要求两条时间 Series 与 `sample_index` 完全一致；sample_index 必须为唯一、升序的 `MultiIndex(timestamp, product)`，两条序列不能含额外或缺失索引。NaT 端点对应 False，不自动按位置错配；有效端点满足 `t < label_end <= label_available_at`。输出与输入等长的 bool Series，不自行 drop 行、读取标签值或应用品种池。

这里只支持前瞻标签；同期目标等其他语义不通过放松端点约束偷偷兼容。窗口清理后全 False 可以返回，由研究脚本按拟合／评价样本门槛决定失败。

### 11.2 统计工具：扩充现有小模块

在 `factors/evaluation/robustness.py` 中：

```python
mean_hac_test(values: pd.Series, *, max_lags: int) -> pd.Series

adjust_pvalues(
    pvalues: pd.Series,
    alpha: float = 0.05,
    method: str = 'holm',
) -> pd.DataFrame
```

均值检验输出至少包含 `n_obs`、`mean`、`standard_error`、`t_stat`、`p_value`、`max_lags`、推断口径和 `status`。非法输入直接报错；合法数据但零方差等不能推断的情况返回无效状态。研究脚本可以先按预定的研究样本门槛把过短窗口记为 not_testable，不需要在工具中预设一个适用所有问题的最低年数。

不导入 `DiagnosticPortfolioResult`、`LabelResult` 或合成器。两类模块通过 Series 和普通表格协作，保持 loose coupling；不新增 `factors.__init__` 导出，也不依赖订单、账户或回测引擎。

### 11.3 示范研究与产物

新增一份 `research/experiments/robustness_mvp.py` 及同目录简短说明。脚本使用当前已有的一类基础因子、小型邻域、一个固定组合 Spec，显式演示：

1. 数据与完整标签时间准备；
2. 固定三段划分及最终保留期隔离；
3. 在开发历史内 walk-forward；
4. 邻域验证比较、重新拟合与信号路径；
5. 连续组合重放、有效原始检验与校正；
6. 冻结最终配方后单独执行 final_holdout。

脚本把开发执行和最终确认分成显式入口，默认只运行开发部分。研究者通过明确调用最终入口打开保留期；这是防止误运行的代码边界，不增加交互审批系统。

示例保留一条固定参数基线，便于判断逐折选择是否改善结果；若正式检验适应性政策相对基线的改善，应对共同日期上的配对收益差声明均值假设，不能用“一个显著、另一个不显著”代替差异检验。

产物写入现有 `research/artifacts/<study_id>/` 约定，至少包含：

- 研究说明／配置快照：候选、主指标、选择／重新拟合政策、最终保留期及查看历史、数据来源和截止时间、代码版本及未提交变更说明。
- `splits`：窗口边界、拟合截止、名义与有效样本数、未覆盖尾部。
- `candidates`、`hypotheses`：包括失败项和完整性状态。
- `fold_metrics`、`parameter_metrics`：预测与组合指标，明确初始化与样本口径。
- `selected_candidates`：逐折选择、拟合权重与状态生效时间；未来需要时再增加通用快照。
- `oos_returns`：唯一实现日期、折／政策归属、毛收益、成本和代理净收益；配套组合 run_id 与统计评价引用。
- 简短研究结论，说明哪些证据支持、哪些证据削弱假设。

格式使用现有 JSON／Parquet 导出能力，研究脚本只补少量本地写出代码；不扩充持久化领域模型。端点 Series 如未单独保存，必须能从已保存的标签定义、权威源索引与数据截止重建；最终组合路径优先通过已有 Store 保存权威输入与结果。

## 12. 实施顺序：每一步都能立即用于研究

### 第一步：固定切分与完整标签边界

实现时间校验、固定三段表与标签时间掩码；用小面板证明没有跨边界标签。接一个固定因子和已有组合组件，完成一次 train / validation / final_holdout 的显式实验。

这一阶段不等 walk-forward 与多重检验全部写完才开展研究，也不为了运行已有标签而放松成熟定义。

### 第二步：Walk-forward 与连续组合路径

实现 rolling / expanding 窗口；研究脚本逐折新建合成与拟合型预处理实例，保存选择与重新拟合记录；拼接有效信号并单次重放组合。优先验证每笔收益的决策时间与边界成本。

### 第三步：小型参数邻域

通过显式候选表加入少量参数点；完成共同预测样本、共同收益日历和完整失效表。先证明一个真实研究可以识别尖峰与平坦区域，不实现抽象搜索空间。

### 第四步：检验族与多重校正

加入均值 HAC 工具，收紧 `adjust_pvalues`，连接预先声明的检验清单。在固定候选的验证样本上完成校正演示；明确探索筛选与最终确认的区别。

四步合起来构成本轮完整 MVP，不是只实现时间切分后便宣称“稳健性开发完成”。每步产生可检查结果，但不提前建设后续阶段框架。

```text

factors/evaluation/robustness.py                   # 现有校正函数及小型均值检验
research/experiments/robustness_mvp.py             # 显式研究示例
```

不修改现有合成器、预处理生命周期、组合状态机或数据引擎。已有模型只允许第 2 节所述的 `DiagnosticSignal.source_stage` 局部枚举扩展；如纳入复合信号端到端示例，补充 `tests/factors/diagnostic_portfolio/test_models.py` 和已有 storage 往返测试，确认不改变原信号的读取。若示范接入暴露其他真实错误，先给出独立问题与最小修复，不把相关重构混入稳健性工具。

## 13. 验证计划与完成标准

### 13.1 时间与标签测试

使用确定性人工交易日历和两个以上品种，覆盖：

- 全日品种整体切分，ragged panel 不改变同日时间角色。
- 固定边界、rolling / expanding 公式、完整折与未覆盖尾部。
- 错误／重复／乱序时间轴、非交易边界、非法长度和空区段。
- 第 5.5 节的 h=3 手算样例；验证重新拟合会重新纳入已成熟的原边界标签。
- label_end 为 NaT、数值非空但期限不完整、可得时间延迟、缺失未来组成观测。
- 逐品种源时间不同与共同时间轴的差异，防止用面板行数或自然日推算期限。
- 修改训练截止之后的标签，不改变当时的拟合输入掩码；修改未来数据，不改变此前的样本外信号和研究权重。

### 13.2 拟合与组合接入测试

测试使用小型人工面板和真实轻量组件，不依赖外部 db：

- IC 加权每折只接收已成熟训练行，验证／测试标签不进入其 fit。
- 新建实例及重新拟合不会污染历史折记录；方向不在测试期翻转。
- 用 `w[d6] × r[d7] − C[d6]` 手算第一笔验证收益，测试首笔收益同样核验。
- 至少两个折在边界发生信号反向，手算折间换手与代理成本，证明单次连续重放保留转换成本。
- 共同调仓锚点不会因裁切历史或切折重置；低频调仓的新状态等待下一调仓日。
- 每个测试实现日只出现一次；末端无对应收益的决策不计入绩效。
- 总体 Sharpe 从完整收益重算，不能通过平均折 Sharpe 得到；合法零仓位日不会被过滤。
- 暖机上下文不计入主评分；失败折保留且终止正式总体结论。

### 13.3 邻域与统计测试

- 候选顺序与并列选择确定；无效候选保留，覆盖分母正确。
- 预测比较使用共同有效行，组合比较使用完整共同收益日历。
- HAC 均值在 `max_lags=0` 时与常数回归的可手算结果一致；正滞后用短序列独立复算 Bartlett 加权协方差。
- 负均值不因双侧 p 值显著而被解释为正经济发现；零方差和样本不足不产生无限显著结果。
- HAC 不自动删除内部 NaN 或压缩日历；非法滞后与非法输入行为确定。
- Holm、BH、BY 校正使用手算向量，验证排序恢复、重复值、边界 0/1、缺失占位和全缺失。
- 例如原始 p 为 `[0.01,0.04,0.20]`，Holm 校正为 `[0.03,0.08,0.20]`；添加一项声明但缺失的检验后，使用 `[0.01,0.04,0.20,1]`，前三项变为 `[0.04,0.12,0.40]`，缺失项输出仍不可判定。
- 未知历史搜索不能被标记为完整检验族；探索结果与最终保留结果不会合并冒称盲测。

不对可视化版式或每一个透视表写镜像测试。重点测试会改变研究结论的时间、选择、成本与推断语义。

## 14. 后续演化及启动条件

第二阶段不随 MVP 完成自动启动。只有反复研究暴露以下具体需求时再扩展：

| 真实痛点 | 可考虑的局部演化 |
|---|---|
| 多份脚本重复实现完全相同的逐折拟合／选择 | 提取薄编排函数，再判断是否需要协议 |
| 标签成熟信息被多个研究重复推导且容易出错 | 为 LabelResult 或独立标签适配结果增加实际端点与可得信息 |
| 需要比较有内部缺失的 IC 时间序列显著性 | 单独设计保留实际时间间隔的推断方法 |
| 同一收益矩阵需要反复检验候选相对基准的整体优越性 | 在联合时间块重采样下评估 Reality Check / SPA 等方法 |
| 大量搜索后需要修正最佳 Sharpe 的选择偏差 | 研究 DSR 的试验次数、相关性与非正态假设；不直接套一个“有效次数” |
| 要估计整个选择流程的过拟合风险 | 评估嵌套时序验证或适合该问题的 PBO／组合交叉验证，重新设计信息边界 |
| 收益集中度／市场状态成为反复争议 | 分时期、分品种／板块、leave-one-out、事前状态分层 |
| 代理成本与真实实现折损主导结论 | 成本／流动性压力和完整回测交付 |
| 研究清单跨脚本丢失、保留期被反复查看 | 轻量试验注册与保留期使用记录，再讨论持久化集成 |

DSR、PBO、Reality Check、SPA 与 BH／BY／Holm 回答不同问题，不在首版中组成一个“完整多重检验工具箱”。普通 p 值校正不能替代选择偏差评估；更复杂的方法也不能替代正确的时间边界和完整研究记录。

本轮要获得的能力是：研究者能够明确说明一项因子结论使用了哪些历史、如何选择、何时拟合、在何种扰动下仍然成立，以及其显著性声明覆盖了哪些检验。后续工具从这些真实研究中的重复与失败继续生长。
