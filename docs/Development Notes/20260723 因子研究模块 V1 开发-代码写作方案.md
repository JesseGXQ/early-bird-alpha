# 因子研究模块 V1 开发-代码写作方案

## 1. 开发目标

V1 目标是一次性实现一条完整、可复现的日频因子研究闭环：

```text
DataFacade
    -> ResearchDatasetBuilder
    -> DynamicUniverse
    -> Factor
    -> PreprocessingPipeline
    -> LabelBuilder
    -> CompositeFactor
    -> FactorEvaluator
    -> ResearchExperimentRunner
    -> ResearchResult
    -> CoreTables / TearSheet
    -> CandidateFactor
```

V1 不是只实现若干因子公式，而是建设完整的日频因子研究框架。完成后，研究者应能在动态多品种面板上完成因子构造、批量与增量计算、完整预处理、多种标签、因子合成、稳健诊断、实验追踪、报告和候选交付。

V1 必须回答：

- 因子值在历史时点是否真实可得？
- 动态品种池是否只使用准入时点已经可见的信息？
- 因子对未来多个期限的收益是否具有预测关系？
- 预测关系能否经受预处理、稳健统计、样本外、参数敏感性和多重检验？
- 多个因子能否按显式算子合成为复合因子，并通过增量接口交给策略？

## 2. 范围与假设

### 2.1 V1 支持

- 日频 Bar。
- 静态列表和动态历史品种池。
- 基于品种上市时长、日成交量/滚动成交量、持仓量、数据覆盖率和可交易状态的基础过滤。
- 品种池参数和判定时点进入实验配置。
- `ResearchFeed` 的 `scheduled` 和 `realized` 视图。
- 长表 `MultiIndex[timestamp, product]` 研究面板。
- 因子的批量及增量接口，以及相互独立的时序/横截面评价模式。
- 原始动量和展期收益率两个基础因子。
- 缺失/异常处理、缩尾、z-score、robust z-score、秩/分位数归一化、中性化、正交化、平滑降噪和可拟合变换器。
- 单层因子合成：等权、投票/排名、IC/ICIR 加权、Grinold 最优 IC、回归合成；可拟合算子仅训练窗口拟合；显式成分缺失政策。
- 行业/品种组、波动率、成交量/流动性、持仓量和展期收益率中性化。
- 多期限真实收益、方向、未来波动率、残差收益和配置化事件标签。
- 覆盖率、IC、Rank IC、分组收益、衰减、换手、归因、稳健推断、多重检验、市场状态、容量和冗余分析。
- 实验 ID、样本划分、参数网格、数据与代码指纹、持久化、缓存、批量和并行执行。
- 可选核心表格和完整 HTML tear sheet。
- 通用策略适配、逐 Bar 增量更新和复合因子输入。

### 2.2 V1 不支持

- 日内和 Tick 因子研究。
- 因子族层级和因子注册查询系统；复合因子嵌套（V1 仅支持单层合成）。
- 自动因子挖掘和自动批准候选因子。
- 在线 Feature Store、分布式集群、实时因子服务和多用户权限。

`V2` 只保留版本名称，不预先分配功能。日内因子研究也不默认归入 V2；未来如有需求，应单独设计其数据、标签、评价、成本和策略交付。

## 3. 开发前置检查

### 3.1 True_Return 端点语义

在编写标签器前，先为 `ResearchFeed` 增加一个最小人工换月契约测试，确认：

```text
True_Return[t] = close_of_same_contract[t] / close_of_same_contract[t-1] - 1
```

当前日频和日内数据引擎分支均已将换月收益写入换月时点。因子模块仍需保留人工换月契约测试，防止后续数据重构造成端点回归。

### 3.2 数据前置条件

- `ResearchFeed` 日频输出必须稳定提供 `Volume` 和 `OpenInterest`，用于动态品种池和中性化。
- 品种首次上市或首个有效研究日期必须可查询，用于上市时长过滤。
    * 已完成，数据引擎新建`RuleQueryService`类，顶层API：`facade.rule_service.get_list_date_product(product)`。
- 展期收益率必须取得同一品种多个合约的价格、到期日、成交量和持仓量。当前主力连续序列不足以完整计算，开发前需确定 `DataFacade` 的期限结构接口或注入独立数据提供者。
    * 已完成，数据引擎新建`TermStructureFeed`类，顶层API：`facade.get_term_strcuture_data(product, start_date, end_date)`。
- 行业/品种组中性化需要可追溯的 `asset_class / sector / subsector / supply_chain` 元数据。
    * 已完成，数据引擎新增期货品种类别+产业链组别数据。顶层API：`facade.rule_service.classification.get_classification/get_products_by/get_dummy_matrix`。

基差动量和仓单变化率是后续因子，不属于本轮完成标准；开发这些因子时再分别接入现货基差和仓单数据。

### 3.3 依赖约束

V1 开发前建立正式依赖清单并锁定版本。预计使用：

- Python 标准库。
- pandas。
- NumPy。
- SciPy。
- statsmodels。
- PyArrow。
- Matplotlib。
- Seaborn。
- pytest。

tear sheet 的设计借鉴 [Alphalens-Reloaded](https://alphalens.ml4trading.io/) 的收益、IC、换手和分组分析，但采用本系统自己的期货数据契约，不强制把 Alphalens-Reloaded 作为运行时依赖。

## 5. 核心公共接口

### 5.1 ResearchDataset

在 `factors/models.py` 定义轻量数据对象：

```python
@dataclass(frozen=True)
class ResearchDataset:
    df: pd.DataFrame
    spec: DatasetSpec
    quality: DataQualitySummary
    universe: pd.DataFrame
```

同时定义：

- `DatasetSpec`
- `UniverseSpec`
- `DataQualitySummary`
- `FactorState`
- `FactorResult`
- `LabelResult`
- `FactorEvaluationResult`
- `ExperimentIdentity`
- `CandidateFactor`

DataFrame 本身仍然可变，因此所有组件均以“不原地修改输入”为契约。必要时在边界复制，而不是在每一个小函数中无条件深拷贝。

> **适应性执行：**
> - `ResearchDataset` 字段布局与原设不同：`df` → `main_panel`（主面板），新增 `auxiliary: Mapping[str, pd.DataFrame] | None` 承载期限结构等附属数据集。
> - `universe` 类型从 `pd.DataFrame` 改为 `pd.Series`（布尔准入掩码）。
> - 期限结构列不再通过 `OPTIONAL_COLUMNS` 常量内嵌于主面板定义，而是由 `DataRequirement` 声明为独立数据源加载。

### 5.2 DynamicUniverse

在 `factors/universe.py` 定义：

```python
DynamicUniverse(spec).build(dataset) -> pd.DataFrame
```

输出与研究面板同索引的布尔准入表，并记录每个被排除样本的原因。`UniverseSpec` 至少包含：

- `min_listing_days`
- `liquidity_lookback`
- `min_daily_volume` 或 `min_average_volume`
- 可选 `min_open_interest`
- `min_data_coverage`
- `as_of`：`current_close` 或 `previous_close`

品种上市时长按品种计算，不因主力合约换月重置。

> **适应性执行：**
> - `UniverseSpec` 删除了 `as_of` 字段——因子研究的品种池只可能在收盘后判定，不存在 `previous_close` 语义，该字段属冗余设计。
> - `DynamicUniverse.build`返回 `tuple[pd.Series, pd.Series]`，第一个 Series 是 universe，第二个为 exclude_reason。

### 5.3 Factor

在 `factors/base.py` 定义抽象基类：

```python
class Factor(ABC):
    name: str
    factor_type: Literal["time_series", "cross_sectional"]
    required_columns: tuple[str, ...]
    min_history: int

    @abstractmethod
    def compute(self, df: pd.DataFrame) -> pd.Series:
        ...

    @abstractmethod
    def initialize_state(self) -> FactorState:
        ...

    @abstractmethod
    def update(
        self,
        state: FactorState,
        timestamp_df: pd.DataFrame,
    ) -> IncrementalFactorResult:
        ...

    def parameters(self) -> Mapping[str, Any]:
        ...
```

公共校验器负责检查：

- 必需列存在。
- 输入只包含因子声明的必需列和规范索引。
- 输出是 Series。
- 输出索引与研究面板完全一致。
- 输出名称与因子名称一致。
- 输出值可转换为数值。
- 因子未声明依赖任何标签列。
- 增量输入只包含一个时间戳下已经可见的完整品种截面。
- `FactorState` 可重置和序列化，且不含标签、策略权重或账户状态。

具体因子不重复这些通用校验。

> **适应性执行：**
> - `factor_type` 被 `computation_scope: Literal['per_product', 'cross_sectional']` 替代——声明计算方式而非评价模式。评价采用时序还是截面取决于研究者的应用逻辑（`EvaluationConfig.mode`）。
> - `Factor.compute()` 输入不再限定为 `pd.DataFrame`——`ResearchDataset.auxiliary` 引入后，附属数据集（如期限结构）的索引结构与主面板不同，因子应根据 `data_requirements` 声明的数据源适配输入格式。

### 5.4 Preprocessor

```python
class FactorPreprocessor(ABC):
    @abstractmethod
    def transform(
        self,
        values: pd.Series,
        dataset: ResearchDataset,
    ) -> pd.Series:
        ...
```

`PreprocessingPipeline` 按配置顺序组合单因子预处理器；`FactorMatrixPreprocessor` 处理跨因子正交化和联合变换。所有可拟合变换器提供 `fit(train_data)` 与 `transform(data)`，拟合参数不得使用验证集和样本外信息。

### 5.5 LabelBuilder

```python
LabelBuilder(
    specs=(
        ForwardReturnLabel(...),
        DirectionLabel(...),
        FutureVolatilityLabel(...),
        ResidualReturnLabel(...),
        EventLabel(...),
    ),
).compute(dataset) -> LabelResult
```

每个标签定义必须提供稳定名称、预测期限、输入字段、端点、缺失传播和基准调整政策。输出 DataFrame 与研究面板同索引。

### 5.6 FactorCombination

```python
class CombinationOperator(ABC):
    """无态算子：等权、投票/排名。"""

    @abstractmethod
    def transform(self, factor_matrix: pd.DataFrame) -> pd.Series:
        ...

class FittableCombinationOperator(CombinationOperator):
    """可拟合算子：IC/ICIR 加权、Grinold 最优 IC、回归合成。"""

    @abstractmethod
    def fit(self, factor_matrix: pd.DataFrame, labels: pd.DataFrame) -> None:
        ...  # 只允许训练窗口数据与训练窗口标签

class CompositeFactor:
    """单层复合因子：成分因子 + 合成算子 + 成分缺失政策。"""

    name: str
    constituents: tuple[Factor, ...]
    combiner: CombinationOperator
    missing_policy: Literal["strict", "renormalize", "abstain"]
```

规则：

- 合成输入是各成分因子完成单因子预处理后的因子矩阵（列 = 成分因子），索引与研究面板一致。
- 成分只允许基础因子，V1 禁止嵌套。
- 可拟合算子的 `fit` 只使用训练窗口；`transform` 不得访问标签。交易时权重冻结，重新拟合属于研究事件。
- 使用 Grinold 算子时不做跨因子正交化矩阵预处理（同一问题，叠用等于双重计数）。
- 增量更新 = 逐成分 `update` 后用冻结权重合成；批量/增量等价性测试延伸到复合层。
- 完整配方可序列化：成分及参数、各成分预处理链、算子及参数、拟合来源（训练窗口、标签规格、产出权重）。

### 5.7 FactorEvaluator

```python
FactorEvaluator(config).evaluate(
    factor_result,
    label_result,
    dataset,
) -> FactorEvaluationResult
```

`FactorEvaluator` 只做编排，具体指标由独立函数或小型类实现。

### 5.8 ResearchExperimentRunner

```python
result = ResearchExperimentRunner(
    dataset_builder=builder,
).run(config)
```

`ExperimentConfig` 显式包含：

- `DatasetSpec`
- `UniverseSpec`
- 一个或多个 Factor 及参数
- 单因子和跨因子预处理配置
- 可选的因子合成配置（CompositeFactor、合成算子及参数、成分缺失政策）
- 标签定义
- `EvaluationConfig`
- 样本内、验证集、样本外或 walk-forward 划分
- 参数网格和随机种子
- 缓存、并行、持久化和报告配置

Runner 支持单因子实验、多因子联合诊断和因子合成实验。多因子合成由 `CompositeFactor` 在因子模块内完成并参与评价；策略层只负责阈值、方向和仓位映射。

## 6. 编码顺序

### Step 0：依赖与数据契约

- 建立并锁定 V1 的正式 Python 依赖清单。
- 为 `ResearchFeed` 日频输出补充 `Volume`、`OpenInterest` 的字段契约和测试。
- 确定品种首次上市或首次有效数据日期的查询方式。
- 确定期限结构数据接口，至少提供同品种可比合约、价格、到期日、成交量和持仓量。
- 准备期货品种分层与多标签分类元数据。

在展期收益率所需数据契约确定前，不编写依赖猜测字段的因子实现。

### Step 1：Schema 与核心模型

实现：

- `DatasetSpec`
- `UniverseSpec`
- `DataQualitySummary`
- `ResearchDataset`
- `FactorState`
- `IncrementalFactorResult`
- `FactorResult`
- `LabelResult`
- `FactorEvaluationResult`
- `ExperimentIdentity`
- `CandidateFactor`
- 领域异常类型

`factors/dataset.py` 同时定义 V1 必需字段、索引名称和数据集构建逻辑，并提供：

```python
validate_research_frame(df) -> DataQualitySummary
```

校验内容：

- `MultiIndex` 名称必须为 `timestamp, product`。
- `DatasetSpec.freq` 在 V1 必须为 `1d`，其他频率直接报错并说明日内研究不在当前架构内。
- 索引唯一并按时间、品种稳定排序。
- product 为大写。
- 必需字段存在。
- timestamp 可转换为 `DatetimeIndex` 层。
- 同一品种内 `trading_date` 不倒退。
- `Volume` 和 `OpenInterest` 为非负数或明确缺失。
- 输出缺失率、起止时间、行数和各品种样本数。

> **适应性执行：**
> - 删除"领域异常类型"——控制个人项目复杂度，所有异常直接使用 Python 内置 `ValueError`。
> - 新增 `DataRequirement(source, columns)` 核心领域类，配套 `DatasetSpec.data_requirements` 字段；因子声明依赖字段的方式从 `required_columns: tuple[str, ...]` 升级为 `data_requirements: tuple[DataRequirement, ...]`。
> - `validate_research_frame` 删除了 `product` 全大写检查和 `timestamp` 可转换为 `DatetimeIndex` 检查——前者在产品代码规范化阶段已保证，后者在数据引擎默认输出 `DatetimeIndex` 的情况下冗余。
> - `DataQualitySummary.product_sample_counts` 类型为 `Mapping[str, int] | None`，索引非法时为 `None`（而非空字典），避免将"无数据"静默表示为 `{}`。

测试先于其他业务代码完成。

### Step 2：ResearchDatasetBuilder 与 DynamicUniverse

继续在 `factors/dataset.py` 实现：

```python
ResearchDatasetBuilder(facade).build(spec) -> ResearchDataset
```

流程：

1. 规范化并检查产品代码。
2. 逐品种调用 `DataFacade.get_historical_vector(...)`。
3. 验证单品种结果非空、索引唯一、字段齐全。
4. 添加 product 索引层。
5. 合并并排序成长表面板。
6. 运行统一 schema 校验。
7. 返回数据和质量摘要。

Builder 先保留完整原始研究面板，再调用 `DynamicUniverse` 生成逐时点准入掩码和排除原因，不直接物理删除原始行。动态品种池依次处理：

1. 品种首次上市或首次有效数据日期。
2. 最短上市时长。
3. 滚动数据覆盖率。
4. 日成交量或滚动平均成交量。
5. 可选持仓量和可交易状态。
6. 研究者显式包含或排除规则。

V1 不在 Builder 中：

- 重建复权、主力合约和收益逻辑。
- 前向填充缺失价格。
- 隐式删除品种却不记录原因。
- 读取订单、账户或交易成本数据。

为单元测试允许注入 Fake DataFacade。

> **适应性执行：**
> - Builder 使用 `get_historical_vector_multiple_products`（多线程并行）替代原设的逐品种串行 `get_historical_vector`；新增 `max_workers: int | None` 参数控制线程数。
> - 删除 `_check_single_product_result`——并行接口 `concat` 后通过面板级别的 `validate_research_frame` 与 Post-hoc 品种缺失覆盖率校验替代逐品种前置校验。
> - Builder 新增附属数据集加载能力：根据 `DatasetSpec.data_requirements` 中的 `DataRequirement`（`source` 不为 `'main_panel'` 的条目），在加载主面板后按需加载 `term_structure` 等数据集，存入 `ResearchDataset.auxiliary`。
> - 期限结构数据集索引重建：从原生的 `MultiIndex[trading_date, contract]` 重建为 `MultiIndex[timestamp, product, contract]`。

### Step 3：批量/增量 Factor 接口与基础因子

在 `factors/library/momentum.py` 实现：

```python
MomentumFactor(lookback=20)
```

计算：

```text
momentum[t] = Adj_Close[t] / Adj_Close[t-lookback] - 1
```

必须按 product 分组滚动，输出保持完整面板索引，前 `lookback` 个观测为 NaN。

`MomentumFactor` 只输出原始过去收益，不内置时序或横截面语义。同一结果可由 `EvaluationConfig.mode` 分别执行 `time_series` 或 `cross_sectional` 评价。截面排名、标准化等变换属于 `PreprocessingPipeline`，不得写入因子计算逻辑。

这里说的排名/标准化，不包括使因子获得可解释经济含义所做的标准化。例如动量、展期因子包含的结构化归一。此处的标准化，是指狭义的从研究范畴上应该属于预处理环节的操作。

在 `factors/library/carry.py` 实现 `RollYieldFactor`。公式必须明确近远月选择、到期天数、年化方式、合约流动性和缺失政策；禁止用主力连续价格的换月跳空近似每日展期收益。

两个基础因子都实现批量 `compute()` 和逐时间戳 `update()`。增量状态只保留最小滚动历史和累计量。

测试覆盖：

- 两个品种价格尺度不同。
- 交易日不完全重合。
- 窗口不足。
- 动态品种池变化。
- 批量与增量输出逐时点等价。
- 展期合约选择和年化公式可手工复算。
- 输入乱序时由数据边界处理，而不是因子静默产生错位。
- 输入 DataFrame 未被修改。

> **适应性执行：**
> - 时序动量和横截面动量不再是两个独立因子类——V1 实现为单一 `MomentumFactor`，`computation_scope='per_product'`。横截面排序/分层转移到评价层。
> - 动量因子计算使用 `True_Return` 而非 `Adj_Close`，原因：加减法复权可能导致早期复权价格为负数，无法计算收益率。
> - `RollYieldFactor` 不再依赖 Runner 预处理合约列，而是直接接收 `ResearchDataset.auxiliary['term_structure']` 作为输入（ `MultiIndex[timestamp, product, contract]`），合约选择逻辑属于因子内部。
> - `Factor.compute()` 输入类型放宽：主面板用 `pd.DataFrame`，展期结构等附属数据集——​​用—​​用 `pd.DataFrame`（​​但可能是不同维度的 MultiIndex）。

### Step 4：完整预处理系统

单因子预处理实现：

- `DropNonFinite`
- `CrossSectionalWinsorizer`
- `RollingTimeSeriesWinsorizer`
- `CrossSectionalZScore`
- `RobustZScore`
- `RankNormalizer`
- `QuantileNormalizer`
- `ExposureNeutralizer`
- `RollingSmoother`
- `EwmSmoother`
- `PreprocessingPipeline`

`ExposureNeutralizer` 支持：

- 行业/品种组虚拟变量。
- 波动率。
- 成交量或其他流动性代理。
- 持仓量。
- 展期收益率。

跨因子矩阵预处理实现：

- 顺序明确的回归残差化。
- cross-factor orthogonalization。
- 因子相关矩阵和条件数诊断。

规则：

- 横截面变换只使用同一 timestamp。
- 滚动时序变换只使用当前及过去数据。
- 可拟合变换器只能在训练集 `fit`，然后对验证集和样本外 `transform`。
- 正交化方法、因子顺序、回归截距和权重必须进入配置；使用 Grinold 合成算子时不做跨因子正交化矩阵预处理（同一问题，叠用等于双重计数）。
- 平滑必须是单边滤波，不得使用居中窗口。
- 标准差为零、回归矩阵奇异或有效样本不足时输出 NaN 和结构化警告。
- 不默认填充缺失因子，处理后索引保持不变。

### Step 5：完整标签系统

实现：

- `ForwardReturnLabel`
- `DirectionLabel`
- `FutureVolatilityLabel`
- `ResidualReturnLabel`
- `EventLabel`
- `LabelBuilder`

真实收益标签：

```text
label_h[t] = product(1 + True_Return[t+1:t+h]) - 1
```

实现要求：

- 每个 product 独立计算。
- 不跨缺口直接把另一个品种收益拼接进来。
- 最后 h 个有效观测保留 NaN。
- 输入中的 NaN 按配置采用严格传播；V1 默认窗口内任一期缺失则标签缺失。
- 不把标签列写回 `ResearchDataset.df`。

未来波动率只能使用 t 之后收益；残差收益必须记录基准、品种组或风险暴露模型的拟合窗口；事件标签必须给出可复现的阈值和端点。测试使用人工序列手工验证各类标签，并单独覆盖换月。

### Step 6：因子合成

在 `factors/combination.py` 实现：

- `CompositeFactor`：成分因子（仅基础因子，V1 禁止嵌套）+ 合成算子 + 成分缺失政策（默认 `strict`，可选 `renormalize` / `abstain`）。
- 无态算子：`EqualWeightCombiner`、`VoteCombiner`。
- 可拟合算子：`ICWeightedCombiner`、`GrinoldOptimalICCombiner`、`RegressionCombiner`，提供 `fit(factor_matrix, labels)` 与 `transform(factor_matrix)`。

规则：

- 合成输入为各成分因子完成单因子预处理后的因子矩阵。
- 可拟合算子的 `fit` 只能使用训练窗口数据与训练窗口标签；`transform` 不得访问标签。
- 交易时合成权重冻结；重新拟合是研究事件，产出新的状态版本，不在增量更新路径上。
- 使用 Grinold 算子时不做跨因子正交化矩阵预处理（同一问题，叠用等于双重计数）。
- 完整配方可序列化：成分及参数、各成分预处理链、算子及参数、拟合来源（训练窗口、标签规格、产出权重）。
- 批量/增量等价性延伸到复合层：增量 = 逐成分 `update` 后用冻结权重合成。

测试覆盖：

- 五种算子在人工面板上的手工复算。
- 成分缺失时三种缺失政策的行为。
- 验证集和样本外数据不改变训练期拟合的权重。
- 批量与增量合成结果等价。
- 因果性：修改 t 之后的数据，冻结权重下 t 及以前的复合因子值不变。

### Step 7：覆盖率、IC 与 Rank IC

`factors/evaluation/diagnostics.py` 中的覆盖率诊断输出：

- 总覆盖率。
- 每个 timestamp 覆盖率。
- 每个 product 覆盖率。
- 因窗口不足、原始缺失和标签缺失造成的有效样本变化。

`ic.py` 支持两种明确模式：

- `cross_sectional`：每个 timestamp 跨品种计算相关。
- `time_series`：每个 product 沿时间计算相关。

横截面模式至少有 `min_observations` 个有效品种才计算。输出 IC 明细及：

- 均值。
- 标准差。
- ICIR。
- 正值比例。
- 有效期数。

Rank IC 使用同组内 rank 后的 Pearson 相关。常数因子或常数标签返回 NaN，并记录警告。

同时实现：

- Newey-West 或其他适合时间相关性的稳健标准误。
- block bootstrap 置信区间。
- 多个因子、参数和标签期限下的多重检验校正。

原始 p-value、校正方法、校正后结果和检验总数必须同时保留。

### Step 8：分组收益

`factors/evaluation/grouped.py` 实现：

- 横截面模式按 timestamp 分组。
- 时序模式按 product 分组。
- 默认 5 组，可配置。
- 输出各组平均未来标签、样本数和最高组减最低组。

重复值导致无法形成目标组数时：

- 不抛出整个实验。
- 该截面返回 NaN。
- 将原因写入警告。

结果命名使用 `grouped_forward_returns`，不得使用 `strategy_returns`、`portfolio_pnl` 等名称。

### Step 9：衰减、换手、归因、稳健性与冗余

`factors/evaluation/diagnostics.py` 将同一因子对不同 horizon 的 IC、Rank IC 和多空组标签汇总为衰减表。

同一文件中的换手诊断实现一种清晰且唯一的 V1 定义：

- 横截面模式：相邻时点最高组和最低组成员变化率。
- 时序模式：相邻时点标准化因子方向变化率。

输出中必须记录定义，避免以后把不同换手口径混用。

`factors/evaluation/attribution.py` 输出：

- 分 product 统计。
- 分自然年度统计。
- 分行业/品种组、交易所和市场状态统计。
- 分流动性、持仓量和展期收益率区间统计。

`factors/evaluation/robustness.py` 实现：

- 样本内、验证集和样本外结果对比。
- walk-forward。
- 参数敏感性。
- 成本代理和流动性压力情景。
- bootstrap 与多重检验汇总。

`factors/evaluation/redundancy.py` 实现：

- 因子 Pearson/Spearman 相关。
- 条件相关和边际 IC。
- 正交化前后解释力变化。
- 共线性和重复信息警告。

`factors/evaluation/composite.py` 实现复合因子的合成专属诊断：

- 成分间相关结构（复用 `redundancy.py` 函数）。
- 复合 IC 相对最优单因子与成分加权平均 IC 的增量。
- 复合换手与成分换手对比。
- 滚动重拟合的权重稳定性。
- 合成算子超参敏感性。

### Step 10：统一评价器、实验身份与编排

`FactorEvaluator` 依次运行：

1. 覆盖率。
2. IC / Rank IC。
3. 分组收益。
4. 衰减。
5. 换手。
6. 完整归因。
7. 稳健性和多重检验。
8. 因子冗余分析。

`ResearchExperimentRunner` 依次运行：

1. 解析并规范化完整配置。
2. 计算配置哈希、数据指纹、Git 提交和实验 ID。
3. 构建数据和逐时点动态品种池。
4. 划分样本内、验证集、样本外或 walk-forward 窗口。
5. 从研究数据中提取各因子声明的输入列。
6. 计算原始因子并校验批量/增量契约。
7. 在训练窗口拟合并应用单因子预处理。
8. 应用跨因子正交化等矩阵预处理。
9. 构造标签。
10. 执行因子合成：可拟合合成算子仅使用训练窗口数据与标签拟合，再对全样本 transform 产出复合因子。
11. 运行评价、归因、稳健性、冗余分析和复合因子合成诊断。
12. 汇总结果、警告和实验身份。
13. 按配置写入持久化存储并生成报告。

`ResearchResult` 保存原始因子值、处理后因子值和复合因子值，避免无法判断结果来自因子本身、预处理还是合成。

### Step 11：实验存储、核心表格与 tear sheet

`factors/storage.py` 提供：

- 基于配置哈希和数据指纹的缓存键。
- 实验 manifest。
- Parquet 结果表。
- JSON 配置、警告和运行环境。
- 成功、失败和部分完成状态。
- 原子写入及缓存命中校验。

批量参数实验支持可配置并行度；相同配置不得重复计算，失败实验不得伪装成有效缓存。

`factors/reporting.py` 支持 `tables` 和 `tear_sheet` 两种模式。核心表格至少包括：

```text
config.json
metadata.json
factor_values.parquet
labels.parquet
universe.parquet
coverage.parquet
ic_detail.parquet
ic_summary.parquet
grouped_returns.parquet
decay.parquet
turnover.parquet
attribution.parquet
robustness.parquet
redundancy.parquet
composite_diagnostics.parquet
warnings.json
```

完整 HTML tear sheet 借鉴 Alphalens-Reloaded 的 Returns、Information Coefficient、Turnover 和 Grouped Analysis，并增加：

- 动态品种池和覆盖率。
- 因子分布及预处理前后对比。
- IC 时序、分布和衰减。
- 分组累计标签和换手。
- 流动性、持仓量和展期收益率暴露。
- 品种、时期、品种组和市场状态归因。
- 样本外、参数敏感性、稳健性和多重检验。
- 因子相关性、正交化和冗余。

报告只消费 `ResearchResult`，不得在绘图阶段重新计算另一套指标。

`CandidateFactor` 保存：

- 因子定义（`Factor | CompositeFactor`）、名称和参数。
- 因子类型。
- 必需字段和最小历史窗口。
- 若为复合因子：完整合成配方（成分及参数、各成分预处理链、合成算子及参数、成分缺失政策、拟合来源）。
- 研究结果引用。
- 研究者备注。

创建 Candidate 必须由研究者显式调用，不设置“IC 大于某值自动通过”。

### Step 12：通用策略适配与复合因子输入

在 `strategy/factor_adapter.py` 实现通用适配：

- 注册策略本次使用的多个 `CandidateFactor` 实例（单因子或复合因子），但不建设全局因子注册中心。
- 将同一时间戳已可见的 `BarMarketEvent` 转为因子增量接口需要的品种截面。
- 为每个因子维护独立 `FactorState`；对复合因子，逐成分维护状态并用冻结权重合成。
- 同步输出当前时点的因子值（含复合因子值）和缺失状态。
- 处理热身期、动态品种池进入/退出、换月和状态重置。

策略适配器只构造因子声明的最小输入，不伪造 `True_Return` 或未来标签，也不创建完整 `ResearchDataset`。

多因子合成由因子模块的 `CompositeFactor` 完成，策略层不自建组合模型。策略侧信号接口负责：

- 因子方向统一、阈值和信号生成。
- 缺失降级政策（与合成算子的成分缺失政策保持一致）。
- 从因子值到目标仓位的映射。

因子模块不得导入 Strategy，依赖方向保持为 `strategy -> factors`。

## 7. 测试计划

### 7.1 核心模型与 Schema

- 非法 horizon、空产品列表和重复产品报错。
- 缺失必需字段报错。
- 重复面板索引报错。
- 非大写 product 被 Builder 规范化。
- 负成交量、负持仓量和非法期限结构报错。
- 输入 Frame 不被组件原地修改。

### 7.2 DatasetBuilder 与动态品种池

- Fake DataFacade 的两个产品正确组成面板。
- 某产品返回空数据时直接报错并指出产品。
- 不完整交易日不被错误前向填充。
- `scheduled` / `realized` 参数原样传递。
- 上市时长按品种而不是当前主力合约计算。
- 成交量过滤按配置使用当日收盘或前一日信息。
- 品种池进入/退出逐时点正确，并保留排除原因。
- 修改未来成交量不影响当前及过去品种池。

### 7.3 因子黄金路径

- 手工验证原始动量严格按品种计算，不依赖同一时点的其他品种。
- 使用同一份原始动量分别验证时序和横截面评价模式。
- 手工验证展期收益率的合约选择、到期日差和年化。
- 窗口严格按产品隔离。
- 因子结果索引与输入完全一致。
- 批量与增量接口在热身期、品种池变化和缺失值下输出等价。

### 7.4 预处理黄金路径

- 缩尾、z-score、robust z-score、秩和分位数归一化可手工复算。
- 中性化后对指定暴露的样本内相关符合预期。
- 正交化结果及因子顺序符合配置。
- 平滑只使用当前及过去值。
- 验证集和样本外数据不会改变训练期拟合参数。
- 奇异矩阵和样本不足产生结构化警告。

### 7.5 标签黄金路径

- 1、5、20 期标签方向正确。
- 使用 t+1 开始的收益，不包含 t。
- 标签不跨产品。
- 尾部 NaN 数量正确。
- 换月附近 `True_Return` 端点符合契约。
- 方向、未来波动率、残差收益和事件标签可手工复算。
- 基准或风险暴露的拟合不读取样本外信息。

### 7.6 因子合成黄金路径

- 五种合成算子在人工面板上可手工复算。
- 成分缺失时 strict / renormalize / abstain 三种政策行为正确。
- 可拟合算子的权重只在训练窗口估计，验证集和样本外数据不改变权重。
- 批量与增量合成结果逐时点等价。
- 复合因子遵守输出契约：索引对齐、名称稳定、不修改输入。

### 7.7 诊断黄金路径

- Pearson IC 和 Rank IC 可手工复算。
- 常数截面返回 NaN。
- 样本不足不被记为 0。
- 分组结果单调性场景正确。
- 重复值和组数不足产生结构化警告。
- 衰减使用不同 horizon 的标签。
- 换手定义与人工成员变化一致。
- 稳健标准误和 bootstrap 使用固定随机种子可复现。
- 多重检验校正保留原始与校正结果。
- 归因分组不丢失或重复样本。
- 冗余分析能识别完全相同和高度相关因子。

### 7.8 因果性测试

构造两份只有未来区间不同的数据：

```text
dataset_a[:t] == dataset_b[:t]
dataset_a[t+1:] != dataset_b[t+1:]
```

断言：

- t 及以前的因子值完全一致。
- t 的未来标签允许不同。
- 预处理后的 t 及以前因子值完全一致。
- 冻结权重下，t 及以前的复合因子值完全一致。
- t 及以前的动态品种池完全一致。

### 7.9 实验、存储与报告测试

使用 5 个以上品种和足够覆盖滚动窗口的人工面板，执行完整实验，检查：

- 所有结果表存在且索引含义明确。
- 实验 ID、配置哈希、数据指纹和 Git 信息完整。
- 警告被收集。
- 缓存命中、失效和失败状态正确。
- 串行与并行结果一致。
- tables 模式文件齐全。
- tear sheet 所有页面可生成，且指标来自 `ResearchResult`。
- 相同输入和配置结果完全一致。

### 7.10 策略集成测试

- 多个 FactorState 相互隔离。
- 策略适配器按时间戳输出完整因子向量（含复合因子值）。
- 热身、缺失和品种池退出政策正确。
- 复合因子合成不改变成分因子值或因子状态。

### 7.11 真实数据冒烟测试

从 `DataFacade` 加载多个品种和足够长的日期区间，运行动态品种池、动量因子和完整实验。期限结构接口就绪后再加入展期收益率冒烟测试。真实数据测试使用独立标记，避免本机绝对路径数据影响核心回归测试。

## 8. 开发过程中的检查点

### Checkpoint 1：数据与标签可信

- 统一面板契约通过。
- 动态品种池不使用未来信息，并能解释每次排除。
- `True_Return` 换月语义通过人工测试。
- 期限结构数据契约通过。
- 全部标签均可手工复算。

在此之前不开始写大量评价指标。

- 三个基础因子结果正确。
- 批量与增量接口等价。
- 无跨品种窗口污染。
- 中性化、正交化和拟合窗口无未来信息。
- 可拟合合成算子仅在训练窗口拟合，权重在样本外冻结。
- 因果性测试通过。
- 输入未被修改。

### Checkpoint 3：诊断结果可信

- IC、Rank IC 和分组收益可手工复算。
- 单品种时不会输出伪横截面 IC。
- NaN、样本不足和重复值政策明确。
- 稳健统计、多重检验、归因和冗余分析可复现。

### Checkpoint 4：实验基础设施完成

- 实验配置可以驱动完整流程。
- 实验身份、持久化、缓存、批量和并行正确。
- 核心表格和 tear sheet 均可输出。
- 候选因子由研究者显式生成。

### Checkpoint 5：策略衔接完成

- 通用适配器支持多个候选因子（单因子或复合因子）。
- 逐 Bar 增量更新和状态生命周期正确；复合因子逐成分更新并用冻结权重合成。
- 候选因子能向现有 Strategy 输出信号输入。

## 9. V1 完成标准

V1 只有同时满足以下条件才算完成：

- 能从 `DataFacade` 构建日频单品种和多品种研究面板。
- 能依据上市时长、流动性等条件构建无未来信息的动态品种池。
- 能通过批量和增量接口计算原始动量和展期收益率，并对同一因子结果独立执行时序或横截面评价。
- 能完成缩尾、归一化、中性化、正交化、平滑和拟合型预处理。
- 能将多个因子按显式算子合成为复合因子，并完成标准诊断与合成专属诊断。
- 能构造真实收益、方向、未来波动率、残差收益和事件标签。
- 能输出完整诊断、稳健统计、多重检验、归因和冗余分析。
- 能执行带身份、样本划分、参数网格、指纹、持久化、缓存和并行的实验。
- 能按配置输出核心表格或完整 tear sheet。
- 能显式生成候选因子（单因子或复合因子），并通过通用增量适配器向策略提供因子输入。
- 时间因果、动态品种池、跨品种隔离、换月标签、批量/增量和手工黄金路径测试全部通过。
- 核心测试不依赖本机外部行情路径。
- 因子模块不依赖订单、成交、账户或回测引擎。

V1 完成后可以支持这样的结论：

> 某个因子在明确的数据、时间、标签和诊断口径下表现出可复现的预测关系，值得进入策略组合和事件驱动回测。

它仍不能直接支持这样的结论：

> 该因子已经形成扣除成本、满足账户和执行约束的可交易策略收益。

## 10. V2 定位

`V2` 仅保留名称，不列预设功能。未来实际研究若暴露出 V1 无法回答的新问题，应重新编写 V2 的研究问题、数据契约、架构修改和代码方案。

日内因子研究不自动归入 V2。它需要独立讨论因子理论、数据来源与规模、标签、交易成本、评价、合成和策略交付，不能通过给当前日频管线增加一个 `freq` 参数来完成。
