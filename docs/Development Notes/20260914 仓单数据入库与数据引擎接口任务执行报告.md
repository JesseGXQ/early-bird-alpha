保留 `source_*` 字段是必要的：Tushare 会在同一 `symbol` 下使用 `fut_name`
区分仓库/厂库等合法记录类型；删除来源名称会错误合并不同记录。

本次数据中存在的单位为：千克、吨、张、手、桶。数据引擎只返回仓库级明细，
没有提供跨单位的自动总量聚合，避免产生无意义求和。

### 3.1 同一品种多单位分析

对当前正式库的 97 个 Parquet 文件进行全量扫描，共检查 2,675,499 行、79 个有数据品种；
`unit` 字段无空值。按本地权威品种代码 `product` 分组后，有 3 个品种出现多个单位：

| 品种 | 权威名称 | 单位及记录范围 | 同日共存 | 是否可稳定换算 |
|---|---|---|---:|---|
| `AG` | 沪银 | 千克：9,064 行，2014-05-19 至 2026-09-11；吨：1,122 行，2020-01-02 至 2025-11-11 | 1,040 个交易日 | 是，`1 吨 = 1,000 千克` |
| `AU` | 黄金 | 千克：2,961 行，2014-05-19 至 2026-09-11；吨：17 行，2020-04-10 至 2025-08-08 | 0 个交易日 | 是，`1 吨 = 1,000 千克` |
| `SC` | 原油 | 吨：3,146 行，2020-01-02 至 2025-11-11；桶：27,495 行，2018-10-24 至 2026-09-11 | 1,040 个交易日 | 否，吨为质量单位、桶为体积单位 |

结论如下：

1. **存在“同一品种、不同单位”**：共 3 个品种，占有数据品种的 3.80%。其中 `AG` 和
   `SC` 的不同单位在大量相同交易日内并存，并非单纯的历史单位切换；`AU` 的两种单位
   在当前数据中没有同日并存。
2. **存在“同一品种、且无法稳定转换的不同单位”**：仅 `SC`。吨与桶分别表示质量和
   体积，换算依赖原油密度、温度及计量口径；当前 schema 未包含这些条件，不能仅凭
   `unit` 给出确定换算系数。`AG`、`AU` 的千克与吨属于同一量纲，可固定换算。
3. 全库出现的“张”“手”没有与其他单位共同出现在同一品种中。数据引擎应继续保留
   `unit` 作为分组键；尤其不得直接汇总 `SC` 的吨与桶。若未来确需统一单位，应额外维护
   带适用条件和生效区间的品种级换算规则，而不应在查询接口中隐式换算。

## 四、全量与增量设计

### 全量模式

- 默认遍历 `product_meta` 的全部品种；
- 每个品种从本地权威上市日期拉取至指定结束日期；
- 请求按自然年分块；
- 达到 Tushare 文档所述单次上限后，通过 `offset` 继续分页；
- 检测连续重复页，不能确认完整性时直接失败；
- 每个正式文件先写 `.tmp`，完成后原子替换。

### 增量模式

- 从本地该来源的最大日期向前回看 10 个日历日；
- 完整替换回看日期窗口，而不是只追加，能够吸收源端修订和删除；
- 按业务自然键去重；
- 重复执行保持幂等；
- 可通过 CLI 调整回看长度、日期范围、品种、节流和重试参数。

### 凭证

读取优先级：

1. `--token`；
2. 环境变量 `TUSHARE_TOKEN`；
3. Git 忽略的 `db/rules_ingestion/supplements/API凭证.txt`。

源码、Parquet、原始快照、审计和本报告均不含凭证。

## 五、Tushare 特殊数据处理

### CU 与 BC

Tushare 的 CU 响应中包含 `fut_name=铜(BC)` 的国际铜记录。如果直接信任
`symbol=CU`，会把国际铜错误归入沪铜；如果同时读取 BC 接口，还会在重叠日期重复计算。

处理规则：

1. 从来源名称括号中的已知本地品种代码识别目标品种；
2. 将 `铜(BC)` 路由到本地权威 `BC / 国际铜 / INE`；
3. BC 和 CU 在 CLI 中自动联动刷新；
4. 业务自然键重叠时优先保留 BC 直接来源，CU 仅补齐其未覆盖历史；
5. 用 `source_symbol/source_product_name/source_exchange` 保留来源证据。

最终结果：

- CU：73,101 行，全部为 CU 直接来源，覆盖 2014-05-19 至 2026-09-11；
- BC：11,698 行，其中 BC 直接来源 4,059 行、CU 补充来源 7,639 行，
  覆盖 2020-12-29 至 2026-09-11；
- 两个来源的 3,922 个重叠业务键只保留一份，优先 BC 直接来源。

## 十一、已知边界

1. Tushare 仓单接口本身没有覆盖中金所金融期货，本地对应文件为空；
2. 单位存在多种，不应在未换算时跨单位聚合；
3. Tushare 未提供稳定记录 ID，本地使用包含来源记录类别、仓库及可选维度的复合自然键；
4. 原始响应和正式 Parquet 均为 Git 忽略数据，需要在新机器上重新执行入库；
5. 若 Tushare 日后出现新的“一个 symbol 承载另一个品种”编码方式，校验和来源字段可用于审计，
   但应先补充显式映射测试再上线。
