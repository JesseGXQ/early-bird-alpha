# 三层期货交易规则数据库：路径、命名标准与模块重组方案

## 背景

当前项目已有一个 `data/` 模块，但三层数据库的边界未被正式化，路径也较为分散。本方案将：
1. 明确三层数据库各自的**本地存储路径**和**文件命名标准**；
2. 规划 `data/` 模块的**必要重构**，以正确反映三层架构；
3. 保持对现有代码（`FileLocator`、`BarLoader`、`DataFacade` 等）的**最小破坏性改动**。

---

## User Review Required

> [!IMPORTANT]
> 以下两处设计决策需要您确认后，才能进入执行阶段：
> 1. **Tier 2 的文件分割粒度**：建议"按交易所分文件"（例如 `SHFE.parquet`），还是"单一总表"（`instrument_registry.parquet`）？两者各有取舍，见下文。
> 2. **`data/metadata/` 目录重命名**：建议将现有的 `data/metadata/` 目录（目前同时存放 Tier 1 YAML 和管理类 Python 文件）拆分为 `data/rules/`（存放管理类）和 `data/db/`（存放数据文件），还是保留现有名称、仅重组内部结构？

## 现状梳理

### 现有路径（对照 `EnvironmentConfig`）

| 变量 | 当前路径 | 实际对应什么 |
|------|----------|-------------|
| `meta_dir` | `./data/metadata/instrument_meta` | Tier 1 YAML 文件 |
| `daily_snapshot_dir` | `./data/storage/daily_snapshots` | 目前兼容 Tier 2 + Tier 3 |
| `master_table_dir` | `./data/metadata/master_tables` | 换月主表（独立概念，不属于三层之列） |
| `data_dir_1min` | `./data/storage/bar_1min` | 行情数据（Tick/Bar，独立于三层架构） |
| `data_dir_tick` | `./data/storage/tick` | 同上 |

### 现有问题

1. `data/metadata/` 目录混放了 Python 管理类（`.py`）和数据文件（`.yaml`），职责不清晰。
2. Tier 2（合约注册表）目前没有明确的路径，数据文件不存在。
3. Tier 3（日频状态）与"日频行情快照（涨跌停价）"混在同一个 `daily_snapshots/` 目录中，将来会产生歧义。
4. `EnvironmentConfig` 的字段命名（`meta_dir`、`daily_snapshot_dir`）无法反映三层架构的概念。

## 提议方案

### 一、三层数据库本地路径与命名标准

#### Tier 1：`product_meta`（品种规则配置）

```
data/
└── db/
    └── tier1_product_meta/          ← 新路径（原 data/metadata/instrument_meta/）
        ├── SHFE_RB.yaml             ← 命名格式：{EXCHANGE}_{PRODUCT}.yaml
        ├── SHFE_AU.yaml
        ├── DCE_I.yaml
        ├── CZCE_MA.yaml
        ├── CFFEX_IF.yaml
        └── _index.yaml              ← 品种索引摘要（可选，供快速枚举）
```

**文件命名规则**：`{EXCHANGE}_{PRODUCT}.yaml`，全部大写。
- 原因：避免不同交易所同名品种冲突（虽然目前罕见），同时便于按交易所过滤。
- 对比原命名（`RB.yaml`）：原方案在没有跨交易所冲突时可用，但不够健壮。

> [!NOTE]
> `_index.yaml` 为可选，内容为所有品种的摘要列表（`product`、`exchange`、`is_active`），
> 供系统启动时快速加载品种目录，不需要逐个打开 YAML。

---

#### Tier 2：`instrument_registry`（合约注册表）

```
data/
└── db/
    └── tier2_instrument_registry/
        ├── SHFE.parquet             ← 按交易所分文件（推荐方案A）
        ├── DCE.parquet
        ├── CZCE.parquet
        └── CFFEX.parquet
```

**或者**（方案B：单一总表）：
```
data/
└── db/
    └── tier2_instrument_registry/
        └── instrument_registry.parquet   ← 单一总表（方案B）
```

**字段**（Parquet schema）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `instrument` | `str` | 合约代码，主键，例如 `RB2610` |
| `product` | `str` | 品种代码，例如 `RB` |
| `exchange` | `str` | 交易所代码，例如 `SHFE` |
| `name` | `str` | 合约中文名称 |
| `multiplier` | `float` | 合约乘数（该合约生命周期内固定） |
| `list_date` | `date` | 上市日期 |
| `expire_date` | `date` | 到期日 |
| `start_deliv_date` | `date` | 开始交割日 |
| `end_deliv_date` | `date` | 最后交割日 |
| `delivery_year` | `int` | 交割年份 |
| `delivery_month` | `int` | 交割月份 |
| `exchange_inst_id` | `str` | 交易所报单合约代码（若与 `instrument` 不同） |

> [!NOTE]
> **方案A（按交易所分文件）vs 方案B（单一总表）**
> - 方案A：查询某交易所的所有合约时，只需加载一个小文件，I/O 效率高。管理（更新）时也只需替换一个交易所的文件，不影响其他交易所。**推荐**。
> - 方案B：全市场扫描（如选股）时只需一次 `read_parquet`，更简单。但文件会越来越大。

---

#### Tier 3：`instrument_daily_status`（日频动态状态）

```
data/
└── db/
    └── tier3_instrument_daily_status/
        ├── SHFE_RB.parquet          ← 命名格式：{EXCHANGE}_{PRODUCT}.parquet
        ├── SHFE_AU.parquet
        ├── DCE_I.parquet
        └── ...
```

**字段**（Parquet schema）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `trading_date` | `date` | 交易日期（联合主键之一） |
| `instrument` | `str` | 合约代码（联合主键之一） |
| `inst_life_phase` | `str` | 合约生命周期状态（`listed` / `active` / `expired`） |
| `is_trading` | `bool` | 当日是否可交易（停牌等） |
| `long_margin_ratio` | `float` | 多头保证金率 |
| `short_margin_ratio` | `float` | 空头保证金率 |

**索引**：Parquet 文件写入时，按 `(trading_date, instrument)` 建立行组（row group）排序，加速点查询。

> [!NOTE]
> **关于涨跌停价的归属**
> 已确认：`upper_price_limit` 和 `lower_price_limit` 放入**日频行情快照**（`daily_bars`），
> 不放入 Tier 3 状态表。Tier 3 仅保存纯交易规则/状态字段。

---

#### 日频行情快照（独立，非三层架构范畴）

```
data/
└── storage/
    └── daily_bars/                  ← 原 daily_snapshots/，重命名
        ├── RB_daily.parquet         ← 命名格式：{PRODUCT}_daily.parquet（保持现有格式）
        ├── AU_daily.parquet
        └── ...
```

**字段**（现有 + 追加涨跌停）：
- `trading_date`、`instrument`（联合索引）
- `open`、`high`、`low`、`close`、`volume`、`open_interest`
- `settle`（结算价）、`pre_settle`（昨结算价）
- `upper_price_limit`、`lower_price_limit`（涨跌停价，从 Tier 3 迁移过来）

### 三、`EnvironmentConfig` 字段变更

```python
# data/config.py  —— 更新后

@dataclass(frozen=True)
class EnvironmentConfig:
    # ── Tier 1 ─────────────────────────────────────────────
    product_meta_dir: str = './data/db/tier1_product_meta'
    # 原: meta_dir = './data/metadata/instrument_meta'

    # ── Tier 2 ─────────────────────────────────────────────
    instrument_registry_dir: str = './data/db/tier2_instrument_registry'
    # 原: 无

    # ── Tier 3 ─────────────────────────────────────────────
    daily_status_dir: str = './data/db/tier3_instrument_daily_status'
    # 原: 无（Tier3 数据尚未建立）
```
