# 中国期货市场交易时段特殊安排研究

> 研究目的：为 `session_override_rules` 的后续设计建立事实边界。  
> 研究范围：中国内地期货交易所的期货交易时段，不系统讨论期权行权时段、客户适当性、持仓限额和交割资格。  
> 资料截止日：2026-06-13。

## 一、结论摘要

中国期货市场并不存在一张可以永久穷举的“特殊交易时段规则表”。从业务语义看，应当至少区分以下三层：

1. **基础交易时段的历史版本**：某品种启用夜盘、永久修改开收市时间。这不是 override。
2. **可重复计算的规则型 override**：例如国债期货最后交易日删除下午盘、法定节假日后首个交易日删除夜盘。
3. **由公告产生的事件型 override**：例如疫情期间暂停全部夜盘、系统故障导致夜盘延迟开市、熔断导致盘中暂停或提前收市。

本次研究确认或识别出七类需要关注的特殊语义：

| 编号 | 类型 | 典型动作 | 是否可预先计算 |
|---|---|---|---|
| R1 | 最后交易日缩短交易 | 删除下午盘或提前收盘 | 可以 |
| R2 | 新合约、新品种上市首日差异 | 首日无夜盘或从夜盘开始 | 可以，但依交易所规则 |
| R3 | 法定节假日夜盘关闭 | 删除节后首个交易日的夜盘 | 可以，但仍应以年度通知校验 |
| R4 | 较长期间暂停夜盘 | 对日期区间删除夜盘 | 不宜仅靠通用规则，需事件公告 |
| R5 | 临时调整开收市时间 | 延迟开盘、提前收盘、暂停某一时段 | 否，需事件公告 |
| R6 | 盘中事件触发暂停或提前结束 | 熔断、技术故障暂停 | 只能在事件发生后确定 |
| R7 | 整个交易日临时休市或顺延 | 修改交易日历，而非修改日内 session | 否，属于交易日历事件 |

最重要的两项纠偏是：

- “节假日前一天无夜盘”是物理日历视角的说法。按期货交易日归属，准确语义通常是：**法定节假日后的第一个交易日不包含夜盘**。
- 截至本报告完成时，没有找到交易所官方规则支持“商品期货合约进入交割月后统一取消夜盘”。该说法不能作为通用 override 写入系统。

## 二、研究口径与证据等级

### 2.1 什么才算 session override

本报告把 override 定义为：在某个已经生效的基础交易时段之上，因为合约生命周期、交易日属性或临时公告，对 session 做删除、替换、截短、延迟或暂停。

以下事项不应混入 override：

- 某品种从某日起永久启用夜盘，属于基础时段新版本。
- 某产品本来就没有夜盘，属于基础时段属性。
- 客户进入交割月后不得持仓或不得开仓，属于客户或持仓规则。
- 合约涨跌停后没有成交，不代表交易时段不存在。
- 行情源缺失数据，不足以证明交易所关闭了该时段。

### 2.2 证据等级

| 等级 | 含义 |
|---|---|
| A | 交易所官方合约、规则、通知或官方专题材料直接确认 |
| B | 交易所官方沿革材料、权威媒体转载交易所通知，或可由多项官方材料稳定推定 |
| C | 市场口头说法、经纪商惯例或尚未找到官方依据的假设 |

## 四、合约生命周期类规则

### 4.1 中金所国债期货最后交易日仅上午交易

这是目前最明确、最稳定的合约级 session override。

中金所现行合约表规定：

| 产品 | 上市日期 | 普通交易日当前时段 | 最后交易日当前时段 | override 动作 |
|---|---:|---|---|---|
| 5年期国债期货 `TF` | 2013-09-06 | 09:30-11:30，13:00-15:15 | 上午盘 | 删除下午盘 |
| 10年期国债期货 `T` | 2015-03-20 | 09:30-11:30，13:00-15:15 | 上午盘 | 删除下午盘 |
| 2年期国债期货 `TS` | 2018-08-17 | 09:30-11:30，13:00-15:15 | 上午盘 | 删除下午盘 |
| 30年期国债期货 `TL` | 2023-04-21 | 09:30-11:30，13:00-15:15 | 上午盘 | 删除下午盘 |

这里应将规则理解为“最后交易日删除下午 session”，而不是把 `09:30-11:30` 永久写死在 override 中。原因是基础开盘时间本身可能存在历史版本，override 只负责生命周期造成的差异。

适用范围是具体到期合约，而不是整个产品在该日都只有上午盘。例如 `T2609` 到期时仅上午交易，不代表同日仍在交易的其他 `T` 合约必须删除下午盘。

### 4.2 股指期货最后交易日提前收盘的历史规则

沪深300股指期货早期的普通交易日时段为上午09:15-11:30、下午13:00-15:15，最后交易日则在15:00结束，因此最后交易日存在15分钟的提前收盘。

2015年12月，中金所修订股指期货交易时间，自2016-01-01起将股指期货连续竞价统一为09:30-11:30、13:00-15:00。普通交易日和最后交易日由此都在15:00结束，原有“最后交易日提前15分钟收盘”的 override 自然消失。

历史适用对象可归纳为：

- `IF`：2010-04-16上市后至2015-12-31。
- `IH`、`IC`：2015-04-16上市后至2015-12-31。
- `IM`：2022年才上市，不存在这段历史规则。

这条沿革说明 override 规则本身也必须具有有效期；不能拿当前合约表反推全部历史。

### 4.3 “进入交割月后无夜盘”未获官方规则支持

本次检索没有发现上期所、上期能源、大商所或郑商所存在一条普遍规则，规定“合约进入交割月后取消夜盘”。郑商所官方夜盘细则列举了新品种首日、节假日和应急处置等特殊情形，没有列出交割月取消夜盘。

该说法很可能混合了以下几类不同规则：

1. 自然人客户必须在规定日期前退出交割月持仓。
2. 交割月持仓手数、整倍数、保证金或限仓标准发生变化。
3. 某个品种从一开始就没有夜盘。
4. 合约最后交易日结束后自然终止交易。
5. 期货公司对客户采取了严于交易所的风控限制。

这些规则会影响“某客户能否交易”，但不等于交易所层面的 session 被删除。因此：

> 在找到“交易所、品种、实施日期、规则原文”四项完整证据之前，不应建立通用的 `delivery_month -> remove_night_session` 规则。

## 五、上市首日类规则

郑商所2014年夜盘规则明确区分“已有品种的新合约”和“新上市品种”：

- 夜盘品种的新合约，首日交易从上市交易日的夜盘开始。
- 新品种上市的首日交易从上市交易日的日盘开始。

这会产生两个容易被忽略的结果：

1. 同样标记为 `list_date = D`，已有夜盘品种的新合约可能在物理日 `D` 之前的晚上已经开始属于交易日 `D` 的交易。
2. 一个未来具有夜盘的新产品，在产品首次上市日 `D` 仍可能没有夜盘；其首个夜盘通常是 `D` 当晚、归属于下一个交易日。

郑商所于2014-12-12启动首批五个夜盘品种：白糖、PTA、棉花、菜籽粕和甲醇。上述首日规则自该夜盘制度实施时即具有业务意义。

其他交易所也可能在新品种上市通知中规定首日从日盘开始，但应逐所、逐版本确认，不能直接把郑商所规则扩展到全部交易所。

## 六、节假日夜盘关闭

### 6.1 准确的交易日语义

郑商所官方材料的原始语义是：

> 法定节假日后第一个交易日无夜盘交易。

其示例为：若10月8日是国庆节后的第一个交易日，则归属于10月8日交易日的夜盘不存在。因此物理日9月30日晚不交易，而10月8日晚恢复夜盘，因为10月8日晚属于10月9日交易日。

由此可见，系统中更稳定的规则表达是：

```text
if trading_date is first_trading_day_after_statutory_holiday:
    remove night session from trading_date
```

而不是：

```text
if calendar_date is last_workday_before_holiday:
    close night session
```

后一种表达依赖物理日期和交易日映射，跨周末、调休和长假时更容易出错。

### 6.2 适用品种和交易所

这条规则只对“在该历史时点已经具有夜盘基础 session”的品种生效，不能维护成一张永不变化的静态产品名单。

| 交易所 | 适用范围 | 最早相关时间 | 说明 |
|---|---|---:|---|
| 上期所 | 当时已启用连续交易的品种 | 2013年连续交易制度启动后 | 品种加入夜盘的日期各不相同 |
| 大商所 | 当时已启用夜盘的品种 | 2014-07-04夜盘上线后 | 后续品种分批加入 |
| 郑商所 | 当时已启用夜盘的品种 | 2014-12-12 | 首批为白糖、PTA、棉花、菜粕、甲醇 |
| 上期能源 | 当时已启用夜盘的国际化品种 | 2018-03-26原油期货上市后 | 应跟随上期能源年度通知 |
| 中金所 | 不适用 | 无夜盘 | 无需产生该 override |
| 广期所 | 截至2026-06-13不适用 | 当前仅日盘 | 官方合约和节假日通知未显示夜盘 |

上期所、上期能源、大商所和郑商所每年发布的节假日安排通常会再次明确具体哪个物理日晚间不进行夜盘。因此，通用规则可以负责计算，年度公告应作为最终校验和事件覆盖来源。

### 6.3 集合竞价联动

郑商所官方材料还确认：夜盘存在时，集合竞价位于20:55-21:00；若该交易日没有夜盘，集合竞价顺延到日盘开市前的08:55-09:00。

所以“删除夜盘”不仅改变连续竞价 session，还可能改变：

- 集合竞价时段；
- 开盘价所属时段；
- 前一日未成交报单的延续边界；
- 强平和结算业务的时限。

只删除一条 `night Session` 而不处理相关 session metadata，仍然可能得到不真实的交易日结构。

## 七、临时公告和事件型 override

### 7.1 2020年疫情期间暂停夜盘

为配合疫情防控，商品期货交易所自2020-02-03晚起暂停夜盘，后于2020-05-06晚恢复。

适用范围包括当时已经具有夜盘的商品期货和相关期权品种：

- 上海期货交易所；
- 上海国际能源交易中心；
- 大连商品交易所；
- 郑州商品交易所。

交易日归属需要特别转换：

- “2020-02-03晚暂停”影响的首个正常目标交易日是2020-02-04。
- “2020-05-06晚恢复”属于2020-05-07交易日。
- 因而按 `trading_date` 存储时，疫情造成的连续无夜盘区间可理解为2020-02-04至2020-05-06之间的有效交易日。
- 2020-02-03本身是春节后首个交易日，本来就没有节前夜盘，应由节假日规则解释。

这是一条交易所级、日期区间型 override，不能通过合约生命周期推导。

### 7.2 2019-12-25夜盘延迟开市

2019-12-25，因结算系统故障，上期所（包括上期能源）、大商所和郑商所公告将当晚夜盘开市时间推迟至22:30，较通常的21:00晚了90分钟。

按交易日归属，该事件主要作用于：

```text
trading_date = 2019-12-26
```

它不是永久修改基础时段，而是一次性的 `replace_open_time` 或 `truncate_session_start` 事件。不同品种原有夜盘收市时间不同，因此不能简单生成一条统一的 `22:30-23:00` session；应保留各产品原收市时间，只替换开市边界，并以各交易所当天通知为准。


### 7.3 技术、通信和结算故障

郑商所夜盘细则明确规定，在下列情况下，交易所可以调整夜盘开市、收市时间或者暂停夜盘：

- 计算机交易系统、通信系统等设施故障，导致10%以上会员不能交易；
- 夜盘开市前，30%以上会员未完成结算或交易系统初始化；
- 交易所认为必要的其他情况。

这类规则虽然存在稳定的“触发条件模板”，但是否触发、何时恢复以及最终时段，必须依赖交易所事件公告。它不适合仅靠 Tier 1 静态规则自动推导。

### 7.4 天气和自然灾害不是自动休市条件

本次研究没有发现中国内地期货交易所存在类似香港市场“达到某级台风或暴雨信号即自动休市”的常设规则。内地期货交易是全国集中市场，某地暴雨、台风或暴雪本身不能直接推导全国交易 session 被删除。

只有当天气或自然灾害进一步造成交易系统、通信、结算、人员组织等问题，并且交易所发布调整或停市通知时，才形成事件型 override。因此，“暴风雨临时休市”不宜作为可以自动计算的通用规则示例。

## 八、盘中暂停和提前结束

### 8.1 2016年股指期货熔断

中金所股指期货熔断制度自2016-01-01生效，实际覆盖2016-01-04至2016-01-07四个交易日，并自2016-01-08起暂停实施。

适用品种为当时全部股指期货：

- 沪深300股指期货 `IF`；
- 上证50股指期货 `IH`；
- 中证500股指期货 `IC`。

主要时段影响为：

- 14:45之前触发5%阈值时，暂停12分钟，随后进行3分钟集合竞价，再恢复连续交易。
- 14:45及以后触发5%阈值时，暂停交易至收市。
- 任意时点触发7%阈值时，暂停交易至收市。
- 股指期货交割日下午13:00后不实施熔断；上午触发的熔断最迟在13:00恢复，以保证交割。
- 国债期货不受股指熔断影响。

2016-01-04和2016-01-07均实际触发熔断并提前结束交易。对历史日内回测而言，这意味着“计划交易 session”和“实际可交易区间”是两个不同概念。

### 8.2 盘中暂停不一定应该改写标准 session

针对熔断或短时技术暂停，系统至少可能需要两种视图：

1. **scheduled sessions**：交易所原计划的标准交易时段。
2. **realized tradable intervals**：扣除熔断、技术暂停等事件后的实际可交易区间。

若把熔断直接改写为当天基础 session，可能导致标准时间轴、行情缺口检测和事件研究失去原始参照；若完全忽略熔断，撮合回测又可能在真实不可交易的分钟成交。因此这类事件不宜与“最后交易日删除下午盘”使用完全相同的语义。

## 九、整日休市与 session override 的边界

交易所可能因国家假期调整、突发事件或假期延长而改变开市日期。2020年春节假期延长并延后复市就是典型例子。

这类事件首先改变的是：

- 某日期是否为交易日；
- 前后交易日的映射；
- 夜盘属于哪个交易日。

它应由 `TradingCalendar` 的交易日层处理。只有在日期仍然是交易日、但其中某些交易小节被删除或改变时，才进入 session override 层。

## 十、不能从真实行情数据直接推断的事项

即使输入参数来自真实行情，也不能只根据“是否观察到成交或行情记录”反推 session：

- 涨跌停封死、无对手盘或极低流动性可能造成长时间无成交。
- 行情供应商可能缺失夜盘、集合竞价或停牌标记。
- 熔断期间可能仍有状态行情，但没有可成交连续竞价。
- 某客户不能开仓，不代表交易所 session 关闭。
- 已到最后交易日的合约和同产品远月合约可能具有不同 session。

因此，真实行情更适合用于校验官方规则计算结果和发现异常，不能替代交易所规则及公告成为唯一事实来源。

## 十一、对后续规则库的事实约束

本报告暂不展开数据库方案，但现有事实至少要求未来设计能够表达：

1. 规则作用域：交易所、产品、具体合约或动态产品集合。
2. 规则有效期：历史规则会开始、终止，也可能被基础时段变更“吸收”。
3. 条件：最后交易日、上市首日、节后首个交易日、指定交易日或事件触发。
4. 动作：删除 session、替换边界、插入暂停区间、整日关闭。
5. 时间归属：公告中的物理日晚上必须转换为目标 `trading_date`。
6. 证据来源：官方规则、公告编号、发布日期、原文链接和证据等级。
7. 两种结果视图：计划交易时段与实际可交易区间。

尤其不应把以下三种数据塞进同一种“规则字典”：

- 可重复计算的通用规则；
- 某个日期的一次性公告；
- 行情数据观察到的异常或缺口。

## 十二、仍需持续核验的事项

公开历史网页存在迁移、失效和附件不可检索问题。正式生产化之前，建议继续补齐：

1. 上期所、上期能源和大商所最早版本的节假日无夜盘规则原文。
2. 2019-12-25上期能源是否存在独立的延迟开市通知。follow-up：已确认，上期能源也延迟了。
3. 各交易所新品种上市首日是否一律从日盘开始，以及历史版本差异。
4. 是否存在极少数产品级公告，在特定交割月份或特定合约上取消夜盘。
5. 历年所有临时停市、延迟开市、提前收市公告的结构化清单。

第4项目前仅是待核验项，不能据此认定“交割月无夜盘”存在。

## 十四、最终判断

对于当前 `session_override_rules` 讨论，可以把事实结论压缩为：

1. **确定存在**：最后交易日缩短、节后首个交易日无夜盘、新品种首日差异、临时停夜盘、临时改开盘时间、盘中熔断或暂停。
2. **已经消失但历史回测需要保留**：2016年前股指期货最后交易日提前15分钟收盘，以及2016年短暂实施的股指熔断。
3. **目前没有官方证据**：商品期货进入交割月后普遍取消夜盘。
4. **无法靠静态规则穷举**：技术故障、疫情、临时休市和其他公告事件，必须保留事件型数据来源。
