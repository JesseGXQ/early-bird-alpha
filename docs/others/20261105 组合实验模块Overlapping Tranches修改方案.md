# 组合实验模块引入 Overlapping Tranches 的修改方案

日期：2026-11-05。

本次交付仅为方案文档，代码与 notebook 修改属于后续实施。本文记录已确认的研究口径、实现设计、运行时间预期与验收标准。

## 一、目标与已确定的研究口径

现有实验采用单一调仓相位。CurveSlope notebook 中，`h=55` 的单锚点代理净 Sharpe 为 1.171，在所测试的 20 个相位中最高，相位均值为 0.946。这说明单锚点结果可能显著影响持有期选择。

新增 overlapping 模式，将研究预算等分给错开调仓的批次，以降低对某一个调仓相位的依赖。这与原始研究提出的等权配置不同调仓相位的思路一致。[参考：Newfound Research](https://www.thinknewfound.com/rebalance-timing-luck)

研究入口：[`curve_slope.ipynb`](../../research/notebooks/202611/curve_slope.ipynb)；组合实验入口：[`experiment.py`](../../factors/diagnostic_portfolio/experiment.py)。

已确定以下口径：

| 项目 | 设计 |
|---|---|
| 批次数 | 等于现有调仓间隔 `h`，覆盖全部 h 个交易日相位 |
| 调度 | 每个交易时点更新一个批次，每个批次每 h 个时点更新一次 |
| 预算 | 每个批次固定占整体研究预算的 `1/h` |
| 启动 | 从 anchor 开始逐日启动，未启动预算留现金 |
| 支持范式 | 现有三种 harvest profile 全部支持 |
| 成本 | 汇总品种净权重变化后计算，允许批次交易内部抵消 |
| 目标波动率 | 在批次层沿用现有配方，汇总后不再缩放 |
| 持仓语义 | 延续现有连续研究权重口径，不增加批次独立净值或收益驱动的权重漂移 |

该功能分散的是调仓相位影响，不保证 Sharpe 提升，也不替代样本外检验。

## 二、调度、权重与记账规则

### 2.1 调度与启动

设全局时间轴为 `t₀…tₙ₋₁`，anchor 对应位置为 `a`，`h=interval`。

- 保留现有 anchor 解析方式：非交易日向后定位至第一个可用时点；anchor 之前保持空仓。
- 批次 `k` 首次在 `a+k` 更新，之后在 `a+k+h、a+k+2h…` 更新。
- 每日到期批次为 `(i-a) % h`。
- 最后一个全局时点仅实现收益，不生成新决策；保留现有不收取期末强制清仓成本的约定。
- 样本不足以启动全部批次时，继续按 `1/h` 分配，记录未完成启动的警告，不放大已启动批次。

以 `h=3` 为例，`qᵢ` 表示在时点 i 使用现有配方生成的完整预算目标：

| 决策时点 | 更新批次 | 汇总权重 |
|---|---|---|
| a | 0 | `qₐ / 3` |
| a+1 | 1 | `(qₐ + qₐ₊₁) / 3` |
| a+2 | 2 | `(qₐ + qₐ₊₁ + qₐ₊₂) / 3` |
| a+3 | 0 | `(qₐ₊₁ + qₐ₊₂ + qₐ₊₃) / 3` |

表中假设没有品种池退出事件。启动完成表示所有相位均已获得一次更新机会，不代表每个批次都有非零持仓。

### 2.2 批次权重与风险

每个到期批次先按现有配方生成完整预算权重 `q`，包括排名、逆波动率、目标波动率及现有权重约束，再按 `1/h` 纳入汇总：

\[
W_t=\frac{1}{h}\sum_{k=0}^{h-1}q_{k,t}
\]

- 非到期批次冻结权重，仅响应品种池强制退出。
- 退出品种须在全部批次中归零；重新准入时，只有后续到期批次可以重新建仓，历史持仓不得恢复。
- 到期批次遇到有效截面不足、信号全部相同或风险估计不可用时，沿用原配方的空仓规则；其他批次继续持有。
- 汇总后不重新归一化至 gross=1。不同批次方向抵消导致的敞口下降属于设计结果。
- 目标波动率配方的汇总组合可能低于目标波动率，也不承诺每天恰好达标。
- 品种退出后不额外修复市场中性，延续现有非调仓日行为。

### 2.3 收益与成本

复用现有汇总组合记账：

\[
R^{gross}_{t+1}=\sum_p W_{t,p}r_{t+1,p}
\]

\[
Cost_t=\sum_p c_p\left|W_{t,p}-W_{t-1,p}\right|
\]

权重与成本仍在决策后的下一期收益中体现。

不得平均各相位的 Sharpe、CAGR 或净值来代替组合绩效。应先汇总权重，再计算收益、净值和指标。毛收益可以与等预算相位收益均值核对；由于交易抵消，代理成本后收益通常不同于各相位净收益的均值。

主绩效继续包含启动期，并保留现有“首次非零敞口之后”的绩效口径，不新增默认剔除启动期的指标规则。

## 三、模块与接口修改

### 3.1 配置与运行器

给 `RebalanceConfig` 追加字段：

```python
mode: Literal['single', 'overlapping'] = 'single'
```

- `single` 保留原行为，现有调用方式和 presets 默认值不变。
- `overlapping` 下，`interval` 表示每个批次的更新间隔，同时决定批次数。
- 本版不增加自定义批次数、相位列表或批次预算参数。
- `build_rebalance_schedule()` 保持返回布尔 Series；overlapping 模式下，anchor 起每天都有一个计划批次更新，因此每天为 True。该标记不代表净交易一定非零。
- anchor 解析提取为共享内部逻辑，避免布尔日程与批次调度出现差异。

运行器仍只对齐一次输入、展开一次矩阵，并只执行一次汇总记账。

### 3.2 共享计算与批次状态

在权重层增加内部批次协调器，复用现有 `WeightStateMachine`，不把 h 个完整 Runner 嵌套运行。

当前三种配方在调仓日生成新目标时，均不依赖上一期持仓，因此可以：

1. 使用一个基础权重机，每日只追加一次收益历史。
2. anchor 起每天计算一个新的完整预算目标。
3. 用 `h × P` 环形缓冲区保存各批次当前目标，替换当日到期批次。
4. 维护批次权重总和，通过新旧批次差额更新汇总权重。
5. 检测品种准入从 True 变为 False 的事件，清除该品种在全部批次中的持仓。

风险历史从全局时间轴起点积累，anchor 仅控制建仓开始时间。单品种波动率、协方差估计及元数据不按 h 份重复计算。

`h=1` 直接复用现有每日调仓路径，使权重及记账结果与原模式一致。返回权重继续遵守副本契约。

未来若新增依赖批次历史持仓的配方，必须重新评估共享生成器的适用性，不能直接套用。

### 3.3 结果与存储

保持 `DiagnosticPortfolioResult` 的现有字段结构，使用已有容器：

- `target_weights`：始终为汇总组合权重。
- `status`：overlapping 模式输出每日到期批次编号、已启动批次数、预算启动比例及强制退出品种数；anchor 前批次编号为空。
- `metadata["tranches"]`：记录批次数、固定预算比例、启动规则、成本口径、风险应用层级和全部批次首次完成启动的时间；未完成则为 None。
- 现有协方差元数据仍按 timestamp 保存，可与 status 联查对应批次。
- 默认不输出完整 `T × h × P` 批次持仓历史，也不为每个批次重复生成绩效表。

存储写入版本升级至 schema 2，显式序列化 `mode` 并纳入配置指纹。新加载器兼容 schema 1、2；旧记录缺少 `mode` 时恢复为 `single`，历史文件和指纹不重写。升级版本可以防止旧加载器忽略新字段后，把 overlapping 实验误读成 single。

同时修复两个相关边界：

- ragged panel 展开后的缺位 `eligible` 明确填 False，避免 NaN 转 bool 后被视为准入。
- 全程空仓时，首次和末次非零权重日期返回 None，避免日期元数据收集报错。

## 四、运行时间与内存预期

### 4.1 估算依据

旧模式大约计算 `T/h` 次新目标；新模式每天更新一个批次，大约计算 T 次新目标。两种模式均只执行一次输入准备和汇总记账。

设 S 为公共处理耗时，C 为一次新目标计算耗时，则：

\[
Time_{single}\approx S+(T/h)C
\]

\[
Time_{overlapping}\approx S+TC+\text{批次维护开销}
\]

因此，目标生成次数约增加 h 倍，整次实验耗时通常不会直接增加 h 倍。目标波动率配方的 C 较大，增长会更明显。

### 4.2 已完成的简单代理验证

使用 Conda base、固定随机种子 `20261105` 的完整合成面板，将现有引擎的 `interval=55` 与 `interval=1` 比较；每种运行两次，取较短耗时。每日调仓结果用来近似新方案的目标生成成本，**不是完整新增功能的实测结果**。

| 配方 | 面板规模 | 每 55 日调仓 | 每日调仓 | 倍率 |
|---|---:|---:|---:|---:|
| 截面排名 | 6,070 日 × 88 品种 | 0.728 秒 | 0.993 秒 | 1.36× |
| 时序逆波动率 | 6,070 日 × 88 品种 | 0.789 秒 | 1.269 秒 | 1.61× |
| 目标波动率 | 1,500 日 × 30 品种 | 0.112 秒 | 1.240 秒 | 11.10× |

额外的 55 批次环形更新，在 6,070 日 × 88 品种上约为 0.014 秒；该测量未包含退出处理和完整审计输出。

据此给出实施预算：

- **截面排名：** 当前规模下，整次 Runner 预期约为原来的 **1.4–2.0 倍**。
- **时序逆波动率：** 预期约为 **1.6–2.5 倍**。
- **目标波动率：** `h≈55` 时应预留**约 10 倍量级或更高**，具体取决于截面宽度、窗口和协方差计算成本；小面板结果不能直接作为大面板上限。

这些范围是工程预估，不设为自动测试的耗时阈值。

CurveSlope 的六次因子计算无需重做。仅按截面排名代理结果外推，72 次 Runner 增量约为 `72 × 0.265 ≈ 19 秒`；真实 notebook 的缺失结构和运行环境会改变数值，端到端增幅还会被原有因子预计算耗时摊薄。

### 4.3 内存

新增主要状态为 `h × P` 的 float64 缓冲区，约占 `8hP` 字节。`h=55、P=88` 时为 38,720 字节，约 37.8 KiB。

不保存完整批次历史，因此不会产生 h 倍的结果表与持仓历史内存。

## 五、实施顺序与验收

实施顺序为：配置及调度 → 批次协调器 → 结果审计及存储兼容 → notebook 接入。

后续实施使用合成数据测试，从仓库根目录、Conda base 执行：

```powershell

```

必须覆盖：

- **兼容性：** 默认 single 通过原有测试；overlapping 的 `h=1` 与原每日调仓的权重、成本和收益一致。
- **调度：** h=3 手算案例、非交易日 anchor、延后启动、短样本未启动完成，以及最后一期不建立新决策。
- **参考实现核对：** 与 h 个独立相位权重机的等预算均值逐日比较，覆盖三种配方、缺失信号、品种退出和重新准入。成本按汇总权重重新计算。
- **相位稳定性：** 相同完整输入历史下，改变 anchor 后，在两组都完成启动且早期持仓全部替换的共同窗口内，汇总权重和后续收益一致；不要求累计净值或全样本指标一致。
- **记账：** 启动成本、下一期对齐、反向交易抵消、分品种成本率、缺失收益政策、全程空仓和批次抵消至零。
- **风险与约束：** 收益历史每日仅追加一次；风险预热包含 anchor 前数据；批次约束先应用后分摊；汇总后不额外归一化或缩放。
- **数据契约：** 缺位准入为 False，退出持仓不会随重新准入恢复，未来信号或收益不影响过去结果，输入与内部状态不被调用方修改。
- **存储：** schema 1 加载与重放、schema 2 两种模式往返、模式配置指纹区分及原有完整性校验。

方案阶段已用无文件改动的原型验证“共享生成器＋环形缓冲区”：在包含延后 anchor、信号缺失及退出重入的合成案例中，三种配方与独立相位参考的最大权重差异均不超过 `1.3×10⁻¹⁶`。正式实现仍需通过上述验收测试。
