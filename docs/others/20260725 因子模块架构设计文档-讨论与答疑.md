## 1. 因子诊断：覆盖率、衰减与换手

### 1.1 覆盖率（Coverage）

**诊断什么**：因子信号的可适用范围——在所有品种 × 所有时间点的面板中，因子能给出有效值的比例。

覆盖率低的因子意味着信号稀疏，仅对少数品种或少数时点有效。文档要求输出"总体、分时点、分品种覆盖率和有效样本数"（架构设计文档第 311 行）。

### 1.2 衰减（Decay）

**诊断什么**：因子预测能力的时效性——即预测力随持有期延长而衰退的速度。

通过分别计算因子对未来 1 天、5 天、10 天、20 天等不同期限收益的 IC 或分组收益，形成"衰减表"（架构设计文档第 332 行）。衰减曲线告诉研究者：

- 因子是短期信号（IC 迅速归零）还是持久信号（长期 IC 仍为正）
- 是否存在均值回复（短期正 IC，长期转负）
- 最优持有期（IC 峰值对应的期限）

慢衰减 + 低换手的因子策略可执行性好；快衰减因子需要高换手、高频交易。

### 1.3 换手（Turnover）

**诊断什么**：因子排序/分组的稳定性，间接衡量隐形成交成本。

架构设计文档提到"计算分组成员变化或标准化权重变化形成基础换手指标"（第 333 行）。换手衡量的是从 t 期到 t+1 期各品种在因子排序中的位置变化：

- 高换手 → 因子信号频繁翻转 → 实际交易摩擦成本高
- 低换手 → 因子稳定 → 策略可执行性好

换手率过高的因子即使 IC 好看，实盘中手续费和滑点也可能吃掉全部收益。

## 2. 因子归因：分解表现来源

架构设计文档中 `attribution.py` 的职责是"分解因子在品种、时期和市场状态中的表现来源"（第 403 行）。

归因分析的意义：整体 IC 均值掩盖了大量不均匀的信息。以一个时间序列动量因子为例：

### 2.1 分品种归因

| 板块 | 品种 | IC 均值 |
|------|------|---------|
| 黑色 | 螺纹钢 | 0.08 |
| 黑色 | 焦炭 | -0.02 |
| 能化 | PTA | 0.09 |
| 农产品 | 白糖 | -0.04 |

**发现**：整体 IC 基本由黑色和能化贡献，有色和农产品无效甚至反向——因子不是普遍适用的。

### 2.2 分时期归因

| 年份 | IC 均值 | 市场背景 |
|------|---------|---------|
| 2018 | -0.01 | 震荡市 |
| 2020 | 0.12 | 强趋势（疫情冲击） |
| 2023 | -0.02 | 趋势衰减 |

**发现**：因子预测力高度集中在强趋势年份。2019 年单独回测可能会否定该因子。

### 2.3 分市场状态归因

按波动率高低将每日截面分组：

| 市场状态 | IC 均值 |
|----------|---------|
| 高波动期（>60%分位） | 0.11 |
| 低波动期（<40%分位） | -0.03 |

按期限结构状态：

| 市场状态 | IC 均值 |
|----------|---------|
| 贴水品种 | 0.09 |
| 升水品种 | 0.01 |

**发现**：动量在高波动 + 贴水的品种上效果显著，在低波动或升水品种上几乎无效，可能与供需紧张带来的持续价格漂移有关。

### 归因的最终意义

把一个平均数拆开，看到它背后不均匀、不稳定的真相，从而做出有信息优势的组合决策：
- 只在特定板块/品种上使用该因子
- 在特定市场状态下增加权重，在不利状态下降低仓位甚至空仓
- 根据宏观环境预判因子表现

## 3. 稳健推断、重采样与多重检验

架构设计文档中 `robustness.py` 的职责是"执行稳健推断、重采样和多重检验"（第 404 行）。

### 3.1 稳健推断（Robust Inference）

**问题**：普通 t 检验假设 IC 序列独立同分布，实际可能存在自相关、异方差和异常值，导致 p 值过于乐观。

**例子**：动量因子 IC 均值 0.045，普通 t = 3.2，p = 0.001，看似高度显著。但 2020 年 3 月某几天 IC 极端值 +0.30（疫情冲击），这些高波动日应降权。

**稳健做法**：
- 按波动率对每日 IC 加权（高波动日降权）
- 使用 Newey-West 标准误（考虑自相关），t 值可能从 3.2 降到 2.1
- 去掉上下 1% 极端 IC 重新统计

**诊断目的**：检查因子表现是否被少数极端样本驱动。

### 3.2 重采样 / Bootstrap

**问题**：单次样本区间可能恰好"运气好"，统计量分布形态未知，无法给出置信区间。

**例子**：从 1200 个日度 IC 中有放回抽取 10000 次，得到 IC 均值经验分布：

```
Bootstrap 95% CI: [0.015, 0.075]
IC 均值 > 0 的概率: 91%
```

逐块 Bootstrap（Block Bootstrap）：每次抽连续 20 天数据块以保留自相关结构：

```
Block Bootstrap 95% CI: [-0.005, 0.090]
IC 均值 > 0 的概率: 86%
```

**诊断目的**：不依赖正态假设，直接估算统计量的不确定性。下界接近零或为负说明正 IC 可能是噪音。

### 3.3 多重检验（Multiple Testing）

**问题**：研究者测试几十个参数组合或因子变体，仅凭运气也会有一些"显著"。不做校正会选出虚假有效的因子送进实盘。

**例子**：测试动量因子回看期 5/10/20/40/60/120/250 天 × 持仓期 1/5/10/20 天 = 28 个参数组合。

- **Bonferroni 校正**：显著性阈值从 0.05 调整为 0.05/28 = 0.0018，所有参数组合可能都不显著
- **FDR 控制**：Benjamini-Hochberg 方法控制错误发现率在 5%
- **样本外检验**：在样本外验证 28 个组合中有多少保持正 IC，筛选真正稳健的参数

**诊断目的**：防止数据挖掘（data snooping）和过拟合。在大量参数扫描后必须用校正方法或样本外测试筛选可靠的因子/参数。

## 4. 因子相关性、重复信息与边际解释能力

架构设计文档中 `redundancy.py` 的职责是"分析因子相关性、重复信息和边际解释能力"（第 405 行）。

### 4.1 因子相关性

计算每日截面上因子间的截面相关系数，再取时间序列均值：

```
           MOM_20    MOM_5    Roll
MOM_20     1.00      0.72     0.15
MOM_5      0.72      1.00     0.10
Roll       0.15      0.10     1.00
```

MOM_20 和 MOM_5 截面相关性 0.72——两种动量因子排的品种顺序高度一致，几乎在说同一件事。MOM 和 Roll 相关性仅 0.15——捕捉的截面排序截然不同。

### 4.2 重复信息（冗余度）

用方差膨胀因子（VIF）衡量一个因子能被其他因子线性解释的程度。MOM 和 S_MOM 互相解释对方 50%+ 的波动（VIF ≈ 2.1），Roll 几乎完全独立（VIF ≈ 1.03）。

更直观：看因子排名的重叠率——MOM vs S_MOM 前 1/3 分组重叠率 68%（高重复），MOM vs Roll 仅 38%（接近随机 33%）。

### 4.3 边际解释能力

用 Fama-MacBeth 截面回归检验新增因子是否提供额外预测信息。

在已有 MOM 的基础上加 S_MOM：S_MOM 的边际贡献不显著（t = 0.7）。
在已有 MOM 的基础上加 Roll：Roll 的边际贡献显著（t = 2.4）——在已知动量的情况下，Roll 仍能提供额外的截面区分度。

### 最终决策

| 因子 | 单独 IC | 相关性 | 边际贡献 | 结论 |
|------|---------|--------|---------|------|
| MOM_20 | 0.045 | 基准 | 基准 | **保留** |
| MOM_5 | 0.042 | 与 MOM 0.72 | 不显著 | **剔除**（冗余） |
| Roll | 0.040 | 与 MOM 0.15 | 显著 | **保留**（增量信息） |

将 MOM 和 Roll 两个低相关 + 各自显著 + 互相有边际贡献的因子组合成复合信号，才是真正从不同角度捕捉收益来源的多因子模型。

## 5. 与开源框架（Alphalens）的对比

| `plotting.py` | 全部可视化函数 |
| `tears.py` | 组织 tear sheet 综合报告页 |

| 欠缺项 | 说明 |

### 5.4 定位差异

```
Alphalens：
  外部因子值 → [ 诊断 + 可视化 + 报告 ]

本项目：
  行情数据 → [ 数据组装 → 因子计算 → 预处理 → 标签构造 → 诊断 → 实验编排 → 候选交付 ]
```

Alphalens 是一个评价工具箱，本项目是一个完整的研究系统。

## 6. 动态品种池（Universe）设计

### 6.1 动态品种池应放入 V1

架构设计文档将动态品种池放在 V2（第 262 行），但讨论后认为**至少存续性过滤应放入 V1**。

**核心理由**：

1. **期货品种池天然是动态的**：新品种上市（生猪 2021、碳酸锂 2023）、老品种退市/无成交（早籼稻、普麦）。没有动态池，多品种长期回测会产生幸存者偏差和前视偏差。

2. **这是数据组装层的基本前提**：`DatasetBuilder` 在构建截面时，必须先确定"当前时点哪些品种是活跃的"，否则会把还未上市的品种错误纳入。

3. **偏差无法被后续诊断发现**：用 2023 年的活跃品种池做 2018 年截面，IC 和分组收益会看起来比真实情况更好，但诊断体系无法检测到这种偏差。

4. **真实研究中的最低配置**：海通证券研报等实际研究中的品种池约束（上市满半年 + 20 日均成交量 > 1 万手）是随手就加的基本过滤条件，不是高级特性。

### 6.2 动态品种池的分层

| 层次 | 内容 | V1 还是 V2 |
|------|------|-----------|
| 第一层：存续性 | 品种已上市且未退市 | **V1** |
| 第二层：基础可交易性 | 均量阈值、均持仓阈值、上市天数 | **V1** |
| 第三层：复杂过滤 | 涨跌停、临近交割月剔除 | V2 |
| 第四层：自适应 | 动态选 top-N 品种、按流动性加权 | V2 |

**修正**：V1 至少应实现第一层 + 第二层的基础可交易性过滤（成交量阈值 + 上市天数）。海通证券研报的"上市满半年 + 20 日均成交量 > 1 万手"就是这两层的典型组合，代码量极小，收益极大。

### 6.3 品种池约束必须进入实验配置

架构设计文档第 3.4 节明确要求"品种池必须进入配置或结果元数据"。具体原因：

- 改变任一约束参数，品种池变化 → IC 计算截面变化 → 分组构成变化 → 换手率和覆盖率变化
- 不记录约束参数，两个同因子同区间但不同池的实验结果出现差异时无法解释原因

建议 `DatasetSpec` 扩展 `universe_rules` 字段：

```python
DatasetSpec:
    start_date
    end_date
    freq
    view
    universe_rules:                          # 新增
        min_listing_days: 126                # 上市满半年
        min_avg_volume: 10000                # 20日均成交量 > 1万手
        min_avg_open_interest: null          # 可选持仓量阈值
        ...
```

### 6.4 内置 + 自定义的双轨设计

`universe.py` 采用"内置积木 + 自定义插件"的设计模式：

**第一轨：内置过滤条件（开箱即用）**

```python
# universe.py 提供
class ListedDaysFilter(UniverseFilter):      # 上市天数
class AvgVolumeFilter(UniverseFilter):       # 均量
class AvgOIFilter(UniverseFilter):           # 均持仓
class DeliveryFilter(UniverseFilter):        # 临近交割月
class TopNActiveFilter(UniverseFilter):      # 动态选 top-N（V2）
```

**第二轨：自定义扩展接口**

```python
# 抽象基类
class UniverseFilter:
    name: str               # 稳定名称
    required_fields: list   # 依赖的数据列（如 'volume'）
    
    def filter(self, panel, t) -> list[str]: ...
    def to_config(self) -> dict: ...       # 序列化，保证可复现
```

研究员可通过继承 `UniverseFilter` 实现自定义过滤条件：

```python
class MyCustomSectorFilter(UniverseFilter):
    name = "custom_sector_exclusion"
    required_fields = ['sector']
    
    def __init__(self, exclude: list[str]):
        self.exclude = exclude
    
    def filter(self, panel, t):
        # 返回过滤后的品种列表
        ...
    
    def to_config(self) -> dict:
        return {'type': self.name, 'params': {'exclude': self.exclude}}
```

配置层按列表组合，顺序执行：

```python
# 仅用内置
universe_rules = [
    ListedDaysFilter(min_days=126),
    AvgVolumeFilter(window=20, min=10000),
]

# 内置 + 自定义
universe_rules = [
    ListedDaysFilter(min_days=126),
    MyCustomSectorFilter(exclude=['agriculture']),
]
```

**关键约束**：自定义条件必须是 `UniverseFilter` 的子类（有名字、有参数、有 `required_fields`、可序列化），不能是 lambda。因为 lambda 无法序列化进入配置，无法跨会话复现，无法自动获取依赖字段。

**抽象基类必须在 V1 就建立**：一旦 V1 的 `DatasetSpec` 和 `DatasetBuilder` 只能接受内置过滤器列表，V2 要改成接受抽象基类就是破坏性变更。在 V1 就定义协议，V2 只多写几个内置滤波器，接口是稳定的。

## 7. 架构不变量回顾

以下规则从 V1 起必须由测试保护（摘自架构设计文档第 434-446 行）：

- 因子值在时点 t 只能使用 t 及以前可见的数据
- 未来标签只能使用 t 之后的数据，且不得进入因子计算
- 因子和标签必须按 `timestamp, product` 精确对齐
- 所有滚动和滞后操作必须在品种内部执行
- 横截面处理必须在同一时间戳内部执行
- 输入面板不得被因子或评价器原地修改
- NaN 必须区分窗口不足、未来标签不足、原始缺失和过滤排除
- 单品种结果不得冒充横截面 IC
- 分组收益不得被称为账户收益或策略净收益
- 相同数据和配置必须产生相同结果
- 策略使用的因子定义与研究使用的因子定义必须可进行一致性验证

## 8. 关键设计决策总结

| 决策 | 结论 |
|------|------|
| 动态品种池是否进 V1 | **是**——至少存续性 + 基础可交易性过滤 |
| 品种池约束是否进实验配置 | **是**——不记录则无法解释结果差异 |
| 自定义过滤器是否用抽象基类 | **是**——不能用 lambda，必须可序列化 |
| 抽象基类是否在 V1 定义 | **是**——避免 V2 产生破坏性变更 |
| `universe.py` 的角色 | 提供常用过滤器 + 定义 `UniverseFilter` 抽象协议 |
| 可视化能力 | V1 表格和文本，V2 HTML 报告和图形（从 Alphalens 学习） |
| Tear Sheet 风格报告 | V2 规划（从 Alphalens 学习） |
| 多因子合成归属 | **因子模块**——`CompositeFactor` 内建于 factors/，策略层消费复合因子（2026-08-10 修订，取代原"组合属策略侧"定位） |
| V1 合成算子 | 等权、投票/排名、IC/ICIR 加权、Grinold 最优 IC、回归合成；可拟合算子仅训练窗口拟合，交易时权重冻结 |
| 复合因子评价 | **两步评价**——标准诊断 + 合成专属诊断（相关结构、权重稳定性、算子参数敏感性等） |

## 9. 增量计算接口

### 9.1 什么是增量计算

架构设计文档第 3.3 节提到"V2 才增加可选的增量计算接口。批量版是语义基准，增量版必须通过一致性测试。"

**批量计算**：每次调用传入完整历史，返回完整因子序列。

```python
factor_values = momentum.compute(entire_history_df)
# 输出：2018-01-02 ~ 2025-07-25 全部因子值
```

**增量计算**：初始化后，每来一个新 Bar 只传入最新一行，返回最新一个值。

```python
state = momentum.initialize(history_df)          # 初始化：跑一遍历史
new_value, new_state = momentum.update(today_bar, state)  # 更新：只算最新值
```

### 9.2 什么场景需要增量计算

| 模式 | 计算量 | 是否需全量数据 | 适用场景 |
|------|--------|:---:|------|
| 预计算 + 截取 | O(n) 一次 | 是 | **历史回测（标准做法）** |
| 受限窗口重复计算 | O(n²) 全程 | 否 | 回测懒人版 |
| 增量计算 | O(n) 全程 | 否 | **实时/盘中** |

### 9.3 回测中是否需要每步重算

**不需要。** 回测的标准做法是在回测前一次性批量计算全量因子值，回测引擎只需按时间切分序列，用 `[0:t]` 窗口保证无未来函数即可。不存在"每步重算"的必然性。

增量接口的真正意义在**实时/盘中场景**——例如基于 1 分钟 K 线刷新动量因子用于日内交易信号。对个人项目，这个场景在很长一段时间内都不会出现，架构文档提它是为了声明约定：批量版是语义基准，防止未来"优化"悄悄破坏语义。

## 10. 复合因子与注册查询

> **2026-08-10 修订**：本节写作时将复合因子定位为 V2。本次架构修订已将**单层复合因子（CompositeFactor）提升为 V1 一等公民**，由因子模块内建实现（架构 §6.7、§7.5；写作方案 Step 6）。注册查询与因子族层级仍归 V2。

### 10.1 复合因子（Compound Factor）

将多个基础因子按一定规则合成为一个新因子。V1 的合成是研究者手写在 notebook 里的临时组合，V2 的复合因子是正式的被管理系统实体。

```python
class CompositeMomentumCarry(FactorDefinition):
    """V2 将复合因子提升为一等公民"""
    name = "mom_carry_60_40"
    required_columns = ['Adj_Close', 'Near_Price', 'Far_Price']
    
    def __init__(self, mom_weight=0.6):
        self.mom = MomentumFactor(window=20)
        self.carry = RollYieldFactor()
        self.mom_weight = mom_weight
    
    def compute(self, df):
        return self.mom_weight * self.mom.compute(df).rank() \
             + (1 - self.mom_weight) * self.carry.compute(df).rank()
```

复合因子有自己的名称、参数可序列化、参与自动化诊断和参数扫描。

### 10.2 注册查询（Registry Query）

因子库有一个中央注册表，支持按条件检索因子：

```python
# 查询所有以 Adj_Close 为输入的因子
registry.query(required_columns=['Adj_Close'])

# 查询所有 carry 族的因子
registry.query(family='carry')

# 查询能化板块 Rank IC > 0.03 的候选因子
registry.query(sector='energy', min_rank_ic=0.03)
```

### 10.3 因子族与复合因子是因子库成长的必然产物

V1 中 `trend.py` 可能只有一两个因子。V2 时同一经济含义下自然分化出多个变体：

```
library/
    trend/
        time_series_momentum.py    # 不同回看期：5/10/20/60/120/250 天
        dual_momentum.py           # 绝对动量 + 相对动量
        moving_average_cross.py    # 均线交叉
        breakout.py                # 突破/通道
    carry/
        roll_yield.py              # 展期收益
        basis.py                   # 基差
        carry_spread.py            # 跨品种 Carry 价差
```

因子族解决"同类因子太多怎么组织"的问题，复合因子解决"不同族之间怎么系统化组合"的问题。两者都是因子库从 3 个长到 50 个以后才会暴露的痛点，所以归入 V2。（2026-08-10 修订：复合因子已提前至 V1，见本节开头注记；因子族与注册查询仍归 V2。）

## 11. V1 与 V2 预处理的完整案例

以下用一个完整的因子研究案例走通全部预处理步骤。

### 案例设定

**因子**：一个三信号复合动量因子，由三个子信号合成：
- `S1`：过去 20 日收益率（标准动量）
- `S2`：过去 5 日收益率（短期动量）
- `S3`：过去 60 日收益率（长期动量）

**品种池**：6 个商品期货 × 3 个板块

| 品种 | 板块 | 
|------|------|
| 螺纹钢 RB | 黑色 |
| 铁矿石 I | 黑色 |
| 焦炭 J | 黑色 |
| PTA | 能化 |
| 甲醇 MA | 能化 |
| 豆粕 M | 农产品 |

**观察时点**：2024-03-15（某一天），我们在这一天计算因子值并做预处理。

---

### 第一步：三信号原始因子值

某日 `compute(df)` 产出的三个子信号面板（已按 `timestamp, product` 对齐）：

```
品种       S1(20日动量)    S2(5日动量)    S3(60日动量)
─────────────────────────────────────────────────────
螺纹钢RB    3.5%          1.2%          12.8%
铁矿石I     2.8%          0.9%          9.5%
焦炭J       NaN          -0.3%          NaN
PTA         -1.5%        -2.1%         -4.2%
甲醇MA      0.3%         -0.8%          1.6%
豆粕M       -8.2%        -15.3%        6.5%
```

**问题**：焦炭的 S1 和 S3 是 NaN（可能是上市时间短，计算 60 日动量时历史窗口不足），豆粕 S2 异常低（-15.3%），整体波动率各品种差异大，且不同持有期的动量尺度不同。

---

### 第二步：V1 预处理

#### 2.1 缺失值处理（Missing Value Handling）

架构文档 V1 支持"基础缺失值处理"。

**策略**：截面中位数填充（仅对该时点该因子做截面中位数填充）

```
S1 截面值：[3.5, 2.8, NaN, -1.5, 0.3, -8.2]
非缺失品种中位数 = 0.3（甲醇MA的值，排序后取中间）

S3 截面值：[12.8, 9.5, NaN, -4.2, 1.6, 6.5]
非缺失品种中位数 = 6.5（豆粕M的值）
```

填充后：

```
品种       S1(20日)      S2(5日)      S3(60日)
─────────────────────────────────────────────────
螺纹钢RB    3.5%         1.2%         12.8%
铁矿石I     2.8%         0.9%         9.5%
焦炭J       0.3%(填)    -0.3%         6.5%(填)
PTA         -1.5%       -2.1%        -4.2%
甲醇MA      0.3%        -0.8%         1.6%
豆粕M       -8.2%       -15.3%        6.5%
```

标记：焦炭 `S1_source = "imputed"`, `S3_source = "imputed"`，进入结果元数据。

---

#### 2.2 截面缩尾（Cross-sectional Winsorization）

架构文档 V1 支持"截面缩尾"。

对每个子信号，在该截面上将超出 ±2σ 的值拉到边界。

**以 S2（5 日动量）为例**：

```
S2 截面值：1.2, 0.9, -0.3, -2.1, -0.8, -15.3
截面均值 = (1.2+0.9-0.3-2.1-0.8-15.3) / 6 = -2.73%
截面标准差 = 5.87%

上界 = -2.73 + 2 × 5.87 = 9.01%
下界 = -2.73 - 2 × 5.87 = -14.47%

豆粕 -15.3% < -14.47%  → 拉到 -14.47%
```

对 S1 和 S3 同样操作。缩尾后：

```
品种       S1(缩尾)     S2(缩尾)     S3(缩尾)
────────────────────────────────────────────────
螺纹钢RB    3.5%         1.2%         12.8%
铁矿石I     2.8%         0.9%         9.5%
焦炭J       0.3%        -0.3%         6.5%
PTA         -1.5%       -2.1%        -4.2%
甲醇MA      0.3%        -0.8%         1.6%
豆粕M       -7.1%(*)   -14.5%(*)(缩) 6.5%
```

(*) S1 豆粕 -8.2% 被缩尾到该截面下界；S2 豆粕 -15.3% 被缩尾。

---

#### 2.3 截面标准化（Cross-sectional Normalization）

架构文档 V1 支持"截面标准化"。

对每个子信号，在该截面上做 z-score 标准化（减均值，除标准差），使各子信号在截面上可比。

**S1 标准化**：

```
S1 截面值（缩尾后）：3.5, 2.8, 0.3, -1.5, 0.3, -7.1
截面均值 = -0.28%, 截面标准差 = 3.45%

z(螺纹钢) = (3.5 - (-0.28)) / 3.45 = 1.10
z(豆粕)    = (-7.1 - (-0.28)) / 3.45 = -1.98
...以此类推
```

**S2 标准化**、**S3 标准化**同理。最终 V1 预处理结果：

```
品种        V1_S1_z    V1_S2_z    V1_S3_z    V1_等权合成(=mean(z))
──────────────────────────────────────────────────────────────────
螺纹钢RB    1.10       0.85       1.42        1.12
铁矿石I     0.89       0.80       0.82        0.84
焦炭J       0.17       0.60      -0.05        0.24
PTA        -0.35      -0.32      -1.45       -0.71
甲醇MA     0.17      -0.05      -0.38       -0.09
豆粕M      -1.98      -1.88      -0.38       -1.41
```

V1 等权合成仅取三个 z-score 的均值。排序：螺纹钢 > 铁矿石 > 焦炭 > 甲醇 > PTA > 豆粕。

**V1 结果的局限性**：
- 是一个纯截面排名——没有考虑各品种自身历史的极端性
- 受板块效应影响——黑色系集体靠前是因为什么？板块共振还是个股动量强？
- 三个子信号的合成权重是等权，但它们的预测能力可能不同

---

### 第三步：V2 预处理（在 V1 基础上叠加）

#### 3.1 滚动时序标准化

V1 截面标准化之后，加一层滚动时序标准化，让每个品种的 z-score 再跟自己过去 252 个交易日的 z-score 分布比较。

**以螺纹钢 V1_S1_z = 1.10 为例**：

```
螺纹钢过去 252 天的 V1_S1_z 时序：
  均值 = 0.05（螺纹钢动量 z-score 整体偏高，平均每次截面排名略偏高）
  标准差 = 0.48

时序 z = (1.10 - 0.05) / 0.48 = 2.19
```

| 品种 | V1_S1_z | 时序均值(252d) | 时序标准差(252d) | V2_时序z |
|------|---------|---------------|-----------------|---------|
| 螺纹钢 | 1.10 | 0.05 | 0.48 | 2.19 |
| 铁矿石 | 0.89 | 0.08 | 0.55 | 1.47 |
| 焦炭 | 0.17 | -0.10 | 0.60 | 0.45 |
| PTA | -0.35 | -0.15 | 0.52 | -0.38 |
| 甲醇 | 0.17 | -0.05 | 0.45 | 0.49 |
| 豆粕 | -1.98 | -0.02 | 0.65 | -3.02 |

**解读**：螺纹钢的截面 z-score 从 1.10 提升到了 2.19，因为虽然截面上它只排第二（铁矿石 0.89），但相对于螺纹钢自身历史，1.10 的 z-score 是一个过去 252 天都罕见的极值。时序标准化捕捉到了"这个品种现在有多异常"的信息。

对三个子信号都做完滚动时序标准化后，等权合成：

```
品种         V2_时序合成
────────────────────────
螺纹钢RB     1.85
铁矿石I      1.32
焦炭J        0.12
PTA         -0.55
甲醇MA      -0.20
豆粕M       -2.61
```

#### 3.2 板块中性化（Sector Neutralization）

架构文档 V2 支持"行业/品种组中性化"。

在这个截面上做回归，剥离板块效应：

```python
# V2_时序合成 = β_黑色*D_黑色 + β_能化*D_能化 + β_农产品*D_农产品 + ε
# 取残差 ε 作为板块中性化后的因子值
```

当前截面的 V2_时序合成值：

```
黑色系：1.85(螺纹), 1.32(铁矿), 0.12(焦炭) → 板块均值 1.10
能化系：-0.55(PTA), -0.20(甲醇)           → 板块均值 -0.38
农产品：-2.61(豆粕)                        → 板块均值 -2.61
```

```
品种        V2_时序合成    板块均值    板块中性化(=值-板块均值)
────────────────────────────────────────────────────────────
螺纹钢RB     1.85         1.10         0.75
铁矿石I      1.32         1.10         0.22
焦炭J        0.12         1.10        -0.98
PTA         -0.55        -0.38        -0.17
甲醇MA      -0.20        -0.38         0.18
豆粕M       -2.61        -2.61         0.00
```

**核心变化**：中性化前螺纹钢是绝对第一（1.85），焦炭排中游（0.12）。中性化后焦炭变成了整个面板中**最低**的值（-0.98）——因为在黑色系内部它是最弱的，板块整体的动量强势掩盖了焦炭的相对弱势。

豆粕从 -2.61 变成了 0.00——因为农产品板块只有它一个品种，残差自动为零。这是单品种板块的中性化问题（V2 可通过别的方式处理，例如用更细的行业树或排除单品种板块）。

#### 3.3 可拟合变换 — IC 加权合成

V1 的等权合成假定三个子信号预测力相同。但实际 `S1_20日动量` 的历史 Rank IC 可能是 0.06，`S2_5日动量` 是 0.01，`S3_60日动量` 是 0.04。

**拟合阶段**（使用 2020-01-01 ~ 2023-12-31 训练窗口）：

| 子信号 | 历史 Rank IC 均值 | IC 稳定性(ICIR) | 归一化权重 |
|--------|------------------|----------------|-----------|
| S1_20日 | 0.060 | 0.72 | 0.60 |
| S2_5日 | 0.012 | 0.15 | 0.05 |
| S3_60日 | 0.048 | 0.55 | 0.35 |

权重 = softmax(IC 均值 × IC 稳定性)，且只在训练窗口上估计。

**变换阶段**（应用于当前 2024-03-15）：

中性化后的三个子信号值为（为简洁，省略逐子信号中性化的计算，取等权合成后再拆分的近似）：

```

────────────────────────────────────────────────────────────────────────────────
螺纹钢RB    0.80         0.10         0.95         0.83
铁矿石I     0.30        -0.05         0.40         0.32
焦炭J       -0.90       -0.20        -1.10        -0.94
PTA         -0.15       -0.40        -0.10        -0.15
甲醇MA      0.15         0.08         0.20         0.16
豆粕M       0.05        -0.10        -0.20        -0.04
```

对比等权合成 vs IC 加权合成：

| 品种 | V1等权 | V2 IC加权 | 变化原因 |
|------|--------|----------|---------|
| 螺纹钢 | 1.12 | 0.83 | S2 权重从 33% 降到 5%，螺纹钢 S2 本来也不突出，影响不大 |
| 焦炭 | 0.24 | -0.94 | S1 焦炭用了填充值（不稳定），IC 加权给了 S1 更高权重，加剧了焦炭的弱势信号 |
| 豆粕 | -1.41 | -0.04 | 板块中性化 + IC 加权后，豆粕不再被极端 S2 值拖累 |

```
    │
    ├── V1: 缺失值处理 ─────────────────── 焦炭 NaN → 截面中位数填充
    │       ↓
```

## 12. 预处理的必要性：IC 不依赖，多因子合成依赖

### 12.1 IC 计算几乎不依赖预处理

- **Rank IC（Spearman）**：完全免疫于任何单调变换。只要品种排序不变，Rank IC 一样。
- **Pearson IC**：对 scale 免疫（标准化不改变），但对 outlier 敏感（缩尾会改变 IC）。

```python
# 原始值 vs 标准化值，Pearson IC 相同（线性变换不改变相关系数）
原始因子值:    [3.5, 2.8, 0.3, -1.5, 0.3, -8.2]
标准化z值:    [1.10, 0.89, 0.17, -0.35, 0.17, -1.98]
```

### 12.2 分组收益对 outlier 敏感

分组收益（Top-Bottom 多空收益）会被极少数极端样本点主导：
- 不做缩尾：分组被 outlier 操纵，多空收益曲线出现剧烈毛刺
- 做了缩尾：分组更稳定，曲线更平滑，反映的是因子的常规区分能力

### 12.3 多因子合成才是预处理的真正受益者

| 预处理步骤 | 对 IC | 对多因子合成 | 不做会怎样 |
|-----------|:---:|:---:|------|
| 缺失值处理 | 部分必要 | 必要 | IC 计算报错或偏误 |
| 截面缩尾 | 否（Rank IC 免疫） | **必要** | 分组被 outlier 主导，合成不稳定 |
| 截面标准化 | 否 | **关键** | 量级大的因子完全主导合成，等权失去意义 |
| 滚动时序处理 | 否 | 必要 | 所有品种用同一阈值，信号质量下降 |
| 板块中性化 | 否 | **关键** | 策略变成板块押注而非选品种，分散化失败 |
| IC 加权合成 | 否 | 必要 | 噪音因子和有效因子等权，信号被稀释 |

**核心逻辑**：预处理不是为了算 IC 好看——IC 本来就不依赖预处理。预处理是为了保证从因子研究到多因子策略的无缝转化：你在研究阶段评价的因子信号，和策略阶段实际用来交易的信号，是同一个东西。

## 13. 预处理步骤的完整性评估

### 13.1 文档现有 V1+V2 覆盖率判断

文档的 V1+V2 覆盖了约 **85%** 的量化工业界标准预处理步骤。

### 13.2 明确缺失的步骤

#### 因子间正交化（Cross-factor Orthogonalization）

文档的"中性化"是对**外部变量**（板块、波动率等）做残差化。正交化是因子**之间**的：

```python
# 中性化：因子值对板块虚拟变量做回归，取残差
# 正交化：因子 B 对因子 A 做回归，取残差
carry_orthogonal = carry - regress(carry, momentum)
```

**意义**：IC 加权合成只解决了权重问题，但如果两个因子各带 40% 重叠信息，合成的信息量显著低于两个独立因子。`redundancy.py` 诊断了这种重叠，但文档中没有对应的**预处理步骤**来消除它。

#### 秩归一化（Rank / Quantile Normalization）

文档只有 z-score 标准化。大量实务框架（WorldQuant 风格）使用截面排名归一化：按排名映射到标准正态分位数，强制因子在每个截面上服从 N(0,1)，完全消除厚尾。

```python
# z-score：对 outlier 敏感（不改变分布形状，只平移+缩放）
# rank norm: rank → 映射到正态分位数 → 强制正态分布
z_normal = norm.ppf((rank - 0.5) / N)
```

**场景**：如果因子值分布是双峰或严重偏态的，z-score 标准化后仍是双峰的。秩归一化强制塑造分布。

#### 中性化目标不完整

文档提到的中性化目标只有"行业/品种组"。实践中还常见：

| 中性化目标 | 意义 |
|-----------|------|
| 波动率 | 剥离"高波动品种因子值天然偏大"的偏差 |
| 成交量/流动性 | 剥离"高流动性品种信号更稳定"的影响 |
| 市值/持仓量 | 剥离规模效应（大品种系统性偏差） |
| 展期收益率 | 在两个动量因子中同时剥离共同展期信号 |

这些都可通过回归残差化统一实现，文档提到了该能力但未将其作为可配置的独立中性化目标列出。

#### 平滑 / 降噪（Smoothing）

部分实务框架对预处理后的因子值做短窗口移动平均（如 3 日 MA），降低逐日噪声，减少换手率。不是因子计算的一部分（因子定义不变），而是在预处理链末端额外插入的一步。

### 13.3 缺失项的实现路径

以上四个缺失项都可在 V2 的"可拟合变换"或"回归残差化"框架下自然实现——本质都是"在给定历史数据上估计某种参数化映射，再应用到未来数据上"的变换，无需新增架构模块。

## 14. 预处理对评价指标的影响：两个论断的辨析

> 本节源于 Step 4（预处理系统）开发前关于"预处理在整个系统中生态位"的讨论。起点是两个直觉论断（facts），本节给出辨析与修正。

### 14.1 两个论断

- **论断一**：因子的预处理步骤（除填充空值和缩尾外）基本不影响 IC、Rank IC、分组多空收益的计算。推论：大多数预处理步骤不影响研究者对"因子本身是否具有预测信息"的判断。
- **论断二**：因子的近乎所有预处理步骤都对特定的多因子合成框架（策略使用方式）有影响。例：线性合成 → 截面标准化必不可少；排名/打分合成 → 截面标准化可以省略。

### 14.2 论断一辨析：部分错误，关键是区分两类预处理

论断一把两类性质不同的预处理混在了一起：

| 类别 | 别名 | 包含步骤 | 对截面排名 |
|---|---|---|---|
| Type A：截面单调变换 | "格式化" | 截面 z-score、秩归一化、分位数归一化、缩尾 | 不变 |
| Type B：信号改性变换 | "改假设" | 中性化、滚动时序标准化、平滑、残差化 | 改变 |

三点修正：

1. **缩尾不改变 Rank IC 与分组**。缩尾保持截面排序（边界并列除外），因此不改变 Rank IC、分组构成与等权分组多空收益；它只改变对极端值敏感的 Pearson IC。论断一把缩尾列为"影响评价"的例外，实际它只影响 Pearson 口径。
2. **Type B 改变一切 IC 口径**。中性化改变排名（§11 案例：焦炭板块中性化后从第 3 跌至第 6）；滚动时序标准化把"截面相对强弱"改写为"自身历史异常度"（螺纹钢 z 从 1.10 → 2.19）；平滑改变信号时序。这些步骤改变 IC、Rank IC 与分组结果——这正是它们存在的目的。
3. 对 §12.2 的精确化："分组收益被 outlier 主导"更准确地说是被**标签（未来收益）的极端值**主导；缩尾因子值不改变等权分组成员资格。只有在因子值加权组合或 Pearson 类统计下，因子极端值才直接影响结果。

因此论断一的推论只对 Type A 成立：Type A 不影响"因子是否含预测信息"的判断，是为下游合成服务的格式转换；**Type B 本身就是研究假设的修改**——评价中性化后的因子，是在回答"剥离板块/波动率暴露后还剩 alpha 吗"这样的新问题。

### 14.3 论断二辨析：基本正确，两点补充

1. **"使用方式"比"合成框架"更宽**。决定预处理需求的还有：仓位映射方式（因子值加权 → 对量纲敏感；分档等权 → 不敏感）、风险约束在哪一层处理（组合层已有板块中性约束 → 因子级中性化可能冗余甚至有害）、换手预算（决定是否需要平滑）。
2. **依赖是双向的**。使用方式决定预处理需求；反过来，评价证据也会要求修改使用方式——例如归因发现因子 IC 全部来自板块暴露，要么加中性化，要么策略层坦然接受"这是板块押注而非选品种"的定性。

## 15. 因子实验中是否需要完整的预处理流水线

**问题**：在一次因子研究实验中，是否有必要执行完整的预处理流水线（缺失值填充、缩尾、截面+滚动时序标准化、中性化）？

**结论：不需要机械地跑完整流水线。预处理是"分层的研究操作"，每一层对应一个研究问题：**

| 层 | 操作 | 回答的研究问题 |
|---|---|---|
| L0 | 原始因子（+最小无效值处理） | 这个变量含有预测信息吗？（基线证据） |
| L1 | 缩尾 | Pearson 口径下结论是否被极端值驱动？（稳健性） |
| L2 | 中性化 | 剥离板块/波动率/流动性暴露后还有 alpha 吗？（新假设） |
| L3 | 时序标准化/平滑 | 信号改性后预测力上升还是下降？换手降到可接受了吗？（新假设） |
| L4 | 截面标准化/秩归一化 | 不回答研究问题——为合成服务，使因子可与其他因子比较/相加 |

要点：

- 典型研究路径是**逐层递进、每层单独评价**，而非"raw 进去、全套出来、只看最终结果"。
- 框架支撑：写作方案 Step 10 要求 `ResearchResult` 同时保存原始因子值、处理后因子值和复合因子值——否则无法判断结论来自因子本身、预处理还是合成。
- **唯一需要跑完整流水线的时机**是交付前的最后验证：用与策略实际使用方式一致的预处理链，确认"策略将要交易的信号"仍保有评价证据（呼应 §12 的核心逻辑）。

## 16. 预处理步骤由谁决定：策略使用方式与模块归属

**问题**：策略研发的生命周期中，哪个环节决定因子所需的预处理步骤？"使用方式"属于本项目的哪个业务模块？

**答案：三层分离。**

1. **决定权在策略的使用方式**——阈值、信号规则、仓位映射、风险约束属于 `strategy/`（架构 §7.9；依赖方向保持 `strategy → factors`）。注意 2026-08-10 架构修订后，合成算子本身内建于因子模块（架构 §7.5 的 `CompositeFactor`），但"用哪种合成、配什么预处理"的需求仍由策略的消费方式驱动。
2. **代码实现留在 `factors/preprocessing.py`**：
   - 预处理涉及严格时间语义（只用当期截面、只用过去数据、训练窗口拟合），属于研究基础设施级的正确性要求，必须由因子模块拥有并用因果性测试保护；
   - 研究流水线要评价处理后的因子，预处理必须可从研究侧调用；
   - 策略在交易时必须复用同一份实现，否则"研究=交易"的一致性立即破裂。
3. **配置进入 `ExperimentConfig`**——预处理顺序和参数显式化、可复现。

**缺口已关闭（2026-08-10 修订）**：本节初稿指出 `CandidateFactor` 未显式包含预处理链、交付配方靠研究者纪律维持。本次架构修订已将完整配方纳入交付契约——`CandidateFactor`（写作方案 Step 11）现保存：因子定义（`Factor | CompositeFactor`）、成分及参数、各成分预处理链、合成算子及参数、成分缺失政策、拟合来源。原 §21.4 的策略侧 `FactorComposition` 草图随之被因子模块内的 `CompositeFactor` 取代。

## 17. 预处理、评价、交付与合成的关系

**问题**：因子预处理、因子评价、因子交付、因子合成（策略使用方法）之间是什么关系？

**一句话概括：预处理定义"被评价的对象"，评价生产"证据"，交付打包"配方+证据"，策略按交付契约消费信号并映射仓位。**

> 2026-08-10 修订：本节初稿写作时，合成定位于策略侧；本次架构修订已将合成（`CompositeFactor`）内建于因子模块，以下流程与关系按新架构更新。

```text
因子计算        产出原始变量（raw signal）
   ↓
预处理          分层加工：Type A 格式化（为合成服务）
   ↓                       Type B 改性（定义新的研究假设）
合成            因子模块内按显式算子组合为 CompositeFactor
   ↓            （可拟合算子仅在训练窗口用训练标签拟合）
评价            在每一层上独立产出证据：
   ↓            L0 基线预测力 → L1 稳健性 → L2/L3 改性后的预测力
   ↓            复合因子走两步评价：标准诊断 + 合成诊断
交付            CandidateFactor = 因子或复合因子定义 + 完整配方
   ↓            （预处理链、合成算子、拟合来源）+ 证据引用
   ↓            ——研究者显式决策，框架不自动批准
策略            消费交付的因子值 → 阈值/信号规则 → 仓位映射 → TargetPosition
```

四组关系的精确含义：

1. **预处理 ↔ 评价：迭代回路**，不是先后关系。归因发现板块集中 → 加中性化 → 重新评价；换手过高 → 加平滑 → 重新评价衰减。每次预处理修改都产生一个新的被评价对象。
2. **评价 → 交付**：评价证据（含复合因子的两步证据）是研究者做交付决策的输入；交付的不是因子值，而是"可复现的定义 + 完整配方 + 证据"。
3. **交付 → 策略**：策略必须消费与评价一致的加工后信号；交付契约（含完整配方）是研究与交易之间的一致性桥梁。
4. **评价 × 策略的边界**：两步评价覆盖单因子与复合因子的预测证据，但不覆盖仓位映射之后的组合表现（净收益、成本、约束满足）——那是 `backtester` 的职责。架构刻意保持的分工不变：因子诊断不得调用事件回测算 IC；候选因子 ≠ 可交易收益。

**第一原则**：整条链只为一个目的——让"研究里评价的那个东西"和"策略实盘中交易的那个东西"是同一个东西。修订后预处理与合成都在因子模块内部，策略只消费交付物并映射仓位——研究与交易之间只剩一座桥、一份契约。

## 18. 日内/高频策略中的因子研究

### 18.1 多因子模型在日内/高频策略中的地位

**是的，多因子模型在日内/高频策略中占有一席之地，而且占比很大。** 但因子类型从"经济逻辑驱动"变成了"市场微观结构驱动"。

| | 日频因子 | 日内/高频因子 |
|---|---|---|
| 典型因子 | 动量、展期收益、波动率、期限结构 | 订单流失衡(OBI)、买卖价差模式、成交量冲击、订单簿深度斜率、报价修订率、到达率 |
| 信息来源 | 价格趋势、供需基本面 | 交易者行为、流动性分布、信息不对称 |
| 预测期限 | 1-20 天 | 几秒到几小时 |
| 典型从业者 | CTA、宏观对冲 | 高频做市商(HFT market makers)、统计套利、日内量化CTA |

高频做市商可能同时挂载几十个因子，实时评估当前的库存风险成本、逆向选择概率和最优报价偏移量——这就是一套多因子决策系统。统计套利使用多品种残差因子 + 订单流信号合成入场信号。日内动量策略则用不同频率的价格因子（5分钟动量 + 1小时动量 + 开盘区间突破）合成仓位。

所以**因子研究的核心理念（定义信号 → 评价预测力 → 合成多因子）在日内/高频场景下依然成立**，但具体实现发生了根本性变化。

---

### 18.2 数据结构

| | 日频 | 日内/高频 |
|---|---|---|
| 单位 | 每日一根 K 线 | Tick / 秒级 / 分钟级 Bar |
| 数据量 | 1品种×5年 ≈ 1200 行 | 1品种×1天 ≈ 34500 秒（Tick级更高） |
| 内存模型 | pandas DataFrame 完全可容纳 | 需要 Parquet/Feather 分块，甚至逐品种逐日延迟加载 |
| 复杂度 | 单表长面板 | 多层数据：Tick 级成交 + L2 订单簿快照 + Bar 聚合，时间对齐远比日频复杂 |

当前架构设计的 `ResearchDataset`（MultiIndex[timestamp, product] 长表面板）的物理设计，在日内场景下需要重新考虑——5000个交易日 × 20品种 = 10万行，完全没问题；但 1天 × 34500秒 × 20品种 = 69万行，一周就是 345万行，pandas 内存模型会在千品种、多年的粒度上崩掉。

---

### 18.3 信噪比和样本量

| | 日频 | 日内 |
|---|---|---|
| 信号强度 | 相对高（日间收益变化大） | 极低（秒级收益几乎全是噪声） |
| 样本量 | 少（5年 ≈ 1200点） | 极多（1天就有34500个秒级截面） |
| 过拟合风险 | 中等 | **极高**——样本量巨大但信号微弱，极容易发现虚假模式 |
| 多重检验压力 | 几十个参数组合 | **几千甚至百万**个时间窗口+参数组合 |

日频因子研究的 IC 可能是 0.04-0.06，p 值在 0.01 水平上显著。日内因子的 IC 可能是 0.002-0.005，但因为有上百万个观测值，t 统计量反而巨大——如果不用严格的多重检验和样本外验证，极其容易过拟合。

---

### 18.4 因子类型

日频的因子是"从经济直觉出发的"，日内不是。日内因子的典型分类：

| 因子族 | 例子 | 含义 |
|--------|------|------|
| 订单流 | 主动买/主动卖量比 | 谁在主动交易？方向性压力 |
| 订单簿形态 | 买一/卖一挂单量比、订单簿斜率 | 当前流动性分布 |
| 微观波动率 | 已实现波动率、波动率跳跃 | 噪声水平 |
| 成交量冲击 | 异常大单出现后的价格漂移 | 信息冲击的不完全消化 |
| 周期性 | 开盘/收盘效应、午盘流动性效应 | 日内固定规律 |
| 跨品种微观 | 两品种订单流领先滞后关系 | 统计套利 |

这和已规划的 `trend/`, `carry/`, `volatility/` 因子库是两套完全不同的树。日内因子库可能是 `order_flow/`, `lob/`, `micro_vol/`, `periodicity/`, `cross_asset/`。

---

### 18.5 标签构造

| | 日频 | 日内 |
|---|---|---|
| 标签来源 | `True_Return` 逐日复合 | 未来 N 秒/Tick 的中间价变化 |
| 首要问题 | 换月跳空的 `True_Return` 端点语义 | **买卖价弹跳(bid-ask bounce)** 对收益的污染 |
| 标签类型 | 收益率为主 | 收益率、方向、波动率调整后收益、成交量加权价格变化 |
| 标签期限 | 1/5/10/20 天 | 5秒/30秒/1分钟/5分钟/30分钟 |

一个核心陷阱：如果你用最后一笔成交价算秒级收益，买卖价弹跳会制造出虚假的负自相关（成交在买价和卖价之间交替跳动，产生纯人造的"反转"信号）。日内标签必须用**中间价(mid-price)**或**成交量加权价格(VWAP)**构造，否则你测出来的"反转因子"IC 全是假象。

---

### 18.6 交易成本建模

这是日频和日内最大的差异点。

| | 日频 | 日内 |
|---|---|---|
| 成本重要性 | 重要但非核心（1-2个滑点，死不了） | **核心**——信号 α 可能只有 2-5bp，成本轻松吃掉 |
| 成本类型 | 手续费 + 1-2 tick 滑点 | 手续费 + 买卖价差 + 冲击成本 + 排队等待成本 |
| 回测中成本建模 | "减掉固定费率"就够了 | 需要模拟订单簿：限价单可能不成交、市价单吃掉价差、大单推价格 |
| 因子与成本的关系 | 弱耦合 | **强耦合**——一个 IC=0.005 的因子如果换手率是日频的 1000 倍，成本后净 IC = -0.01 |

**日频因子研究的思维模式**：因子 IC 好 → 可交易 → 交给策略层。

**日内因子研究的思维模式**：因子 IC 好 → **但这 IC 是在什么交易成本假设下算的？** → 在真实成本（含价差、冲击、不成交）下还有剩吗？→ 如果没有，你发现的是市场微观结构噪声而非超额收益。

---

### 18.7 评价方法差异

| | 日频 | 日内 |
|---|---|---|
| 截面 IC 模式 | 同一时间戳上跨品种 | 同一秒/Tick 上跨品种（但品种交易时刻不完全同步） |
| 时间对齐 | 日频天然对齐 | **多品种 Tick 时间戳不同，需要做前向填充/对齐** |
| 分组收益 | 简单等权 | 需加入成交量权重（流动性权）——买入量小的品种分组收益在实操中无法实现 |
| 衰减 | 按天 | 按秒/分钟（衰减极快，因子半衰期可能是几十秒） |
| 容量分析 | V2 才考虑 | **V1 就必须考虑**——有些信号只能在 5 手量级上有效 |

---

### 18.8 因子合成与策略交付

日频多因子合成后是一个静态截面排名 → 目标仓位 → 持有至下一个交易日。日内合成产出的不是一个仓位向量，而是一个**随时间连续变化的最优仓位目标**，策略层需要处理：

- 限价单算法（TWAP/VWAP/POV/Implementation Shortfall）
- 部分成交后的仓位漂移
- 跨品种保证金约束下的实时再平衡

这不是因子模块的职责（架构文档已明确），但在日内场景下，因子模块和策略层的接口契约必须比日频更紧密——因子值的更新频率、延迟容忍度、是否需要因子值附带置信度（如订单簿稀疏时信号质量标注）都会影响策略。

---

### 18.9 总结对比表

| 维度 | 日频因子研究 | 日内/高频因子研究 |
|------|------------|-----------------|
| 因子类型 | 经济逻辑驱动 | 微观结构驱动 |
| 因子库结构 | `trend/carry/volatility/...` | `order_flow/lob/micro_vol/periodicity/...` |
| 数据量 | MB 级 | GB-TB 级 |
| 数据处理 | pandas 单机 | 分块/惰性加载/可能的分布式 |
| 信噪比 | 中等 | 极低 |
| 过拟合风险 | 中等 | 极高 |
| 标签构造 | 日频 True_Return | 中间价/VWAP 的秒级变化，需处理买卖价弹跳 |
| 交易成本 | 后处理减常数 | **内嵌于因子评价**（信号 α 和成本的直接比较） |
| 容量分析 | V2 | **V1 必需** |
| 衰减周期 | 几天到几周 | 几秒到几十分钟 |
| 时间对齐 | 自然对齐 | 需显式处理异步 Tick 对齐 |
| 策略交付接口 | 日终目标仓位向量 | 随时间连续变化的目标 + 限价单算法参数 |

**核心结论**：因子研究的核心理念（定义、评价、合成、迭代）在两个频率上是相同的，但具体的工程实现、因子定义空间、评价方法和风险关注点完全不同。当前架构设计的这套 `factors/` 模块是为日频优化的，它不能直接套用到日内，但其架构思想（显式配置、结构化结果、标签与因子隔离、因果性测试）在日内场景下同样适用，只是需要一套独立的管道实现。

## 19. 标签类型详解

以下以**螺纹钢**某一天的因子值为例，逐一解释架构设计文档中列举的五类标签。

### 标签基础概念

标签是"正确答案"——给定一个因子在 t 时刻的信号，我们想知道它在未来赚了多少钱。标签永远只在因子之后的时间构造，绝不能进入因子计算。

螺纹钢在某日 t 的行情：

```
t-1 收盘：4000
t 收盘：4050
t+1 收盘：4080
t+2 收盘：4060
t+3 收盘：4120
t+4 收盘：4100
t+5 收盘：4150
```

---

### 19.1 多期限真实未来收益（V1）

架构文档定义的标签格式：

```
forward_return_h[t] = product(1 + True_Return[t+j], j=1..h) - 1
```

即以当前 t 价格为基准，未来 h 天的复合收益。

**例子**：

```
forward_return_1d[t] = True_Return[t+1]
                     = (4080 - 4050) / 4050 = 0.74%

forward_return_3d[t] = (1 + r_{t+1}) × (1 + r_{t+2}) × (1 + r_{t+3}) - 1
                     = (1 + 0.74%) × (1 + (4060-4080)/4080) × (1 + (4120-4060)/4060) - 1
                     = (1.0074) × (0.9951) × (1.0148) - 1
                     = 1.72%

forward_return_5d[t] = ... = 2.47%
forward_return_10d[t] = ...
forward_return_20d[t] = ...
```

这样在 t 这一刻，螺纹钢就有了一行标签：

```
品种       因子值     1d标签    3d标签    5d标签    10d标签   20d标签
─────────────────────────────────────────────────────────────────────
螺纹钢     +2.1σ      0.74%     1.72%     2.47%      ...       ...
```

"多期限"的意义：对同一个因子，同时用 1/3/5/10/20 天的标签各自算一遍 IC 和分组收益，这就是**衰减分析**——看因子预测力在多长时间尺度上有效。

---

### 19.2 方向标签（V2）

不关心"赚了多少"，只关心"赚还是亏"——把连续收益率转化为二分类问题。

**例子**：

```
forward_return_5d[t] = 2.47% > 0  →  方向标签 = +1（涨）
forward_return_5d[t] = 2.47%      →  真实收益标签 = 2.47%
```

整个面板做方向标签后：

```
品种       因子值      5d收益     5d方向标签    5d方向(加阈值)
──────────────────────────────────────────────────────────
螺纹钢     +2.1σ      2.47%        +1              +1
铁矿石     +1.8σ      0.12%        +1               0  ← 微小涨幅视为中性
焦炭       -0.5σ     -3.2%        -1              -1
PTA        +0.3σ     -0.15%       -1              -1
甲醇       -1.2σ     -1.8%        -1              -1
豆粕       +0.8σ      0.08%       +1               0  ← 微小涨幅视为中性
```

加了阈值（如 |r| > 0.5%）后，可以把小波动视为"无信号"（0），只有确实有意义的涨跌才标记。

**为什么需要方向标签**：

| 真实收益标签 | 方向标签 |
|-------------|---------|
| IC = Pearson(factor, return) 连续值回归 | 可算 accuracy、precision、recall、AUC |
| 被极端日（如豆粕 +15%）主导 | 对极端日免疫 |

方向标签让评价维度从"相关性"扩展到"分类质量"，在一些场景（如信号用于触发止损/止盈而非调仓）比 IC 更直接。

---

### 19.3 波动率调整标签（V2）

问题：同样赚了 2%，低波品种上是超常收益，高波品种上是随机波动。

**例子**：同一天，螺纹钢 5 日收益 2.47%，PTA 5 日收益 2.50%——几乎一样。但看看各自前 20 个交易日的波动：

```
螺纹钢 20日波动率 = 1.2%（低波动品种）
PTA    20日波动率 = 3.5%（高波动品种）
```

```
原始标签：
  螺纹钢 5日收益 = 2.47%
  PTA    5日收益 = 2.50%    ← 基本相同

波动率调整后标签：
  螺纹钢 5日收益 / 年化波动率 = 2.47% / (1.2% × √5) = 2.47% / 2.68% = 0.92
  PTA    5日收益 / 年化波动率 = 2.50% / (3.5% × √5) = 2.50% / 7.83% = 0.32
```

**解读**：螺纹钢的 2.47% 是接近 1 个标准差的大涨（不寻常），PTA 的 2.50% 只是 0.32 个标准差的日常波动。用波动率调整后标签计算 IC，等于在问"因子预测的是超额波动调整后收益，还是原始收益？"——前者不会被高波动品种的随机大振幅所污染。

**意义**：如果你构建的多因子策略会对每个品种的波动率做仓位归一化（universal target volatility sizing），那么波动率调整后的标签和你最终的策略目标才是匹配的。用原始收益标签评价的因子，可能在真实存在仓位归一化时不成立。

---

### 19.4 残差标签（V2）

把"大盘/板块涨了所以我跟着涨了"的部分剥离掉，只保留"独自的超额收益"作为标签。

**例子**：当天黑色系板块指数涨了 1.5%。螺纹钢涨了 2.47%——其中 1.5% 是板块贡献，0.97% 是它自有的超额表现。

```
残差标签 = 真实收益 - β × 板块收益

螺纹钢 5日真实收益 = 2.47%
黑色板块 5日收益 = 1.8%
螺纹钢 β(对板块) = 1.1

螺纹钢 残差标签 = 2.47% - 1.1 × 1.8% = 0.49%
```

对另外两个品种：

```
品种      5日收益     板块收益     β      残差标签
─────────────────────────────────────────────────────
螺纹钢    2.47%       1.8%       1.10    0.49%
铁矿石    1.50%       1.8%       0.95   -0.21%   ← 板块涨但个股跑输
焦炭      3.80%       1.8%       0.85    2.27%    ← 超额强
```

**为什么需要残差标签**：

用原始收益标签评价时的逻辑链是：

> "因子高 → 未来收益高 → 因子好"

用残差收益标签评价的逻辑链是：

> "因子高 → 跑赢自身的板块 β 预期 → 因子有**超越系统性风险暴露的**预测力"

如果因子的 IC 在原始收益标签上是 0.05，在残差标签上跌到 0.01，说明这个因子实质上只是在捕捉板块风险暴露，不是真正的 alpha。对多因子策略而言，这两个因子是完全不同的——前者可以通过做多板块 ETF 实现，后者才是你真正的选品种能力。

---

### 19.5 事件标签（V2）

不是基于收益率连续值，而是基于"特定事件发生后是否出现特定模式"。

**例子一：换月事件**

```
标签定义：
  事件 = 换月日（is_roll = True）
  标签 = 换月日后 3 天收益率 - 换月日前 3 天收益率
```

> 研究问题：换月前后是否存在异常的价格模式？动量因子在换月附近的信号是否失真？

对所有换月日构建完标签后，不是用"因子值"去预测标签，而是用"事件是否发生"去分析价格行为模式。

**例子二：库存报告发布**

```
标签定义：
  事件 = 库存数据发布日
  标签 = 发布日后 1 天的收益率

研究问题：同样的动量因子信号，在库存报告发布日 vs 非发布日，预测效果是否不同？
```

这和第 2 章"分市场状态归因"不同——归因是在已有连续标签上按事件划分子集分别统计 IC，事件标签本身就是事件专属的标签定义。

**例子三：极端事件**

```
标签定义：
  事件 = 单日涨幅 > 3σ（极端上涨日）
  标签 = 极端上涨日后 1/3/5 天的累计收益率是否均值回复

研究问题：极端上涨后是否自动反转？这个反转现象是否可被因子捕捉？
```

**事件标签和普通标签的区别**：

| | 普通标签 | 事件标签 |
|---|---|---|
| 标签定义 | 对每个 t 计算未来 h 天收益 | 只在事件发生时定义，非事件日无标签 |
| 样本分布 | 全时段均匀分布 | 稀疏分布（事件日只占总交易日的 5-10%） |
| 用途 | 评价"这个因子能不能持续预测收益" | 评价"这个因子在特定事件中的行为模式" |
| 典型分析 | IC 时序、分组收益衰减 | 事件窗口前后平均累计收益曲线 |

---

### 19.6 标签类型总结

| 标签类型 | V1/V2 | 核心问题 | 不受什么干扰 |
|----------|:---:|------|------|
| 多期限真实收益 | V1 | 因子未来能赚多少？ | —（基础） |
| 方向标签 | V2 | 因子判断涨跌的准确率？ | 被极端收益主导 |
| 波动率调整标签 | V2 | 因子预测的是异常收益还是普通波动？ | 被高波动品种的大振幅污染 |
| 残差标签 | V2 | 因子有超越板块风险暴露的 alpha 吗？ | 被板块/系统的 β 收益污染 |
| 事件标签 | V2 | 因子在特定事件中有什么行为模式？ | 全时段平均掩盖了事件特异性 |

**核心结论**：从 V1 到 V2，标签的设计从"笼统地问能不能预测收益"逐步细化到"剥离各种非 alpha 成分后还能不能预测"，最终指向的是策略层的真实净值来源——不是你赚了多少，而是你赚的钱里哪些是 beta（廉价、可复制）、哪些是 alpha（你的核心能力）。

---

## 20. 实验能力：从 V1 到 V2

以下围绕一个具体场景展开：研究员对"20日动量因子"做一次完整实验。

---

### 20.1 显式配置（Explicit Configuration）

**含义**：实验的所有条件不再是散落在 notebook 各处的变量，而是一个结构化对象。

**反面教材——配置散落各处**：

```python
# notebook 第 1 个 cell
products = ['RB', 'I', 'J', 'TA', 'MA', 'M']
start = '2018-01-01'
end = '2023-12-31'

# notebook 第 5 个 cell
factor_params = {'window': 20}

# notebook 第 12 个 cell
label_horizons = [1, 5, 10, 20]

# notebook 第 18 个 cell
winsorize_pct = 0.02

# ... 三个月后你完全不记得改了哪个 cell 重新跑出来的 IC 是 0.045 而不是 0.038
```

**V1 设计**：

```python
config = ExperimentConfig(
    dataset=DatasetSpec(
        start_date='2018-01-01',
        end_date='2023-12-31',
        freq='D',
        view='scheduled',
        universe_rules=[
            ListedDaysFilter(min_days=126),
            AvgVolumeFilter(window=20, min=10000),
        ]
    ),
    factor=FactorConfig(
        name='momentum_20d',
        params={'window': 20},
        type='time_series'
    ),
    preprocessing=PreprocessingConfig(
        winsorize={'method': 'cross_sectional', 'sigma': 2.0},
        normalize='z_score'
    ),
    labels=LabelConfig(
        horizons=[1, 5, 10, 20],
        source='True_Return'
    ),
    evaluation=EvaluationConfig(
        mode='cross_sectional',
        n_groups=5,
        min_samples_per_group=3
    )
)

result = ExperimentRunner().run(config)
```

**价值**：当你三个月后想问"上次 IC=0.045 的那次实验用的什么参数"时，只要看这一个配置对象，不需要翻阅 350 行 notebook 代码。

---

### 20.2 结构化结果（Structured Results）

**含义**：实验结果不只是一张 IC 均值数字或一张图，而是一个层次化的数据对象，可以程序化访问。

**反面教材**：

```python
# V0 风格：打印几行，画几张图，靠人眼判断
print(f"Mean IC: {ic.mean():.4f}")
print(f"ICIR: {ic.mean()/ic.std():.4f}")
plt.plot(ic.cumsum())
plt.show()
# 图很好看，但下次你想"找出 2020 年 3 月 IC 最低的那天"——
# 只能对着图数格子，无法程序化提取
```

**V1 设计**：

```python
result = ExperimentRunner().run(config)

# 结构化访问任何子结果
result.ic.summary
# → {'mean': 0.045, 'std': 0.12, 'icir': 0.38, 'pct_positive': 0.62, 'n_samples': 1200}

result.ic.detail                       # 每日 IC DataFrame
# → timestamp  |  1d_IC  |  5d_IC  |  10d_IC  |  20d_IC
#    2020-03-15|  0.023  |  0.041  |  0.068   |  0.055
#    2020-03-16| -0.012  |  0.003  |  0.019   |  0.027
#    ...

result.grouped_returns.detail          # 分组收益 DataFrame
result.coverage.detail                 # 覆盖率 DataFrame
result.turnover.detail                 # 换手率 DataFrame
result.decay_table                     # 衰减表
result.warnings                        # 所有警告列表

# 程序化提取
worst_ic_day = result.ic.detail['5d_IC'].idxmin()
print(f"5日IC最低的交易日：{worst_ic_day}，IC={result.ic.detail.loc[worst_ic_day, '5d_IC']:.4f}")
```

**价值**：结构化结果让你能**编写代码二次分析结果**，而不是每次都要重新跑一遍实验。今天算出来的分组收益表，明天可以批量对比 10 个因子版本的衰减曲线，全自动。

---

### 20.3 CSV / JSON 导出（V1）

**含义**：结构化结果可以持久化为可交换的文件格式。

**V1 设计**：

```python
result.export_csv('output/momentum_20d/')
# → output/momentum_20d/
#     ic_detail.csv
#     ic_summary.json
#     grouped_returns.csv
#     coverage.csv

#     config.json

```

**场景**：
- 研究员 A 跑完实验，导出 CSV 发给研究员 B——B 不需要重新跑一次看结果
- 把 `ic_summary.json` 扔进你的前端页面或 Grafana Dashboard
- Excel 打开 `grouped_returns.csv` 做可视化（不是每个人都用 Python）

---

### 20.4 指纹（Fingerprint，V2）

**含义**：对实验的核心输入生成唯一哈希，作为实验的"DNA"。

**V2 设计**：

```python
# 指纹 = hash(配置 + 数据版本 + 代码版本)
fingerprint = ExperimentFingerprinter.compute(config, dataset)
# → "e8f3a9b2c1d4e5f6"

result = ExperimentRunner().run(config, dataset)
result.fingerprint = fingerprint
result.data_fingerprint = dataset.compute_hash()
result.code_version = git_commit_hash()
result.config_hash = config.compute_hash()
```

**实际意义**：

```
场景：你做了三次实验，都叫 momentum_20d：

第1次：IC=0.045，配置 window=20, winsorize=2σ, universe=22品种
       指纹：a1b2c3d4

第2次：IC=0.052，你觉得"变好了"——但你忘了是不是改了 window 到 40
       指纹：b5c6d7e8  ← 配置哈希和第1次不同！说明参数变了

第3次：IC=0.045，你觉得"回到最初了"——但你怎么确定真的完全一样？
       指纹：a1b2c3d4  ← 和第1次指纹相同，确认为同一实验
```

更进一步——**数据指纹**能回答一个更隐蔽的问题：

```
1月1日你跑了一次，IC=0.045
3月1日你又跑了一次，IC=0.041

是因子参数变了？代码改了？还是数据源更新了（历史数据修正）？
→ 查看 data_fingerprint 差异，发现是数据源在2月做了一次价格修正
→ 你的"衰退"不是因子的问题，是数据变了
```

### 20.6 缓存（Caching，V2）

**含义**：相同输入下已经计算过的步骤不重复计算。

**V2 设计**：


**对批量/参数扫描的加速**：

```
对于个人项目，这不算决定性优势；但对于上百因子的批量扫描，差距显著。
```

### 21.1 一个因子的一致性证明（V1）

**问题**：同一个因子定义，在两种不同的调用模式下，得出的值必须一致。

| 调用模式 | 场景 | 输入形式 |
|----------|------|---------|
| 批量模式（研究环境） | `FactorEvaluator` 做因子诊断 | 全量历史 DataFrame |
| 事件模式（策略环境） | `BacktestEngine` 在回测中实时使用 | 受限历史窗口（只能看到 t 及以前） |

如果你在研究中得到"t 时刻因子值 = 1.23"，而策略回测中同一时刻的值是 1.18，那你研究的结论和策略的执行就不是同一个东西。

**实际例子**：

**研究环境（批量）**：

```python
# factors/ 模块中：一次性传入全部历史
full_df = load_full_history('RB', '2018-01-01', '2023-12-31')
momentum = MomentumFactor(window=20)
factor_values_batch = momentum.compute(full_df)

# 2023-06-15 这一天的因子值
print(factor_values_batch.loc['2023-06-15'])
# → 1.23
```

**策略环境（事件回测）**：引擎从 2018-01-01 开始逐日推进，到了 2023-06-15 这一天：

```python
# strategy/ 模块中：strategy adapter 把当天之前的历史行情
# 组装成因子要求的输入格式，调用同一个 momentum.compute()
restricted_df = build_restricted_view(full_df, up_to='2023-06-15')
factor_value_strategy = momentum.compute(restricted_df).iloc[-1]

print(factor_value_strategy)
# → 必须等于 1.23，否则一致性失败
```

**一致性测试**：

```python
# test_factor_consistency.py
def test_momentum_batch_vs_event_consistency():
    """黄金不变量：同一时间窗口下，批量研究和事件策略得到的因子值必须一致"""
    df = build_test_panel()  # 小规模人工面板
    
    # 批量模式：一次性全算
    batch_result = momentum.compute(df)
    
    # 事件模式：逐个时点推进，每个时点只用 ≤t 的数据
    event_results = []
    for t in df.index.get_level_values('timestamp').unique():
        restricted = df.loc[:t]
        val = momentum.compute(restricted).iloc[-1]
        event_results.append((t, val))
    
    # 对比最后一期的值
    assert batch_result.iloc[-1] == event_results[-1][1], \
        f"一致性失败: batch={batch_result.iloc[-1]}, event={event_results[-1][1]}"
```

**如果一致性失败，可能的原因**：

| 失败原因 | 具体场景 |
|----------|---------|
| 因子内部用了全样本归一化 | `z_score = (x - full_mean) / full_std` 而非 `(x - rolling_mean) / rolling_std` |
| 因子用了前视数据填充 | `df.fillna(method='bfill')` 在事件模式下根本不可用 |
| 滚动窗口对齐差异 | `df.rolling(20).mean()` 在受限窗口下首 19 个值是 NaN，批量模式则不是 |
| 索引排序差异 | 批量模式可能重新排序了索引，事件模式保留了逐日追加的顺序 |

**V1 只做一个因子的一次一致性测试（时间序列动量作为黄金样例）**，目的是**证明框架设计是对的**——只要因子遵循 `compute(df)` 的契约（只用 df 里提供的数据，不偷看全局），一致性就是自动保证的。如果这个样例通过了，其他因子只要遵守同样的契约就天然一致。

### 21.2 通用策略适配器（V2）

**问题**：V1 的一致性证明只针对一个特定因子写一段适配代码。V2 需要一个通用的、可复用的适配机制。

**为什么策略层的数据格式和研究层不同**：

```python
# 研究层因子输入（长表面板）：
# MultiIndex[timestamp, product], columns = ['Adj_Close', ...]
# 
# strategy/ 策略层收到的数据（事件回测风格）：
# BarMarketEvent 对象
event = BarMarketEvent(
    product='RB',
    timestamp=Timestamp('2023-06-15 15:00:00'),
    adj_close=4050.0,
    adj_open=4020.0,
    adj_high=4080.0,
    adj_low=4010.0,
    raw_close=4048.0,      # 研究层不需要
    volume=125000,
    open_interest=58000,
    # ... 还有很多其他字段
)
```

策略层根本不知道什么是 `ResearchDataset`，它看到的是一个一个的 `BarMarketEvent`。

**通用适配器的作用**：把一个策略内部的"事件流"映射为因子要求的 `compute(df)` 接口。

```python
class FactorAdapter:
    """将策略层的事件流转换为因子输入的通用适配器"""
    
    def __init__(self, factor: FactorDefinition, history_window: int):
        self.factor = factor
        self.history_window = history_window  # 保持多少个历史 Bar
        self._buffer = {}  # {product: DataFrame}
    
    def on_bar(self, event: BarMarketEvent) -> float | None:
        """每到一个新 Bar，追加历史，返回该品种当前时点的因子值"""
        product = event.product
        
        # 1. 从事件提取因子所需的字段
        row = {col: getattr(event, col.lower()) 
               for col in self.factor.required_columns}
        
        # 2. 追加到该品种的历史缓冲区
        if product not in self._buffer:
            self._buffer[product] = pd.DataFrame(columns=self.factor.required_columns)
        self._buffer[product].loc[event.timestamp] = row
        
        # 3. 裁剪到历史窗口
        cutoff = event.timestamp - pd.Timedelta(days=self.history_window)
        self._buffer[product] = self._buffer[product].loc[cutoff:]
        
        # 4. 构造因子输入并计算
        if len(self._buffer[product]) >= self.factor.min_history:
            df_input = self._buffer[product].copy()
            df_input.index = pd.MultiIndex.from_product(
                [[event.timestamp], [product]],
                names=['timestamp', 'product']
            )
            # 调用研究层的同一个 compute()
            return self.factor.compute(df_input).iloc[-1]
        
        return None
```

**使用**：

```python
# strategy/models/ 中的策略类
class MomentumStrategy:
    def __init__(self):
        self.mom_adapter = FactorAdapter(
            factor=MomentumFactor(window=20),
            history_window=365
        )
        self.carry_adapter = FactorAdapter(
            factor=RollYieldFactor(),
            history_window=365
        )
    
    def on_bar(self, event: BarMarketEvent) -> TargetPosition:
        mom_signal = self.mom_adapter.on_bar(event)
        carry_signal = self.carry_adapter.on_bar(event)
        
        if mom_signal is None or carry_signal is None:
            return TargetPosition.zero()
        
        # 合成并生成仓位
        composite = 0.6 * mom_signal + 0.4 * carry_signal
        return TargetPosition(weight=composite)
```

**"通用"的含义**：无论是动量、展期收益还是未来任何新因子，只要它实现了 `FactorDefinition` 的 `compute(df)` 接口和声明了 `required_columns`，同一个 `FactorAdapter` 就能工作。不需要为每个因子类型单独写一套策略层适配代码。

### 21.3 增量因子接口（V2）

**问题**：上面 `FactorAdapter.on_bar()` 每触发一次就调用 `momentum.compute(df)`，而 `compute` 是批量接口——即便你只传入了 365 天的数据，它也会从头算一遍完整的 20 日滚动窗口。一天一次没问题，一分钟一次就是灾难。

**增量接口**：

```python
class IncrementalMomentumFactor:
    """增量版本：保存状态，每次只增量更新"""
    
    def initialize(self, history_df: pd.DataFrame) -> dict:
        """初始批量计算，返回批量结果 + 内部状态"""
        values = self._batch_compute(history_df)
        # 保存增量计算所需的中间状态
        state = {
            'price_window': deque(maxlen=self.window),  # 只保留最近 window 天的价格
            'last_value': values.iloc[-1]
        }
        # 用历史数据填充滚动窗口
        for p in history_df['Adj_Close'].iloc[-self.window:]:
            state['price_window'].append(p)
        return state
    
    def update(self, today_price: float, state: dict) -> tuple[float, dict]:
        """增量更新：传入最新价格 + 上一次的状态 → 返回新值 + 新状态"""
        state['price_window'].append(today_price)
        
        if len(state['price_window']) < self.window:
            return np.nan, state
        
        # O(1) 计算：只用到窗口内的价格
        new_value = (today_price - state['price_window'][0]) / state['price_window'][0]
        state['last_value'] = new_value
        return new_value, state
```

**策略中的使用**：

```python
class MomentumStrategy:
    def __init__(self):
        self.mom_factor = IncrementalMomentumFactor(window=20)
        self.mom_state = None  # 尚未初始化
    
    def on_start(self, historical_bars: list[BarMarketEvent]):
        """策略启动时用历史数据初始化增量状态"""
        history_df = events_to_df(historical_bars)
        self.mom_state = self.mom_factor.initialize(history_df)
    
    def on_bar(self, event: BarMarketEvent) -> TargetPosition:
        """每个新 Bar 只更新一步，不重算历史"""
        mom_signal, self.mom_state = self.mom_factor.update(
            today_price=event.adj_close,
            state=self.mom_state
        )
        # ... 后续逻辑
```

**增量接口的一致性测试**：

```python
def test_batch_vs_incremental_consistency():
```

### 21.4 多因子组合接口（V2）

> **2026-08-10 修订**：本节的策略侧 `FactorComposition` 草图已被取代——多因子合成内建于因子模块（`factors/combination.py` 的 `CompositeFactor`，见架构 §6.7/§7.5、写作方案 Step 6），策略层消费 `CandidateFactor` 交付的复合因子，不再自建组合模型。本节保留作为设计演化的对照记录。

**问题**：`CandidateFactor` 是单个因子的交付物（名称 + 参数 + 研究证据）。策略层要的不是一个因子，而是一个**多因子组合方案**。

**设计**：

```python
class FactorComposition:
    """策略层使用的多因子组合接口"""
    
    def __init__(self):
        self.factors: list[CandidateFactor] = []
        self.weights: list[float] = []        # 各因子权重
        self.preprocessing: PreprocessingPipeline = None  # 组合前的预处理
        self.neutralization: dict = {}         # 组合层面的中性化（如板块中性化）
    
    def add_factor(self, candidate: CandidateFactor, weight: float):
        self.factors.append(candidate)
        self.weights.append(weight)
    
    def compute_composite(self, panel: pd.DataFrame) -> pd.Series:
        """计算多因子合成值"""
        scores = []
        for factor, weight in zip(self.factors, self.weights):
            raw = factor.definition.compute(panel)      # 计算原始因子值
            processed = self.preprocessing.transform(raw)  # 预处理
            scores.append(weight * processed)
        
        composite = sum(scores)
        
        # 可选的组合层面中性化
        if self.neutralization.get('sector', False):
            composite = neutralize_by_sector(composite, panel['sector'])
        
        return composite
```

**策略中的使用**：

```python
# strategy/ 层

        # 从因子库拿候选因子（附带研究证据）

        ])
        self.composition.neutralization = {'sector': True}
    
    def generate_target_positions(self, today_panel: pd.DataFrame):
```

### 21.5 策略衔接能力总结：V1 vs V2

```
V1（一个因子的一致性证明）:
    研究层 MomentumFactor.compute(df)
    ↓ 同一代码
    策略层 adapter 调用 MomentumFactor.compute(restricted_df)
    ↓ 测试比对
    两个值相等 → 一致性通过

    意义：证明"因子定义一次，研究/策略都用同一份代码"的架构可行


V2（通用适配 + 增量 + 多因子组合）:
    
    通用适配器（FactorAdapter）:
        任意 Factor.compute(df)
        ← 策略事件自动映射为 df 输入
        不写重复适配代码
    
    增量接口（update）:
        Factor.compute(df)     → 批量基准（权威）
        Factor.update(bar, state) → 增量实现（性能优化）
        ← 一致性测试保证二者等价
    
    多因子组合（FactorComposition）:
        [CandidateFactor A, CandidateFactor B, ...] + weights
        → 组合层面的 compute_composite(panel)
        = 策略最终的截面信号
```

**一句话**：V1 证明"因子可以在研究和策略两个环境中共用同一份代码"，V2 让这个共用变得通用（不限于一个样例）、高效（增量计算）和可组合（多因子的策略层接口）。

## 22. 策略的任务分解：因子合成与目标仓位映射

**论断**：策略可以粗略地分为两个任务——1. 因子合成；2. 目标仓位映射。

**评价：基本正确**，与架构 §7.9 的切分一致：

```text
factor value -> signal rule -> position sizing -> TargetPosition
```

三个细化点：

1. **"因子合成"内部还藏着一步"信号规则"**。合成产出的是连续分数（composite score），分数变成可交易的方向/强度还需规则：阈值（score 超过阈值才行动）、缺失降级（某因子 NaN 时降权还是弃权）、方向统一（不同因子值方向约定不一致）。写作方案 Step 12 列的策略侧职责——"因子方向统一、阈值和信号生成；缺失降级政策；从因子值到目标仓位的映射"——前两项属于"信号规则"，末项是"映射"。（2026-08-10 修订：合成的权重/算子部分已内建于因子模块 `CompositeFactor`，策略侧只保留信号规则与仓位映射——两任务划分因此更精确：因子模块产出复合 score，策略负责 score → 信号 → 仓位。）
2. **"目标仓位映射"内部包含风险覆盖层（risk overlay）**：波动率目标（vol targeting）、敞口上限（单品种/板块/总杠杆）、保证金约束。它不改变"赌什么"，只改变"赌多大"，但决定策略的风险特征。
3. **执行不在两个任务之内**：订单生成、拆单、滑点属于 `executor/`，是策略模块之外的第三个任务。

两种模式下两个任务的语义不同：

| | 时序模式（CTA 主流） | 横截面模式 |
|---|---|---|
| 合成 | 每个品种内部跨因子加权 | 品种间打分排名 |
| 映射 | 单品种信号 → 单品种仓位 | 排名 → 品种间资金分配（多空） |

## 23. 业界主流的因子合成方法（benchmark）

**问题**：量化界作为 benchmark 的因子合成方法有哪些？

按复杂度排序：

### 23.1 等权合成（Equal Weight）—— 一切方法的基准

各因子标准化后等权平均。学术与业界的默认 benchmark，任何花哨方法必须跑赢它才有存在价值——计量经济学著名的 forecast combination puzzle（Clemen 1989；Stock & Watson）：由于权重估计误差，样本内"最优"权重在样本外经常输给等权。要求截面 z-score 或秩（否则量纲大的因子主导）。

### 23.2 IC / ICIR 加权 —— 业界最常用的"有脑"基准

`w_i ∝ mean(IC_i)` 或 `w_i ∝ ICIR_i`，用训练窗口的历史 IC 拟合权重，滚动/扩张窗口更新。券商金工研报的标准做法（§11.3.3 的案例即用此法）。缺点：IC 估计噪声大、权重不稳；**忽略因子间相关性**——两个高度相关的强因子会双倍计权。属于可拟合变换，须走 fit/transform 契约。

### 23.3 最优 IC 加权（Grinold 式均值-方差合成）—— 教科书最优解

`w* ∝ Σ⁻¹ · IC`，出自 Grinold & Kahn《Active Portfolio Management》：IC 向量是期望收益，因子协方差矩阵 Σ 度量冗余，合成目标是最大化复合信号 IR。**显式处理相关性**——冗余因子自动降权，是 §4"边际解释能力"思想在合成层的实现。缺点：协方差估计误差大，需收缩（Ledoit-Wolf）；样本外常输给 ICIR 加权甚至等权。定位为理论标杆。

### 23.4 回归合成（Fama-MacBeth / 截面回归）—— 计量标准

训练期每个截面做 `r(t+1) ~ F1(t) + ... + Fk(t)` 回归，系数的时间序列均值即权重。直接对准收益预测，多元回归天然处理相关性。缺点：系数不稳定、期货截面太小（几十个品种回归几个因子，自由度紧张）。时序 CTA 的对应物：逐品种时序回归或 panel 回归。

### 23.5 排名 / 投票合成 —— 最鲁棒的非参数方法

秩平均、方向投票（每因子投 +1/-1/0）、前后 n 名打分。时序 CTA 中投票法极常见。优点：极端值免疫、无需标准化、无参数估计误差、天然处理缺失（弃权）。缺点：丢失幅度信息（动量 0.5% 与 50% 同为一票）。

### 23.6 机器学习合成 —— 远期选项

ridge/lasso、LightGBM、神经网络，可捕捉因子交互与非线性。本项目现实约束：日频、几十个品种、几年样本——有效样本量小、多重检验压力大、过拟合风险极高。V1 阶段不需要。

### 23.7 总览与对预处理的要求

| 方法 | 地位 | 处理相关性 | 估计误差风险 | 对预处理的要求 |
|---|---|---|---|---|
| 等权 | 基准 | 否 | 无 | 标准化（可比量纲） |
| IC/ICIR 加权 | 业界标准 | 否 | 中 | 标准化 + 可拟合（训练期 IC） |
| Grinold 最优 IC | 理论最优 | 是 | 高 | 标准化 + 可拟合（协方差矩阵） |
| 回归合成 | 计量标准 | 是 | 高 | 标准化 + 可拟合（回归系数） |
| 排名/投票 | 鲁棒备选 | 否 | 无 | 仅需秩（或无） |
| ML | 远期选项 | 是 | 极高 | 全套 + 严格样本外纪律 |

对本项目的落地建议：

1. **V1 以等权和 IC/ICIR 加权为默认基准**——覆盖个人研究的大部分场景，且在现有预处理框架能力内。
2. **Grinold 最优权留作第三选项**——它直接消费 `redundancy.py` 的因子相关矩阵，评价层冗余分析结果可无缝变成合成层权重输入。
3. **投票法作为 CTA 时序模式的"最少假设"对照组**——符合 trend following 直觉，对预处理要求最低。
4. 与 §14–§17 闭环：**合成方法选定后，预处理链的必要项即被确定**——先讨论策略使用方式，再定预处理流水线的交付形态，这个顺序是对的。

## 24. 期货业界时序模式与截面模式的使用格局

**问题**：工业界实践中，时序模式（多因子作用于单品种、逐品种独立决策）与截面模式（多因子截面排序、映射多品种仓位），哪个被更多使用？是否约 50%-50%？

**回答：不是 50-50。** 按全球管理期货（Managed Futures / CTA）行业 AUM 口径，**时序模式占明显主导**，截面模式是重要少数派。此问题无权威公开统计，以下为基于行业结构的定性判断。

### 24.1 判断依据

1. **海外 CTA 行业主体是时序趋势**。SG CTA / Trend Index 成分基金（Man AHL、Aspect、Transtrend、Lynx、Winton 等）的核心策略是时序趋势跟踪：每个品种用自身历史产生信号，波动率定仓位，组合层做风险分配。学术归因研究（Baltas & Kosowski, "Momentum Strategies in Futures Markets and Trend-Following Funds"）：CTA 基金收益主要由时序动量解释，而非截面动量。理论支柱是 Moskowitz, Ooi & Pedersen (2012) 的 Time Series Momentum。
2. **配置者诉求是 crisis alpha / 凸性**（股债双杀时 CTA 往往赚钱），该性质来自时序趋势结构；截面相对价值策略给不出同样干净的凸性。
3. **期货市场结构天然偏向时序**：

| 维度 | 时序模式 | 截面模式 |
|---|---|---|
| 可下注对象 | 40 个品种 = 40 个独立赌注，容量大 | 40 个品种分 5 组，每组 8 个，分组粗糙 |
| 统计功效 | 每品种几十年时序 | 截面仅几十个样本点 |
| 对冲意义 | — | 商品期货无股票那样强的共同 beta，多空"净化"收益有限 |
| 容量 | 大 | 小 |

4. **股票语境正好反转**：股票有几千只截面，截面多因子选股是绝对主流，时序择时是边缘。"多因子 = 截面打分"的股票直觉需要校准——期货界"多因子"的默认含义更偏时序。
5. **中国语境的特殊态势**：券商金工的期货因子研报大量采用截面多空框架（股票方法论移植，评价体系现成）；2022 下半年–2023 时序趋势普遍回撤后，部分量化 CTA 私募转向截面多空、短周期、基本面量化或混合；但传统 CTA 主体与存量规模仍在时序一侧。
6. **实务真实形态是混合**：时序信号定方向作为核心仓位来源，截面排名做倾斜——同样做多，风险预算多给排名靠前的品种。

### 24.2 对本项目的意义

1. 本仓库定位 Multi-factor Trend Following——核心是时序模式，与行业主流一致；截面模式是重要的对照与补充，不是主角。
2. `EvaluationConfig.mode = time_series / cross_sectional` 双模式设计正好对上这个现实：同一因子先看时序有效性，再看截面区分度。
3. 预处理要求差异（呼应 §14）：**时序模式要求低**（投票/简单加权即可，无需截面标准化）；**截面模式要求高**（标准化、中性化几乎是前提）。以时序为第一策略形态时，截面类变换器服务的是"备选策略形态"与"因子诊断"，而非主战场。

## 25. 复合信号的预测力再检验

**问题**：业界标准工作流中，多因子合成后是否要对新复合因子再做一次预测效力检验（IC、分组多空收益等）？

**回答：是，而且必须。** 复合信号检验是研究链中**决策权重最高**的一次检验——策略最终交易的是复合信号，不是任何单个因子。按第一原则（研究评价的 = 策略交易的），它是回测之前最接近真实可交易信号的研究阶段评价。

### 25.1 为什么必须再检验

1. **复合预测力不是单因子 IC 的线性外推**：
   - 分散化可能增值：Grinold 基本定律 `IR = IC × √breadth`——多个弱相关因子合成后有效广度上升，复合 IR 理论上应高于任何单因子；检验验证该理论在本数据上实证成立。
   - 合成也可能毁值：权重给错（IC 估计噪声）、冗余因子双倍计权、方向冲突——复合 IC 低于最优单因子 IC 的情况实务中并不罕见，不检验就发现不了。
2. **这是 fit/transform 纪律的考场**：
   - 等权合成：无拟合参数，全样本评价相对安全（但仍受因子筛选的选择偏差影响）。
   - IC 加权 / 回归 / Grinold：权重在训练窗口拟合——**用同一段数据既拟合权重又评价复合 IC，评价完全被样本内拟合污染**。标准做法：训练窗口拟合权重 → 样本外评价复合信号。复合检验天然成为"合成方案是否过拟合"的 OOS 检验。
3. **复合层专属检验项**：

| 检验项 | 回答的问题 |
|---|---|
| 复合 IC vs 最优单因子 IC | 合成增值了吗？ |
| 复合 IC vs 各因子加权平均 IC | 分散化收益兑现了吗？ |
| 复合换手 | 通常应低于单因子（信号噪声相互抵消）——不降反升说明有问题 |
| 权重稳定性 | 滚动重拟合窗口下权重漂移多大？ |
| 合成方案参数敏感性 | 换一组合理权重/窗口，结论翻转吗？ |
| 复合多空分组的尾部/回撤行为 | 等权诊断组合的风险形态，回测前最后一道关 |

### 25.2 在本框架中的落点

> 2026-08-10 修订：本节初稿基于"合成属策略侧"的旧架构，提出"策略侧产出 Series 送回 FactorEvaluator"的绕行方案。本次修订已将合成内建于因子模块，复合信号评价成为原生流程，无需绕行。

多因子合成由因子模块的 `CompositeFactor` 完成，复合因子与单因子走同一条评价流水线：

```text
CompositeFactor（因子模块）
    -> 成分因子预处理 -> 合成算子 -> 复合因子值
    -> 第一步：标准诊断（IC / Rank IC / 分组 / 衰减 / 换手）
    -> 第二步：合成诊断（evaluation/composite.py：
             相关结构、分散化增量、权重稳定性、算子参数敏感性）
    -> 通过后再进 BacktestEngine   <-- 成本、保证金、约束的最终验证
```

策略层交易的是已通过两步评价的复合因子（冻结权重）；因子诊断与事件回测的边界不变。

### 25.3 标准工作流总结

```text
单因子检验（每个因子有没有信息）
  -> 冗余分析（谁和谁重复）
  -> 合成（等权 / IC加权 / Grinold）
  -> 复合信号检验（合成是否增值、是否过拟合、换手是否下降）
  -> 事件回测（成本、约束、仓位映射的现实检验）
```

缺了复合检验，等于"配方没尝过就端上桌"——单因子全优、复合翻车，实务中并不罕见。

## 26. 因子正交化、冗余诊断的关系

### User

一个有关因子预处理相关的问题：因子的正交化在因子预处理中扮演什么角色？我们知道，在因子研究中，很容易出现所谓的冗余（重复）信息问题——某个因子和另一个因子或一组因子高度相关，使得我们在做因子合成时容易出现冗余信息重复计入问题（例如直接用简单线性合成）。而所谓的IR = IC * sqrt(breadth)，这里的 breadth 要求的也是各因子之间是独立（正交）的。

我想请你讲讲，在量化工业界的因子研究的管线中，是如何处理因子冗余问题的？我能想到最简单的方法是最优 IC 加权（Grinold 式均值-方差合成），这个因子合成算子考虑了因子之间的相关性，可以做到类似正交化的作用。那么是不是标准工作流程中，也会有先检验 redundancy （作为因子评估流程的一部分），然后再做相应的正交化预处理（例如`docs\Development Notes\20260723 因子研究模块 V1 开发-代码写作方案.md`的 Step10 中，专门便有一个“因子冗余分析”？ 

### Assistant

这个问题的答案可以分三层来讲。先给结论：**“先做冗余检验（评估环节）、再决定是否做正交化处理”确实是业界标准管线的骨架**，你们的 V1 方案（Step 9 的 `redundancy.py` + Step 10 编排）和这个实践是一致的。但“正交化”在管线中的位置和形态比“一个无脑执行的预处理步骤”要微妙得多——它有三个不同的角色，而且和 Grinold 算子是**互斥的二选一关系**（你们方案第 325 行那条规则正是业界共识的体现）。

#### 一、先厘清：“正交化”在管线里其实出现在三个不同位置

| 位置 | 动作 | 对谁正交 | 目的 |
|---|---|---|---|
| 单因子预处理 | **中性化**（行业/市值/风格回归取残差） | 已知**风险**因子 | 剔除不想要的风险暴露，标准预处理，几乎无脑执行 |
| 因子评估 | **冗余检验**（纯诊断，不改变因子） | 其他 **alpha** 因子 | 入库评审：新因子是否带来增量信息 |
| 合成前 / 合成内 | **跨因子正交化** 或 **Grinold 类算子** | 其他 **alpha** 因子 | 避免合成时重复计入，二者二选一 |

---

关键认知是：你问的那种"对 alpha 因子库的冗余正交化"通常**不属于**单因子预处理链——它是有上下文的（对谁正交取决于当前因子库里有什么），放在预处理链里执行会丢失这个上下文。所以工业界一般把它拆成"评估环节的诊断"和"合成环节的处理"两件事。

#### 二、冗余问题的本质：breadth 被高估

Grinold 基本定律 IR ≈ IC · √breadth 中，breadth 是**独立**赌注的数量。N 个高度相关的因子，有效 breadth 远小于 N——它们本质上是对同一个赌注的 N 次重复计数。两个后果：

1. **复合 IR 被高估**：你以为 breadth = N，实际可能只有 1.5；
2. **简单线性合成重复计入信息**：等权/IC 加权隐含假设各因子独立，相关因子会让某类信息在复合信号中获得数倍于它应得的权重。

所以冗余处理的目标不是"消灭相关"（不可能，好因子天然聚簇在少数经济逻辑上），而是**让每个独立信息源恰好被计入一次**。

#### 三、业界的三个处理层次

**层次 1：评估/入库评审阶段的冗余检验（诊断，不改因子）**

这是标准动作，典型内容：

- **相关矩阵**：因子值截面相关的时序均值，以及更重要的——**IC 序列/因子收益的时序相关**（两个口径用途不同，下面讲）；
- **聚类**：对相关矩阵做层次聚类，把因子库切成若干"信息簇"，每簇只保留 IR 最高或最稳健的代表；
- **增量 IC / 边际 IC**：新因子对库内现有因子（或现有复合因子）回归取残差，检验残差的 IC。残差 IC ≈ 0 → 该因子没有增量信息 → 不入库或标记为冗余。这是" redundancy test 作为评估流程一部分"的核心形式；
- **阈值规则**：|ρ| > 0.7 左右的配对只留一个；VIF/条件数检查多重共线性。

你们 Step 9 `redundancy.py` 里的"因子相关、条件相关和边际 IC、正交化前后解释力变化、共线性警告"正是这一套，验收标准"能识别完全相同和高度相关因子"也对得上。

**层次 2：显式正交化（处理手段之一）**

- **Schmidt 序贯正交化**（Gram-Schmidt）：f̃₁ = f₁，f̃₂ = f₂ − β₂,₁·f̃₁，其中 β₂,₁ = cov(f₂, f̃₁)/var(f̃₁)，依此类推。优点：排第一的因子保留原始含义，归因清晰（"谁吃掉谁的信息"明确）；缺点：**顺序敏感**——先做的因子占尽信息，后面的被榨干，顺序本身是主观决策（通常按 IR 降序或先验重要性）。你们方案要求"正交化方法、因子顺序必须进入配置"就是在管住这个主观性。
- **对称正交化**（Löwdin）：F̃ = F·(FᵀF)^(−1/2)。无顺序依赖，且在所有正交化变换中对原始因子的整体扭曲最小；代价是**每个因子都被改动**，可解释性全丢。
- **PCA**：完全正交，但主成分抓的是方差结构而非预测力（第一主成分未必 IC 最高），经济含义模糊，alpha 合成里用得少，更多用于风险模型。
- **残差化**：就是层次 1 增量 IC 检验的"执行版"——只保留新因子对现有复合因子的残差，直接作为独立成分入库。

**层次 3：合成算子内嵌相关性处理（隐式正交化）**

你说的 Grinold 最优 IC 加权：最大化复合 IR，即 max_w (wᵀμ)/√(wᵀΣw)，解为 **w\* ∝ Σ⁻¹μ**（μ 为各因子 IC 或 IR 向量），最优复合 IR = √(μᵀΣ⁻¹μ)。

关键数学事实：**Σ⁻¹ 就是隐式正交化**。把 Σ 做 Cholesky 分解（或对称开方）代入可以看出，w\* 恰好等于"先把因子正交化、再按各正交成分的独立 IR 加权"的复合形式。当 Σ = I（因子已正交）时退化为按 IR 比例加权。所以：

> **Grinold 算子 ≡ 正交化 + 独立 IR 加权，两条路线处理的是同一个问题。**

这正是你们方案第 325 行"使用 Grinold 算子时不做跨因子正交化矩阵预处理（同一问题，叠用等于双重计数）"的原理——先正交化再喂给 Σ⁻¹ 算子，Σ 已经是单位阵的近邻，求逆会放大噪声并重复折扣。

#### 四、实践中怎么选，以及坑点

理论上 Grinold 最优，实践中很多人反而选"显式正交化 + 简单加权"，原因：

1. **Σ 估计噪声**：因子多、有效样本短，Σ⁻¹ 把估计误差放大成权重噪声，样本外不稳定、换手高。常见对策是收缩（Ledoit-Wolf）、或对 Σ 只取对角（退化为 IC_IR 加权，不调整相关性）、或干脆显式正交化后等权——**稳健性优先于理论最优**；
2. **时变性**：相关结构随市场状态漂移，静态正交化/静态 Σ 样本外失效，需要滚动重拟合并监控权重稳定性（你们 `composite.py` 里"滚动重拟合的权重稳定性"诊断就是干这个的）;
3. **可解释性**：Schmidt 保留归因链，对称正交化和 Σ⁻¹ 加权都不保留——投研上需要向人解释"这个复合信号为什么这么做"时，序贯正交化有优势；
4. **两个相关性口径别混用**：冗余**筛查**常用因子值截面相关（衡量信号长得像不像）；合成**权重**应基于 IC/因子收益的时序相关（决定组合层面的风险与 IR）。两个因子值相关 0.8 但 IC 序列相关 0.3 是完全可能的；
5. **正交化不创造信息**：满秩线性变换可逆，不改变因子库的总信息量，也不提升任何单因子 IC。它的全部作用是让"简单线性加权"变得安全——复合 IR 的提升来自权重更合理，而非信息变多。

#### 五、对照你们 V1 方案

你们的设计与业界实践是对齐的，而且层次划分干净：

- **Step 9 `redundancy.py`** = 层次 1（诊断：相关、边际 IC、共线性警告）；
- **`FactorMatrixPreprocessor` 跨因子正交化**（runner 第 8 步）= 层次 2（显式处理路线，顺序/方法入配置）；
- **Grinold 合成算子**（runner 第 10 步）= 层次 3（内嵌路线），并用规则强制与层次 2 互斥；
- **`composite.py` 的合成诊断**（复合 IC 相对最优单因子的增量、权重稳定性）= 验证冗余处理是否真的买到了 breadth。

一个值得注意的编排细节：runner 里正交化（第 8 步）在冗余分析（第 11 步）之前，所以 `redundancy.py` 里的"正交化前后解释力变化"是**前后对比**设计——既在原始因子上识别冗余，又验证正交化处理的效果，这个顺序是合理的。

一句话总结：标准管线 = **评估环节做冗余检验（边际 IC 决定是否入库）→ 合成环节二选一处理残余冗余（显式正交化 + 简单加权，或 Grinold 算子内嵌处理）**，而不是把正交化当成对每个新因子无脑执行的预处理步骤。
