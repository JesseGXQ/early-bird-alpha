# Rules Ingestion Workspace

本目录用于管理“外部数据源 -> 本地期货交易规则数据库”的入库设计、流程编排、执行记录和审计线索。

这里不是最终规则数据库本身。最终领域模型、manager 和规则数据仍应保留在 `data/rules/` 中；本目录关注的是：这些规则如何从 Tushare、BigQuant、交易所公告等外部信息中被分析、校验、转换并写入本地数据库。

## Task Scope

当前任务是为本地三层期货交易规则数据库建立一条可追踪的数据生产流程。核心工作不是简单搬运字段，而是逐个变量分析：

- 外部数据来自哪些表和字段；
- 外部数据粒度是否匹配本地模型；
- 是否需要版本管理、范围管理或人工确认；
- 需要哪些数据校验和网络资料二次确认；
- 最终如何转换为本地领域模型可接受的格式。

本任务覆盖的主要目标包括：

- TIER 1-3 期货交易规则数据库；
- 日频快照数据库；
- 各交易所交易日历；
- 外部原始数据缓存与本地规则生成之间的流程衔接。

## Complexity

该任务复杂度是多维度的，但不必做成重型系统。主要复杂点包括：

- 外部表粒度与本地模型粒度不一致，例如合约-日期级数据需要压缩为品种级版本历史；
- 某些字段需要从历史时间序列中推断 `effective_date`；
- 同一规则可能存在一刀切、新老划断、特定合约范围等不同变更方式；
- BigQuant、Tushare 与交易所公告之间可能需要互补和交叉验证；
- 如果校验结果不满足本地模型假设，可能需要反向调整领域模型。

## Recommended Workflow

1. 建立外部数据源画像，理解 Tushare 和 BigQuant 的表结构、字段语义、数据粒度和历史覆盖范围。
2. 按本地数据库层级和变量逐项制定入库方案，做到“一事一议”。
3. 先选择代表性变量做可行性试跑，例如 `product`、下单量限制、`price_tick`、手续费和交易时段。
4. 再批量下载外部数据全量表，并保留原始快照。
5. 执行规则生成、校验、入库，并记录过程、结果、假设和未决问题。

## Files

- `external_sources.md`: 记录 Tushare、BigQuant 等外部数据源的表级画像。
- `variable_ingestion_plan.md`: 按本地变量记录入库来源、校验规则、转换逻辑和输出格式。
- `execution_log.md`: 记录实际下载、分析、校验和入库执行过程。
- `decisions.md`: 记录规则入库任务中需要人工决策的问题（例如关键设计判断等需要拍板的决策）。文档中包含`List of Decided Decisions`（已有决策概括）。
- `task.md`：对所有任务进行跟踪和记录。

如果开始保存大批量数据，可再增加 `raw_snapshots/` 和 `derived_outputs/`。
